# Настройка T3 Code для работы с worktree

Как включить параллельную работу над несколькими независимыми изменениями:
каждый тред T3 работает в своём worktree, со своими портом, compose-проектом
и базой данных.

## Что уже есть в репозитории

| Скрипт | Что делает |
| --- | --- |
| `scripts/dev-env.sh` | Готовит рабочую копию: создаёт `.env` (секреты копирует из основного checkout'а или генерирует), пишет `WEB_PORT` 8090–8139 (детерминированно от имени ветки), `POSTGRES_DB=my_life_<ветка>`, `COMPOSE_PROJECT_NAME=my-life-<ветка>`, ставит `npm ci`. Флаг `--skip-npm` пропускает установку зависимостей. |
| `scripts/dev-up.sh` | Вызывает `dev-env.sh`, затем `docker compose up -d --build`, печатает адрес приложения. Аргументы уходят в `docker compose`. |
| `scripts/dev-down.sh` | `docker compose down`. С `-v` удаляет и том с данными БД. |

`dev-env.sh` идемпотентен: повторный запуск сохраняет прежние значения и не
переустанавливает `node_modules`. В основном checkout'е (не worktree) скрипт
ничего не меняет, чтобы не переименовать базу и не сменить порт.

## Что настроить в T3

Проект **my-life** → настройки проекта (шестерёнка) → **Scripts**. Сейчас список
скриптов пустой.

| Имя | Команда | Иконка | Флаги |
| --- | --- | --- | --- |
| `Dev env` | `./scripts/dev-env.sh` | `configure` | **run on worktree create** |
| `Docker up` | `./scripts/dev-up.sh` | `play` | без `autoOpenPreview` |
| `Docker down` | `./scripts/dev-down.sh` | `configure` | — |

Почему так:

- **run on worktree create** — новый worktree сразу получает свой `.env` и
  зависимости, без ручных шагов.
- **autoOpenPreview не включаем** — порт у каждой копии свой, а `previewUrl` в
  T3 статический; адрес печатает сам `dev-up.sh`.
- **run on settle / stop on settle не включаем** — иначе контейнеры гаснут,
  как только агент закончил ответ, а вы ещё не успели потыкать приложение.

## Рабочий цикл

1. Смержить предыдущий PR, обновить основной checkout: `git switch master && git pull`.
2. Создать новый тред и выбрать в нём работу в **worktree**.
3. При создании worktree T3 запускает `Dev env`: свой `.env` + `npm ci`.
4. В треде запустить `Docker up` и открыть напечатанный адрес
   `http://localhost:<порт>`.
5. Работа, коммиты, push — как обычно, в ветке этого worktree.
6. Закончили — `Docker down`. После мержа PR worktree можно удалить:
   `git worktree remove ../<путь>`.

## Ограничения и нюансы

- **Порты.** Наружу публикуется только `WEB_PORT`; у каждой копии он свой из
  диапазона 8090–8139. Если два разных имени ветки дадут одинаковый порт
  (редко), поменяйте `WEB_PORT` в `.env` этой копии вручную.
- **База и контейнеры.** `COMPOSE_PROJECT_NAME` даёт отдельные имена
  контейнеров, сеть и том `postgres-data`, поэтому базы копий не пересекаются.
- **Первая сборка.** `dev-up.sh` собирает образы с префиксом проекта (слои
  сборки общие, поэтому повторные сборки быстрее), это занимает несколько минут.
- **Секреты.** `.env` копий не коммитится; секреты берутся из `.env` основного
  checkout'а. Если его нет — генерируются `openssl rand`.
- **Кэш Maven** (`~/.m2/repository`) общий для всех копий; `node_modules` и
  `target/` — свои в каждой копии.
