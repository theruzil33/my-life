## Purpose

Учёт личной медиатеки в сервисе `media`: фильмы и сериалы, книги и игры, которые пользователь только планирует, уже начал или завершил, с названием, необязательным описанием и статусом, изолированно по пользователю.

## ADDED Requirements

### Requirement: Виды записей и их статусы

Сервис `media` SHALL хранить записи трёх видов: `FILM` — фильмы и сериалы, `BOOK` — книги, `GAME` — игры. Каждая запись SHALL иметь статус из набора: `NOT_STARTED` («Не начал»), `IN_PROGRESS` («В процессе»), `COMPLETED` («Завершил»). Статус SHALL быть независим от вида записи, и любой статус SHALL быть допустим для записи любого вида. Переход между статусами SHALL быть разрешён в любом направлении в любой момент.

#### Scenario: Запись каждого вида создаётся с любым статусом

- **WHEN** аутентифицированный пользователь создаёт запись вида `FILM`, `BOOK` или `GAME` со статусом `NOT_STARTED`, `IN_PROGRESS` или `COMPLETED`
- **THEN** `media` сохраняет запись с указанными видом и статусом и возвращает её в ответе

#### Scenario: Статус можно изменить на любой другой

- **WHEN** у записи статус `COMPLETED` и пользователь меняет его на `IN_PROGRESS`
- **THEN** `media` сохраняет новый статус и возвращает запись с ним

#### Scenario: Отклонение неизвестного вида или статуса

- **WHEN** запрос содержит вид или статус, не входящий в допустимый набор
- **THEN** `media` отклоняет запрос ошибкой валидации и не создаёт и не изменяет запись

### Requirement: Создание записи медиатеки

`media` SHALL предоставлять эндпоинт создания записи для аутентифицированного пользователя. Запрос MUST содержать вид и название; описание MUST быть необязательным, а статус MUST по умолчанию быть `NOT_STARTED`, если не указан. Название MUST быть непустым после удаления окружающих пробелов и MUST быть не длиннее 200 символов. Описание MUST быть не длиннее 2000 символов; описание из одних пробелов SHALL считаться отсутствующим. Созданная запись SHALL принадлежать пользователю, выполнившему запрос. Ответ SHALL содержать идентификатор и все сохранённые поля записи.

#### Scenario: Создание записи с названием, описанием и статусом

- **WHEN** аутентифицированный пользователь создаёт запись с видом, названием, описанием и статусом
- **THEN** `media` сохраняет запись и возвращает её с идентификатором, названием, описанием, видом и статусом

#### Scenario: Статус по умолчанию

- **WHEN** аутентифицированный пользователь создаёт запись без указания статуса
- **THEN** `media` сохраняет запись со статусом `NOT_STARTED`

#### Scenario: Описание необязательно

- **WHEN** аутентифицированный пользователь создаёт запись только с видом и названием
- **THEN** `media` сохраняет запись без описания и возвращает её без описания

#### Scenario: Окружающие пробелы удаляются

- **WHEN** пользователь создаёт запись с названием и описанием, окружёнными пробелами
- **THEN** `media` сохраняет название и описание без окружающих пробелов

#### Scenario: Отклонение создания без названия

- **WHEN** запрос на создание не содержит названия или содержит название из одних пробелов
- **THEN** `media` отклоняет запрос ошибкой валидации и не создаёт запись

#### Scenario: Отклонение слишком длинного названия

- **WHEN** запрос на создание содержит название длиннее 200 символов
- **THEN** `media` отклоняет запрос ошибкой валидации и не создаёт запись

#### Scenario: Отклонение создания без вида

- **WHEN** запрос на создание не содержит вид записи
- **THEN** `media` отклоняет запрос ошибкой валидации и не создаёт запись

### Requirement: Список записей по виду

`media` SHALL предоставлять эндпоинт списка записей аутентифицированного пользователя с необязательным фильтром по виду. Если вид указан, ответ SHALL содержать только записи этого вида; если вид не указан, ответ SHALL содержать все записи пользователя. Ответ SHALL содержать для каждой записи идентификатор, вид, название, описание и статус. Записи MUST быть упорядочены по возрастанию идентификатора, чтобы порядок был стабильным между запросами.

#### Scenario: Список записей указанного вида

- **WHEN** у пользователя есть записи видов `FILM`, `BOOK` и `GAME`, и он запрашивает список с видом `BOOK`
- **THEN** `media` возвращает только записи вида `BOOK`

#### Scenario: Список всех записей без фильтра

- **WHEN** у пользователя есть записи нескольких видов, и он запрашивает список без указания вида
- **THEN** `media` возвращает все его записи независимо от вида

#### Scenario: Пустой список

- **WHEN** у пользователя нет записей указанного вида
- **THEN** `media` возвращает пустой список и успешный ответ

#### Scenario: Стабильный порядок списка

- **WHEN** пользователь запрашивает список дважды без промежуточных изменений
- **THEN** `media` возвращает записи в одном и том же порядке

### Requirement: Изменение записи

`media` SHALL предоставлять эндпоинт изменения записи аутентифицированного пользователя. Запрос MUST содержать название, описание и статус записи в их новом значении; правила проверки названия, описания и статуса SHALL совпадать с правилами создания. Вид записи MUST NOT изменяться этим эндпоинтом. Ответ SHALL содержать запись с обновлёнными полями.

#### Scenario: Изменение названия, описания и статуса

- **WHEN** аутентифицированный пользователь изменяет название, описание и статус своей записи
- **THEN** `media` сохраняет новые значения и возвращает запись с ними

#### Scenario: Вид записи не меняется

- **WHEN** пользователь изменяет название, описание и статус записи
- **THEN** вид записи остаётся прежним

#### Scenario: Отклонение изменения без названия

- **WHEN** запрос на изменение не содержит названия или содержит название из одних пробелов
- **THEN** `media` отклоняет запрос ошибкой валидации и не изменяет запись

#### Scenario: Отклонение изменения несуществующей записи

- **WHEN** пользователь изменяет запись, которой у него нет
- **THEN** `media` отвечает ошибкой "не найдено" и не создаёт новую запись

### Requirement: Удаление записи

`media` SHALL предоставлять эндпоинт удаления записи аутентифицированного пользователя. После успешного удаления запись MUST NOT появляться в списках пользователя. Повторное удаление уже удалённой записи SHALL приводить к ошибке "не найдено".

#### Scenario: Удаление записи

- **WHEN** аутентифицированный пользователь удаляет свою запись
- **THEN** `media` удаляет запись и отвечает успешным ответом без тела

#### Scenario: Удалённая запись исчезает из списка

- **WHEN** пользователь удалил запись и запрашивает список её вида
- **THEN** удалённая запись отсутствует в списке

#### Scenario: Повторное удаление отклоняется

- **WHEN** пользователь повторно удаляет уже удалённую запись
- **THEN** `media` отвечает ошибкой "не найдено"

### Requirement: Изоляция записей по пользователю

`media` SHALL ограничивать доступ к записям их владельцем. Запрос MUST идентифицировать пользователя по внутреннему заголовку с его идентификатором, который проставляет gateway. Пользователь MUST NOT видеть, изменять или удалять записи другого пользователя. Попытка изменить или удалить чужую запись MUST приводить к ошибке "не найдено" и MUST NOT раскрывать её существование.

#### Scenario: Список содержит только свои записи

- **WHEN** у двух пользователей есть записи одного вида, и один из них запрашивает список
- **THEN** `media` возвращает только записи запрашивающего пользователя

#### Scenario: Чужая запись не изменяется

- **WHEN** пользователь пытается изменить запись, принадлежащую другому пользователю
- **THEN** `media` отвечает ошибкой "не найдено", и запись второго пользователя остаётся без изменений

#### Scenario: Чужая запись не удаляется

- **WHEN** пользователь пытается удалить запись, принадлежащую другому пользователю
- **THEN** `media` отвечает ошибкой "не найдено", и запись второго пользователя остаётся без изменений

#### Scenario: Запрос без идентификатора пользователя отклоняется

- **WHEN** запрос к эндпоинтам медиатеки не содержит внутреннего заголовка с идентификатором пользователя
- **THEN** `media` отклоняет запрос с ошибкой аутентификации
