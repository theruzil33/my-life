## Purpose

Страница «Медиатека» в веб-клиенте: три подвкладки для фильмов и сериалов, книг и игр с просмотром, созданием, редактированием и удалением записей и сменой их статуса.

## ADDED Requirements

### Requirement: Доступ к странице медиатеки

Веб-клиент SHALL предоставлять страницу медиатеки по адресу `/media`, доступную только аутентифицированному пользователю, и карточку «Медиатека» на главной странице. Страница SHALL содержать ссылку возврата на главную страницу и заголовок страницы.

#### Scenario: Аутентифицированный пользователь открывает медиатеку

- **WHEN** аутентифицированный пользователь переходит по адресу `/media`
- **THEN** веб-клиент показывает страницу медиатеки с заголовком, ссылкой возврата на главную страницу и подвкладками

#### Scenario: Неаутентифицированный пользователь перенаправляется на вход

- **WHEN** неаутентифицированный пользователь открывает адрес `/media`
- **THEN** веб-клиент перенаправляет его на страницу входа

#### Scenario: Возврат на главную страницу

- **WHEN** пользователь нажимает ссылку возврата на странице медиатеки
- **THEN** веб-клиент открывает главную страницу

### Requirement: Подвкладки видов записей

Страница медиатеки SHALL содержать три подвкладки в порядке «Фильмы и сериалы», «Книги», «Игры». Подвкладка «Фильмы и сериалы» SHALL быть открыта по умолчанию. Каждая подвкладка SHALL показывать записи только своего вида. Переключение подвкладок MUST NOT перезагружать страницу, и данные уже открытой подвкладки SHALL сохраняться при переключении.

#### Scenario: Подвкладка по умолчанию

- **WHEN** пользователь открывает страницу медиатеки
- **THEN** открыта подвкладка «Фильмы и сериалы» и запрошен список записей вида `FILM`

#### Scenario: Переключение подвкладок

- **WHEN** пользователь нажимает подвкладку «Книги» или «Игры»
- **THEN** веб-клиент показывает её активной и запрашивает список записей соответствующего вида

#### Scenario: Данные подвкладки сохраняются при переключении

- **WHEN** пользователь открыл подвкладку, дождался загрузки списка, переключился на другую подвкладку и вернулся обратно
- **THEN** список прежней подвкладки отображается без повторной загрузки и без потери данных

### Requirement: Список записей подвкладки

Каждая подвкладка SHALL отображать список записей своего вида в порядке, полученном от API. Для каждой записи SHALL отображаться название и статус в виде подписи «Не начал», «В процессе» или «Завершил», а описание SHALL отображаться при его наличии. Во время загрузки списка веб-клиент SHALL показывать признак загрузки. Если записей нет, веб-клиент SHALL показывать сообщение об отсутствии записей. Если загрузка завершилась ошибкой, веб-клиент SHALL показывать сообщение об ошибке и возможность повторить загрузку.

#### Scenario: Отображение записей

- **WHEN** API возвращает записи подвкладки
- **THEN** веб-клиент показывает для каждой записи название, описание (при наличии) и подпись статуса

#### Scenario: Запись без описания

- **WHEN** у записи нет описания
- **THEN** веб-клиент показывает название и статус записи без пустого блока описания

#### Scenario: Пустой список

- **WHEN** API возвращает пустой список для подвкладки
- **THEN** веб-клиент показывает сообщение об отсутствии записей

#### Scenario: Ошибка загрузки списка

- **WHEN** запрос списка завершился ошибкой
- **THEN** веб-клиент показывает сообщение об ошибке и позволяет повторить загрузку

### Requirement: Создание записи

Каждая подвкладка SHALL предоставлять возможность создать запись своего вида. Форма создания SHALL содержать обязательное поле названия, необязательное поле описания и выбор статуса со значением «Не начал» по умолчанию. Форма MUST NOT позволять изменить вид создаваемой записи. При пустом названии веб-клиент SHALL показывать ошибку валидации и MUST NOT отправлять запрос. После успешного создания новая запись SHALL появиться в списке текущей подвкладки.

#### Scenario: Создание записи с названием, описанием и статусом

- **WHEN** пользователь заполняет название, описание и статус и подтверждает создание
- **THEN** веб-клиент отправляет запрос создания, закрывает форму и показывает новую запись в списке

#### Scenario: Статус по умолчанию в форме

- **WHEN** пользователь открывает форму создания записи
- **THEN** выбран статус «Не начал»

#### Scenario: Пустое название не отправляется

- **WHEN** пользователь пытается создать запись с пустым или состоящим из пробелов названием
- **THEN** веб-клиент показывает ошибку валидации и не отправляет запрос

#### Scenario: Ошибка создания отображается в форме

- **WHEN** запрос создания завершился ошибкой
- **THEN** веб-клиент показывает сообщение об ошибке в форме и оставляет введённые значения

### Requirement: Смена статуса записи

Веб-клиент SHALL позволять изменить статус записи прямо в списке подвкладки без открытия формы редактирования. После успешного изменения отображаемый статус записи SHALL обновиться. При ошибке изменение MUST NOT менять отображаемый статус, а веб-клиент SHALL показать сообщение об ошибке.

#### Scenario: Быстрая смена статуса

- **WHEN** пользователь выбирает другой статус у записи в списке
- **THEN** веб-клиент отправляет запрос изменения и показывает новый статус записи

#### Scenario: Ошибка смены статуса

- **WHEN** запрос смены статуса завершился ошибкой
- **THEN** веб-клиент показывает сообщение об ошибке и оставляет прежний статус записи

### Requirement: Редактирование названия и описания

Веб-клиент SHALL позволять открыть форму редактирования записи, в которой можно изменить название, описание и статус. Форма SHALL быть заполнена текущими значениями записи. Вид записи MUST NOT быть доступен для изменения. После успешного сохранения список подвкладки SHALL показывать обновлённые значения.

#### Scenario: Форма заполнена текущими значениями

- **WHEN** пользователь открывает редактирование записи
- **THEN** форма показывает текущие название, описание и статус записи

#### Scenario: Сохранение изменений

- **WHEN** пользователь изменяет название, описание или статус и подтверждает сохранение
- **THEN** веб-клиент отправляет запрос изменения, закрывает форму и показывает обновлённые значения в списке

#### Scenario: Пустое название не отправляется при редактировании

- **WHEN** пользователь очищает название и пытается сохранить изменения
- **THEN** веб-клиент показывает ошибку валидации и не отправляет запрос

### Requirement: Удаление записи

Веб-клиент SHALL позволять удалить запись из списка подвкладки, запрашивая подтверждение удаления. После успешного удаления запись SHALL исчезнуть из списка. При отказе от подтверждения запрос удаления MUST NOT отправляться. При ошибке удаления запись SHALL остаться в списке, а веб-клиент SHALL показать сообщение об ошибке.

#### Scenario: Удаление с подтверждением

- **WHEN** пользователь подтверждает удаление записи
- **THEN** веб-клиент отправляет запрос удаления и убирает запись из списка

#### Scenario: Отказ от удаления

- **WHEN** пользователь отменяет подтверждение удаления
- **THEN** веб-клиент не отправляет запрос и оставляет запись в списке

#### Scenario: Ошибка удаления

- **WHEN** запрос удаления завершился ошибкой
- **THEN** веб-клиент показывает сообщение об ошибке и оставляет запись в списке

### Requirement: Передача ошибок API пользователю

Веб-клиент SHALL передавать пользователю сообщение об ошибке, возвращённое API, и MUST NOT показывать неинформативные технические подробности. Ошибки отдельных операций MUST NOT приводить к потере уже загруженного списка.

#### Scenario: Сообщение API показывается пользователю

- **WHEN** API отвечает ошибкой с сообщением
- **THEN** веб-клиент показывает это сообщение пользователю

#### Scenario: Список сохраняется при ошибке операции

- **WHEN** операция создания, изменения или удаления завершилась ошибкой
- **THEN** ранее загруженный список записей остаётся отображённым
