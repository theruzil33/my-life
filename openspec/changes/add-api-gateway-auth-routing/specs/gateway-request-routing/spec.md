## Purpose

Capability отвечает за маршрутизацию входящих HTTP-запросов, прошедших через gateway, к нужному backend-сервису на основе префикса URL, чтобы клиенту достаточно обращаться к единственной точке входа.

## ADDED Requirements

### Requirement: Маршрутизация по префиксу URL к настроенному сервису

Gateway SHALL перенаправлять входящий запрос к backend-сервису, сопоставленному с префиксом пути запроса согласно статической конфигурации маршрутов, сохраняя метод запроса, тело и заголовки, не зарезервированные gateway.

#### Scenario: Запрос к известному префиксу маршрутизируется в нужный сервис

- **WHEN** входящий запрос имеет путь с префиксом, сопоставленным в конфигурации с конкретным backend-сервисом
- **THEN** gateway перенаправляет запрос на этот сервис с тем же методом и телом и возвращает клиенту ответ сервиса без изменений содержимого

#### Scenario: Ответ сервиса возвращается клиенту без искажений

- **WHEN** backend-сервис отвечает на перенаправленный запрос с определённым статус-кодом и телом
- **THEN** gateway возвращает клиенту тот же статус-код и то же тело ответа

### Requirement: Отказ в маршрутизации для неизвестного префикса

Gateway SHALL отвечать ошибкой "не найдено", если путь запроса не соответствует ни одному сконфигурированному префиксу маршрута, и MUST NOT обращаться к какому-либо backend-сервису в этом случае.

#### Scenario: Запрос с неизвестным префиксом

- **WHEN** входящий запрос имеет путь, для которого нет соответствующего префикса в конфигурации маршрутов
- **THEN** gateway отвечает ошибкой "не найдено" и не выполняет обращение к backend-сервисам

### Requirement: Передача контекста аутентифицированного пользователя проксируемым сервисам

Для маршрутов, требующих аутентификации, gateway SHALL передавать идентификатор аутентифицированного пользователя проксируемому backend-сервису в запросе, чтобы сервис не должен был самостоятельно проверять JWT access-токен.

#### Scenario: Идентификатор пользователя передаётся сервису

- **WHEN** gateway успешно проверил JWT access-токен и маршрутизирует запрос к backend-сервису на защищённом маршруте
- **THEN** gateway включает в перенаправленный запрос идентификатор аутентифицированного пользователя

### Requirement: Публичные маршруты аутентификации не проксируются как обычные сервисы

Gateway SHALL обрабатывать запросы к маршрутам регистрации и входа локально, а не перенаправлять их через общий механизм маршрутизации к backend-сервисам.

#### Scenario: Запрос к маршруту аутентификации обрабатывается локально

- **WHEN** входящий запрос имеет путь, зарезервированный для регистрации или входа
- **THEN** gateway обрабатывает запрос собственной логикой аутентификации и не перенаправляет его ни одному backend-сервису
