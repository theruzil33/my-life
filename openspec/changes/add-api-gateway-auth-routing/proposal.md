## Why

Сейчас в `backend/gateway` есть только пустой Spring Boot проект без единой точки входа для клиентов. Планируется несколько независимых бэкенд-сервисов (уже есть `tracker`, дальше появятся другие), и каждому из них нужна проверка личности пользователя. Без общего gateway каждый сервис должен был бы сам реализовывать регистрацию/логин и хранить учётные данные пользователей, что дублирует логику и усложняет добавление новых сервисов. Нужен единственный gateway, который отвечает за регистрацию и аутентификацию пользователей и маршрутизирует остальные запросы к нужному backend-сервису по URL.

## What Changes

- Добавить в `gateway` регистрацию пользователя по email и паролю (пароль хранится только в виде хеша, email уникален).
- Добавить в `gateway` логин по email и паролю, который выдаёт JWT access-токен при успешной проверке.
- Добавить проверку JWT для защищённых запросов, проходящих через gateway (валидация подписи и срока действия токена).
- Добавить в `gateway` обратный прокси-роутинг: входящие запросы (кроме `/auth/**`) перенаправляются на нужный backend-сервис на основе префикса URL, согласно статической конфигурации маршрутов.
- Настроить хранение пользователей gateway в PostgreSQL (одна общая база на первом этапе, отдельная схема/набор таблиц для gateway).
- **BREAKING**: отсутствует — `gateway` ранее не содержал бизнес-логики, breaking change не применим.

## Capabilities

### New Capabilities
- `gateway-user-auth`: регистрация пользователя (email + пароль), логин с выдачей JWT, валидация JWT для последующих запросов.
- `gateway-request-routing`: маршрутизация входящих HTTP-запросов на backend-сервисы по префиксу URL, включая передачу контекста авторизованного пользователя.

## Impact

- Затронутый код: `backend/gateway/src/main/java/com/theruzil/gateway/**`, `backend/gateway/src/main/resources/application.properties`, `backend/gateway/pom.xml` (добавление зависимостей: Spring Security, JWT-библиотека, Spring Data JPA, PostgreSQL-драйвер).
- Новая инфраструктурная зависимость: развёрнутый отдельно PostgreSQL, доступный gateway по JDBC; на первом этапе используется одна база для всех сервисов.
- Затронутые сервисы: `backend/tracker` (и последующие backend-сервисы) должны быть доступны gateway по конфигурируемому базовому URL для проксирования; сами эти сервисы в рамках данного изменения не модифицируются.
- Новые внешние API: `POST /auth/register`, `POST /auth/login` (и, при необходимости, `POST /auth/refresh` — уточняется в design.md).
- Конфигурация: список маршрутов «префикс URL → сервис» задаётся статически в конфигурации gateway на первом этапе (без service discovery).
