## Purpose

Импорт статистики привычек и задач из CSV-выгрузки (например, Google Таблиц) в сервис `tracker`: разбор файла за выбранный месяц, автоматическое создание отсутствующих активностей и заполнение отметок выполнения по дням месяца с изоляцией данных по аутентифицированному пользователю.

## ADDED Requirements

### Requirement: Импорт CSV-файла за месяц

Tracker SHALL предоставлять эндпоинт импорта, принимающий CSV-файл и целевые месяц и год для аутентифицированного пользователя. Запрос MUST содержать файл, месяц и год; при отсутствии любого из них запрос MUST быть отклонён ошибкой валидации. Целевой месяц SHALL задаваться вызывающей стороной (месяц и год) и MUST NOT извлекаться из содержимого или имени файла. Эндпоинт SHALL разобрать файл, создать отсутствующие активности и сохранить отметки выполнения за дни выбранного месяца. Все созданные активности и отметки SHALL принадлежать пользователю, выполнившему запрос.

#### Scenario: Успешный импорт заполняет отметки месяца

- **WHEN** аутентифицированный пользователь отправляет корректный файл с указанием месяца и года
- **THEN** tracker разбирает файл, создаёт отсутствующие активности, сохраняет отметки выполнения за дни выбранного месяца и возвращает успешный ответ

#### Scenario: Отклонение импорта без файла

- **WHEN** запрос импорта не содержит файла
- **THEN** tracker отклоняет запрос ошибкой валидации и не сохраняет данные

#### Scenario: Отклонение импорта без месяца или года

- **WHEN** запрос импорта не содержит месяц или год
- **THEN** tracker отклоняет запрос ошибкой валидации и не сохраняет данные

#### Scenario: Имя файла не влияет на импорт

- **WHEN** аутентифицированный пользователь импортирует файл с произвольным именем и указанным месяцем и годом
- **THEN** tracker разбирает содержимое файла и относит отметки к указанному месяцу и году независимо от имени файла

#### Scenario: Импорт не зависит от месяца в данных

- **WHEN** пользователь импортирует один и тот же файл, указывая разные месяцы и годы
- **THEN** tracker создаёт или обновляет отметки на дни каждого указанного месяца отдельно

### Requirement: Разбор активностей, вариантов и типов файла

Tracker SHALL разбирать файл как CSV с запятой в роли разделителя полей. Строка активности SHALL содержать название в первом столбце, необязательный вариант во втором столбце, тип в третьем столбце и значения дней месяца в последующих столбцах. Тип SHALL определять вид активности: «Привычка» SHALL соответствовать типу `HABIT`, «Задача» — типу `TASK`. Строки без распознаваемого типа (заголовок таблицы, итоговые строки) MUST игнорироваться. Если название в строке не указано, названием SHALL считаться название из предыдущей строки-активности. Если у строки указан непустой вариант, tracker SHALL включить его в название активности, чтобы варианты одного названия (например, «Утром» и «Вечером») считались разными активностями. Tracker SHALL игнорировать окружающие пробелы в текстовых значениях.

#### Scenario: Распознавание типа активности

- **WHEN** строка файла содержит в столбце типа «Привычка» или «Задача»
- **THEN** tracker создаёт активность типа `HABIT` или `TASK` соответственно

#### Scenario: Строки без типа пропускаются

- **WHEN** файл содержит строку заголовка или итоговую строку без распознаваемого типа активности
- **THEN** tracker не создаёт по ней активность и не считает её ошибкой

#### Scenario: Пустое название продолжает предыдущую активность

- **WHEN** строка активности не содержит названия, а предыдущая строка-активность содержала название
- **THEN** tracker относит эту строку к активности с названием из предыдущей строки

#### Scenario: Вариант включается в название

- **WHEN** строка активности содержит название и непустой вариант во втором столбце
- **THEN** tracker формирует название активности из названия и варианта так, что строки с разными вариантами дают разные активности

#### Scenario: Вариант отсутствует

- **WHEN** строка активности не содержит варианта во втором столбце
- **THEN** tracker использует название активности без варианта

### Requirement: Сопоставление активностей по типу и названию

При импорте tracker SHALL сопоставлять активности файла с существующими активностями пользователя по типу и названию. Если активности с такими типом и названием у пользователя нет, tracker SHALL создать её. Если такая активность уже есть, tracker SHALL переиспользовать её и MUST NOT создавать дубликат. Для новой активности дата начала SHALL быть первым числом выбранного месяца, а периодичность — ежедневной. При переиспользовании существующей активности tracker MUST NOT изменять её дату начала, периодичность, тип и название.

#### Scenario: Отсутствующая активность создаётся

- **WHEN** аутентифицированный пользователь импортирует активность, для которой у него нет активности с такими типом и названием
- **THEN** tracker создаёт активность с этим типом и названием, привязанную к пользователю, с датой начала первого числа выбранного месяца и ежедневной периодичностью

#### Scenario: Существующая активность переиспользуется без дублирования

- **WHEN** аутентифицированный пользователь импортирует активность, для которой у него уже есть активность с такими типом и названием
- **THEN** tracker использует существующую активность и не создаёт вторую

#### Scenario: Активности различаются по типу и названию

- **WHEN** у пользователя есть активность типа `HABIT` с некоторым названием, а файл содержит активность типа `TASK` или иное название
- **THEN** tracker считает её отдельной и создаёт новую активность

#### Scenario: Расписание существующей активности не меняется

- **WHEN** tracker переиспользует существующую активность с собственной датой начала и периодичностью
- **THEN** дата начала, периодичность и тип существующей активности остаются без изменений

### Requirement: Заполнение отметок выполнения по дням месяца

Для каждой активности и каждого дня выбранного месяца tracker SHALL сохранять отметку выполнения, если в столбце этого дня указано значение строго больше нуля. Пустое или нулевое значение дня MUST NOT создавать отметку. Дни за пределами длины выбранного месяца (например, 30 и 31 для февраля) MUST игнорироваться. Дни позже сегодняшней даты в настроенном часовом поясе сервиса MUST NOT создавать отметку. Повторная отметка на уже отмеченную пару «активность + дата» MUST NOT создавать дубликат. Дни, не соответствующие расписанию активности (до её даты начала или вне её периодичности), MUST NOT отмечаться.

#### Scenario: Положительные значения дней создают отметки

- **WHEN** файл содержит для активности положительные значения в нескольких столбцах дней
- **THEN** tracker сохраняет отметку выполнения на каждый такой день выбранного месяца

#### Scenario: Нулевые и пустые дни не создают отметок

- **WHEN** в столбце дня указан ноль или значение отсутствует
- **THEN** tracker не создаёт отметку на этот день

#### Scenario: Повторный импорт не дублирует отметки

- **WHEN** аутентифицированный пользователь повторно импортирует файл, где для дня уже есть отметка
- **THEN** tracker сохраняет единственную отметку на эту пару «активность + дата»

#### Scenario: Дни за пределами месяца игнорируются

- **WHEN** файл содержит значения в столбцах дней, которых нет в выбранном месяце
- **THEN** tracker не создаёт отметок на эти дни

#### Scenario: Будущие дни не отмечаются

- **WHEN** файл содержит положительное значение в столбце дня позже сегодняшней даты в настроенном часовом поясе сервиса
- **THEN** tracker не создаёт отметку на этот день

### Requirement: Импорт дополняет данные и не удаляет существующие

Импорт MUST NOT удалять активности и отметки, отсутствующие в файле. Отметки выбранного месяца, не затронутые строками файла, SHALL остаться без изменений. Импорт MUST NOT изменять тип, название, дату начала и периодичность существующих активностей.

#### Scenario: Существующие отметки месяца сохраняются

- **WHEN** у пользователя за выбранный месяц уже есть отметки, которых нет в файле
- **THEN** после импорта эти отметки остаются без изменений

#### Scenario: Расписание активностей не меняется

- **WHEN** аутентифицированный пользователь выполняет импорт
- **THEN** тип, название, дата начала и периодичность существующих активностей остаются без изменений

### Requirement: Отклонение некорректного файла без частичных изменений

Если файл не является корректным CSV или не содержит ни одной строки-активности с распознаваемым типом, tracker MUST отклонять импорт ошибкой валидации. Если значение дня или иное числовое значение не удаётся разобрать, tracker MUST отклонять импорт ошибкой валидации. При любой ошибке импорта tracker MUST NOT сохранять частичный результат: ни одна активность и ни одна отметка MUST NOT быть создана или изменена. Ответ об ошибке MUST содержать понятное сообщение.

#### Scenario: Некорректный файл отклоняется

- **WHEN** аутентифицированный пользователь отправляет файл, который не является корректной выгрузкой со строками активностей
- **THEN** tracker отвечает ошибкой валидации и не сохраняет данные

#### Scenario: Ошибка не оставляет частичных изменений

- **WHEN** импорт завершается ошибкой после разбора части файла
- **THEN** ни созданные в ходе этого запроса активности, ни отметки не сохраняются

### Requirement: Результат импорта

Tracker SHALL возвращать в ответе на успешный импорт количество созданных активностей и количество сохранённых отметок выполнения.

#### Scenario: Успешный импорт возвращает сводку

- **WHEN** аутентифицированный пользователь успешно импортирует файл
- **THEN** tracker возвращает количество созданных активностей и количество сохранённых отметок

### Requirement: Изоляция импорта по пользователю

Импорт SHALL ограничиваться владельцем данных: запрос MUST идентифицировать пользователя по внутреннему заголовку с его идентификатором, который проставляет gateway. При отсутствии заголовка tracker MUST отклонять запрос с ошибкой аутентификации. Файл одного пользователя MUST NOT затрагивать активности и отметки другого пользователя.

#### Scenario: Импортируемые данные принадлежат пользователю

- **WHEN** аутентифицированный пользователь выполняет импорт
- **THEN** все созданные активности и отметки привязаны к этому пользователю

#### Scenario: Запрос без идентификатора пользователя отклоняется

- **WHEN** запрос импорта не содержит внутреннего заголовка с идентификатором пользователя
- **THEN** tracker отклоняет запрос с ошибкой аутентификации

#### Scenario: Импорт не затрагивает данные другого пользователя

- **WHEN** один пользователь импортирует файл, а у другого пользователя есть свои активности и отметки
- **THEN** активности и отметки второго пользователя остаются без изменений
