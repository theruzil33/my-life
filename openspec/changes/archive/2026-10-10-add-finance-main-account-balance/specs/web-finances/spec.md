## MODIFIED Requirements

### Requirement: Список счетов на странице финансов

Вкладка «Счета» страницы финансов SHALL отображать все счета пользователя, получая их из API финансов. Для каждого счёта SHALL отображаться его название и финальная сумма. Главный счёт SHALL быть визуально помечен как главный. Если у пользователя нет счетов, вкладка SHALL показывать пустое состояние вместо списка. Во время загрузки вкладка SHALL показывать признак загрузки, а при ошибке загрузки — понятное сообщение об ошибке и MUST NOT показывать список.

#### Scenario: Список счетов отображается

- **WHEN** аутентифицированный пользователь открывает вкладку «Счета», и у него есть счета
- **THEN** веб-клиент показывает список этих счетов с названием и финальной суммой каждого

#### Scenario: Главный счёт помечен

- **WHEN** аутентифицированный пользователь открывает вкладку «Счета», и один из его счетов является главным
- **THEN** веб-клиент визуально помечает главный счёт как главный

#### Scenario: Финальная сумма учитывает операции

- **WHEN** у пользователя есть главный счёт с операциями прихода и ухода
- **THEN** веб-клиент показывает в списке финальную сумму главного счёта, полученную из API финансов

#### Scenario: Пустое состояние при отсутствии счетов

- **WHEN** аутентифицированный пользователь без счетов открывает вкладку «Счета»
- **THEN** вкладка показывает пустое состояние вместо списка счетов

#### Scenario: Индикация загрузки списка

- **WHEN** веб-клиент запрашивает список счетов
- **THEN** вкладка показывает признак загрузки до получения ответа API финансов

#### Scenario: Ошибка загрузки списка счетов

- **WHEN** запрос списка счетов завершается сетевой ошибкой или ошибкой сервера
- **THEN** вкладка показывает сообщение об ошибке и не показывает список счетов

### Requirement: Создание счёта через модальное окно

Страница финансов SHALL предоставлять кнопку добавления, открывающую модальное окно создания счёта. Модальное окно SHALL содержать поля названия и начальной суммы и SHALL содержать выбор признака «сделать счётом главным». Веб-клиент SHALL проверять перед отправкой, что название непустое, а начальная сумма указана и является числом, и MUST NOT отправлять запрос при нарушении этих условий, показывая причину. Веб-клиент SHALL передавать в API финансов выбранный признак главного счёта. При успешном создании веб-клиент SHALL закрыть модальное окно и обновить список счётов. Если запрос завершился ошибкой, веб-клиент SHALL показать сообщение об ошибке, оставить модальное окно открытым с введёнными значениями и MUST NOT обновлять список. Пока запрос создания выполняется, повторная отправка формы MUST быть недоступна.

#### Scenario: Открытие модального окна создания счёта

- **WHEN** пользователь нажимает кнопку добавления на странице финансов
- **THEN** веб-клиент показывает модальное окно с полями названия и начальной суммы и выбором признака «сделать счётом главным»

#### Scenario: Успешное создание счёта

- **WHEN** пользователь заполняет непустое название и начальную сумму и подтверждает создание
- **THEN** веб-клиент отправляет запрос создания в API финансов, закрывает модальное окно и обновляет список счетов

#### Scenario: Передача признака главного счёта

- **WHEN** пользователь включает выбор «сделать счётом главным» и подтверждает создание
- **THEN** запрос создания в API финансов содержит признак главного счёта

#### Scenario: Отклонение создания без названия

- **WHEN** пользователь подтверждает создание с пустым названием
- **THEN** веб-клиент не отправляет запрос и показывает сообщение о необходимости указать название

#### Scenario: Отклонение создания без суммы

- **WHEN** пользователь подтверждает создание без начальной суммы
- **THEN** веб-клиент не отправляет запрос и показывает сообщение о необходимости указать начальную сумму

#### Scenario: Закрытие модального окна без создания

- **WHEN** пользователь закрывает модальное окно, не подтвердив создание
- **THEN** веб-клиент не создаёт счёт и не меняет список счетов

#### Scenario: Ошибка API финансов при создании

- **WHEN** запрос создания счёта завершается ошибкой API финансов
- **THEN** веб-клиент показывает сообщение об ошибке, оставляет модальное окно открытым с введёнными значениями и не обновляет список

#### Scenario: Повторная отправка формы создания недоступна

- **WHEN** запрос создания счёта ещё выполняется
- **THEN** веб-клиент не позволяет подтвердить создание повторно

### Requirement: Удаление счёта с подтверждением

Страница финансов SHALL предоставлять для каждого неглавного счёта действие удаления. Действие удаления MUST быть недоступно для главного счёта. Перед удалением веб-клиент SHALL запрашивать подтверждение пользователя. При подтверждении веб-клиент SHALL отправить в API финансов запрос удаления счёта и после успешного ответа SHALL убрать счёт из списка. При отмене подтверждения веб-клиент MUST NOT отправлять запрос и MUST NOT менять список. Если запрос удаления завершился ошибкой, веб-клиент SHALL показать сообщение об ошибке и MUST NOT убирать счёт из списка. Пока запрос удаления этого счёта выполняется, повторное удаление MUST быть недоступно.

#### Scenario: Запрос подтверждения удаления

- **WHEN** пользователь выбирает действие удаления у неглавного счёта
- **THEN** веб-клиент запрашивает подтверждение удаления до отправки запроса

#### Scenario: Действие удаления недоступно для главного счёта

- **WHEN** пользователь просматривает вкладку «Счета», и один из счетов является главным
- **THEN** веб-клиент не предоставляет действие удаления для главного счёта

#### Scenario: Подтверждённое удаление убирает счёт из списка

- **WHEN** пользователь подтверждает удаление неглавного счёта
- **THEN** веб-клиент отправляет запрос удаления и после успеха убирает счёт из отображаемого списка

#### Scenario: Отмена удаления не меняет список

- **WHEN** пользователь отменяет подтверждение удаления
- **THEN** веб-клиент не отправляет запрос удаления и оставляет счёт в списке

#### Scenario: Ошибка API финансов при удалении

- **WHEN** запрос удаления завершается ошибкой API финансов
- **THEN** веб-клиент показывает сообщение об ошибке и оставляет счёт в списке

#### Scenario: Повторное удаление недоступно во время запроса

- **WHEN** запрос удаления счёта ещё выполняется
- **THEN** веб-клиент не позволяет повторно инициировать удаление этого счёта
