## MODIFIED Requirements

### Requirement: Редактирование привычки

Tracker SHALL предоставлять эндпоинт редактирования существующей привычки пользователя, позволяющий изменить название, дату начала действия и периодичность. Изменение MUST применять те же правила валидации, что и при создании, и MUST NOT удалять или изменять уже сохранённые отметки выполнения привычки.

#### Scenario: Успешное редактирование привычки

- **WHEN** аутентифицированный пользователь изменяет название, дату начала и/или периодичность своей привычки на корректные значения
- **THEN** tracker сохраняет новые значения и возвращает обновлённую привычку

#### Scenario: Сохранение отметок выполнения при редактировании

- **WHEN** аутентифицированный пользователь редактирует привычку, для которой ранее были отмечены выполнения
- **THEN** tracker сохраняет все ранее отмеченные даты выполнения без изменений

#### Scenario: Отклонение редактирования с некорректной датой начала

- **WHEN** аутентифицированный пользователь изменяет дату начала привычки на дату в будущем
- **THEN** tracker отклоняет запрос ошибкой валидации и не изменяет привычку

## ADDED Requirements

### Requirement: Создание привычки с датой начала не в будущем

Tracker SHALL предоставлять эндпоинт создания привычки, который сохраняет привычку для аутентифицированного пользователя с названием, датой начала действия и периодичностью. Название MUST быть непустым, дата начала MUST быть сегодняшней датой или прошлой датой, а периодичность MUST быть либо ежедневной, либо непустым набором конкретных дней недели.

#### Scenario: Успешное создание ежедневной привычки с сегодняшней датой начала

- **WHEN** аутентифицированный пользователь создаёт привычку с непустым названием, датой начала равной сегодня, и периодичностью «ежедневно»
- **THEN** tracker сохраняет привычку, привязанную к этому пользователю, и возвращает созданную привычку с её названием, датой начала и периодичностью

#### Scenario: Создание привычки с прошлой датой начала

- **WHEN** аутентифицированный пользователь создаёт привычку с датой начала раньше сегодняшней
- **THEN** tracker сохраняет привычку с указанной прошлой датой начала

#### Scenario: Создание привычки с конкретными днями недели

- **WHEN** аутентифицированный пользователь создаёт привычку с периодичностью в виде непустого набора дней недели
- **THEN** tracker сохраняет привычку с этими днями недели в качестве периодичности

#### Scenario: Отклонение создания без названия

- **WHEN** аутентифицированный пользователь создаёт привычку с пустым или отсутствующим названием
- **THEN** tracker отклоняет запрос ошибкой валидации и не сохраняет привычку

#### Scenario: Отклонение создания с датой начала в будущем

- **WHEN** аутентифицированный пользователь создаёт привычку с датой начала позже сегодняшней даты
- **THEN** tracker отклоняет запрос ошибкой валидации и не сохраняет привычку

#### Scenario: Отклонение создания без периодичности

- **WHEN** аутентифицированный пользователь создаёт привычку с пустым набором дней недели и без признака ежедневной периодичности
- **THEN** tracker отклоняет запрос ошибкой валидации и не сохраняет привычку

## REMOVED Requirements

### Requirement: Создание привычки

**Reason**: Правило даты начала инвертируется: прошлое становится допустимым, будущее — запрещённым. Набор сценариев требования меняется (сценарий про будущую дату начала превращается в отклонение, сценарий про прошлую — в успех), а MODIFIED не позволяет переименовывать или удалять существующие сценарии.

**Migration**: Использовать требование «Создание привычки с датой начала не в будущем». Запросы `POST /tracker/habits` с датой начала в прошлом теперь принимаются, с будущей датой начала — отклоняются ошибкой валидации (`400`).
