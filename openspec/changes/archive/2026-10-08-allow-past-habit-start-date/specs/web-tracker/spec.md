## ADDED Requirements

### Requirement: Создание привычки через модальное окно с датой начала не в будущем

Вкладка «Привычки» SHALL предоставлять кнопку «Добавить привычку», открывающую кастомное модальное окно создания привычки. Модальное окно SHALL содержать поля названия, даты начала и периодичности; периодичность SHALL задаваться выбором между ежедневной и конкретными днями недели, при этом выбор дней недели SHALL быть доступен при периодичности «конкретные дни недели». Веб-клиент SHALL проверять перед отправкой, что название непустое, дата начала не позже сегодняшней, а периодичность заполнена, и MUST NOT отправлять запрос при нарушении этих условий, показывая причину. Веб-клиент SHALL NOT позволять выбрать будущую дату начала. При успешном создании веб-клиент SHALL закрыть модальное окно и обновить список привычек за выбранную дату. Изменение и удаление существующих привычек в этом интерфейсе MUST NOT предоставляться.

#### Scenario: Открытие модального окна

- **WHEN** пользователь нажимает кнопку «Добавить привычку»
- **THEN** веб-клиент показывает модальное окно с полями названия, даты начала и периодичности

#### Scenario: Создание ежедневной привычки

- **WHEN** пользователь заполняет название, дату начала не позже сегодняшней и выбирает ежедневную периодичность, затем подтверждает создание
- **THEN** веб-клиент отправляет запрос создания в трекер, закрывает модальное окно и обновляет список привычек

#### Scenario: Создание привычки с прошлой датой начала

- **WHEN** пользователь заполняет название, дату начала в прошлом и периодичность, затем подтверждает создание
- **THEN** веб-клиент отправляет запрос создания в трекер, закрывает модальное окно и обновляет список привычек

#### Scenario: Создание привычки по конкретным дням недели

- **WHEN** пользователь выбирает периодичность «конкретные дни недели» и отмечает хотя бы один день недели, затем подтверждает создание
- **THEN** веб-клиент отправляет запрос создания с выбранными днями недели и после успеха закрывает модальное окно

#### Scenario: Дни недели доступны только для соответствующей периодичности

- **WHEN** в модальном окне выбрана ежедневная периодичность
- **THEN** веб-клиент не предлагает выбирать дни недели и не отправляет их в запросе

#### Scenario: Отклонение создания без названия

- **WHEN** пользователь подтверждает создание с пустым названием
- **THEN** веб-клиент не отправляет запрос и показывает сообщение о необходимости указать название

#### Scenario: Отклонение создания с датой начала в будущем

- **WHEN** пользователь подтверждает создание с датой начала позже сегодняшней
- **THEN** веб-клиент не отправляет запрос и показывает сообщение о недопустимой дате начала

#### Scenario: Будущая дата начала недоступна для выбора

- **WHEN** пользователь открывает выбор даты начала в модальном окне
- **THEN** веб-клиент не позволяет выбрать дату позже сегодняшней

#### Scenario: Отклонение создания без периодичности

- **WHEN** пользователь выбирает периодичность «конкретные дни недели», не отметив ни одного дня, и подтверждает создание
- **THEN** веб-клиент не отправляет запрос и показывает сообщение о необходимости выбрать периодичность

#### Scenario: Закрытие модального окна без создания

- **WHEN** пользователь закрывает модальное окно, не подтвердив создание
- **THEN** веб-клиент не создаёт привычку и не меняет список привычек

#### Scenario: Ошибка трекера при создании

- **WHEN** запрос создания привычки завершается ошибкой трекера
- **THEN** веб-клиент показывает сообщение об ошибке, оставляет модальное окно открытым с введёнными значениями и не обновляет список

#### Scenario: Повторная отправка формы создания недоступна

- **WHEN** запрос создания привычки ещё выполняется
- **THEN** веб-клиент не позволяет подтвердить создание повторно

#### Scenario: Отсутствие действий изменения и удаления

- **WHEN** пользователь просматривает список привычек
- **THEN** веб-клиент не предоставляет действий изменения или удаления привычки

## REMOVED Requirements

### Requirement: Создание привычки через модальное окно

**Reason**: Правило даты начала инвертируется: прошлое становится допустимым, будущее — запрещённым. Набор сценариев требования меняется (сценарий про прошлую дату начала превращается в успех, сценарий про будущую дату начала удаляется), а MODIFIED не позволяет переименовывать или удалять существующие сценарии.

**Migration**: Использовать требование «Создание привычки через модальное окно с датой начала не в будущем»: поле даты начала больше не ограничивает прошлое и запрещает будущее.
