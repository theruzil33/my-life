## Context

Страница трекера (`client/web/src/pages/TrackerPage.jsx`) содержит вкладки «Привычки», «Задачи» и «Статистика». Вкладки «Привычки» и «Задачи» построены на общем компоненте `ActivityListTab`, который загружает активности одного типа на выбранную дату, хранит состояние чекбоксов и модальные окна редактирования.

API трекера `GET /tracker/habits?date=...` уже поддерживает отсутствие параметра `type` и в этом случае возвращает активности обоих типов. Веб-клиент передаёт query-параметры через `trackerApi.listOnDate`, который опускает значения `undefined`, поэтому для новой вкладки достаточно вызвать его без типа.

Текущая вкладка по умолчанию — «Привычки»; вкладка «Привычки» монтируется всегда, остальные — лениво при первом открытии.

## Goals / Non-Goals

**Goals:**

- Добавить вкладку «Сегодня» первой и сделать её вкладкой по умолчанию.
- Показывать на ней активности обоих типов за сегодняшнюю дату без выбора даты.
- Группировать активности по частям дня с порядком от текущей части дня и группой «Весь день» в конце.
- Переиспользовать существующую логику отметки выполнения, не дублируя её.
- Сохранить даты и состояние уже открытых вкладок при переключении.

**Non-Goals:**

- Изменения бэкенда, схемы БД и API.
- Создание, переименование, удаление активностей и изменение частей дня на вкладке «Сегодня».
- Настройка границ частей дня пользователем: границы фиксированы.
- Автоматическое обновление данных с сервера по таймеру (перечитывание происходит при импорте, смене даты и перезагрузке вкладки).

## Decisions

### Отдельный компонент `TodayTab` вместо расширения `ActivityListTab`

`ActivityListTab` ориентирован на один тип активности, выбор даты и модальные окна редактирования. Вкладке «Сегодня» нужны оба типа, фиксированная дата и группировка; добавление режима в существующий компонент усложнило бы его ветвления и риск регрессии.

Решение: новый компонент `client/web/src/tracker/TodayTab.jsx`; `ActivityListTab` продолжает обслуживать «Привычки» и «Задачи». Общие части выносятся в небольшие модули.

Альтернатива — два параллельных запроса `listOnDate` по типам и слияние результатов — отклонена: API уже умеет вернуть оба типа одним запросом, а слияние потребовало бы дополнительной сортировки и обработки частичных ошибок.

### Переиспользуемый хук отметок выполнения

Логика переключения чекбоксов с учётом части дня, блокировки во время запроса и отката при ошибке одинакова на всех трёх вкладках. Чтобы не расходились правила, она выносится в хук `client/web/src/tracker/useCompletionToggle.js`:

- вход: `accessToken`, `date`, `setActivities`;
- состояние: `pendingKeys`, `actionError`;
- результат: `completionFor`, `isPending`, `toggleCompleted`, `setActionError`.

`ActivityListTab` переводится на этот хук без изменения внешнего поведения; `TodayTab` использует его с сегодняшней датой. Существующие тесты `HabitsTab` и `TasksTab` служат защитой от регрессии.

Альтернатива — продублировать логику в `TodayTab` — отклонена из-за риска расхождения правил отметки.

### Чистые функции группировки и вычисления текущей части дня

Вычисления выносятся в `client/web/src/tracker/todayGroups.js`:

- `currentTimeOfDay(now)` — по локальным часам: 6–11 → `MORNING`, 12–17 → `DAY`, иначе `EVENING`;
- `timeOfDayGroupOrder(now)` — циклический сдвиг порядка `MORNING → DAY → EVENING`;
- `groupActivities(activities, now)` — возвращает непустые группы в нужном порядке; активность попадает в каждую группу из своего набора `timeOfDay`, активности с пустым набором — в группу «Весь день» последней.

Чистые функции легко покрыть unit-тестами с фиксированным `now` и не зависят от рендера. Внутри группы сохраняется порядок, полученный от API.

### Обновление текущей части дня без перезагрузки

`TodayTab` хранит `now` в состоянии и обновляет его раз в 60 секунд (`setInterval` с очисткой при размонтировании). Из `now` выводятся и порядок групп, и сегодняшняя дата; при смене даты эффект загрузки перечитывает активности. Так вкладка, оставленная открытой на весь день, остаётся актуальной.

Альтернатива — вычислять время только при монтировании — отклонена: к вечеру порядок групп оставался бы утренним.

### Ленивое монтирование вкладок

Так как вкладка по умолчанию меняется, «Привычки» переводятся на тот же механизм ленивого монтирования, что и «Задачи»/«Статистика». При первом открытии вкладка монтируется и остаётся в дереве, поэтому выбранная дата и данные сохраняются при переключениях. Вкладка «Сегодня» монтируется всегда и получает `refreshToken` при импорте.

### Разметка и визуальное различие

Группы отображаются как секции с заголовками «Утро», «День», «Вечер», «Весь день». У текущей группы показывается метка «Сейчас» и отдельный CSS-класс. Для каждой активности выводится метка типа «Привычка» или «Задача». Переиспользуются существующие классы списка и чекбоксов (`habits-list`, `habit-item`, `habit-checkbox`, `habit-name`), новые классы добавляются в `App.css`.

## Risks / Trade-offs

- [Часовой пояс браузера может отличаться от часового пояса трекера вблизи полуночи] → дата и границы частей дня уже вычисляются на клиенте в существующих вкладках; поведение согласовано с текущим подходом. Риск принят и не устраняется в этом изменении.
- [Одна активность может отображаться в нескольких группах] → такова цель группировки; чекбокс в каждой группе относится только к её части дня, а метка типа и заголовок группы делают контекст однозначным.
- [Рефакторинг логики отметок может затронуть «Привычки» и «Задачи»] → существующие тесты этих вкладок остаются без изменений и должны проходить; при расхождении предпочтительнее сохранить текущее поведение.
- [Интервал обновления вызывает лишние рендеры] → период 60 секунд и малый объём данных делают накладные расходы незначительными; интервал очищается при размонтировании.

## Migration Plan

Изменение только клиентское, миграция данных не требуется. Откат — вернуть прежний порядок вкладок и вкладку по умолчанию, удалить `TodayTab` и связанные стили; API и данные остаются совместимыми.
