## Why

Сейчас трекер поддерживает только один вид активностей — обязательные ежедневные привычки. Пользователю нужно вести рядом ещё один, необязательный вид активностей («Задачи») по тем же правилам (название, дата начала, периодичность, отметка выполнения, история), видеть их в отдельной вкладке и в общей статистике, но при этом отличать один вид от другого.

## What Changes

- Ввести у активности признак типа: `HABIT` (обязательная привычка) и `TASK` (необязательная задача). Тип MUST храниться и возвращаться API для каждой активности.
- Backend tracker: создание и редактирование активности принимает тип; список активностей на дату и история отдают тип и допускают выбор типа для списка; отметка и отмена выполнения, правила валидации и определение сегодняшней даты остаются общими для обоих типов.
- Backend tracker: миграция БД добавляет тип существующим активностям со значением по умолчанию `HABIT`, чтобы уже заведённые привычки остались обязательными.
- Веб-клиент: на странице трекера появляется вкладка «Задачи» рядом с «Привычки»; вкладка «Задачи» показывает необязательные активности на выбранную дату с тем же поведением отметки, пустого состояния и создания, что и «Привычки».
- Веб-клиент: форма создания на вкладке «Задачи» создаёт активность типа `TASK`, форма «Привычки» — типа `HABIT`.
- Веб-клиент: вкладка «Статистика» показывает оба типа в одной матрице, визуально разделяя строки по типу, чтобы виды активностей были различимы.
- Правила обязательности (необязательные задачи не блокируют выполнение привычек) не вводят новых ограничений на отметку; различия между типами — только признак типа, отображение и выбор вкладки.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `tracker-habits`: ввести тип активности `HABIT`/`TASK`; создание, редактирование, список на дату и история учитывают и возвращают тип; общие правила (название, дата начала, периодичность, отметка/отмена, изоляция по пользователю, часовой пояс) распространяются на оба типа.
- `web-tracker`: добавить вкладку «Задачи» с тем же поведением, что у «Привычки»; кнопка создания создаёт активность выбранного типа; статистика отображает оба типа в одной матрице с визуальным разделением по типу.

## Impact

- `backend/tracker`: сущность активности и enum типа, миграция `V3`, `HabitService`, `HabitController`, DTO (`HabitRequest`, `HabitResponse`, `HabitOnDateResponse`, `HabitHistoryResponse`), unit- и интеграционные тесты.
- `client/web`: `src/pages/TrackerPage.jsx`, `src/tracker/HabitsTab.jsx` (вынос/обобщение), новая вкладка задач, `src/tracker/HabitFormModal.jsx`, `src/tracker/StatisticsTab.jsx`, `src/api/trackerApi.js`, тесты `test/tracker/*`.
- `backend/gateway`: изменения маршрутизации не требуются — используется существующий префикс `/tracker`.
- Поведение API: у `POST /tracker/habits` появляется обязательное поле типа; список на дату и история начинают возвращать тип и поддерживать выбор типа для списка. Существующие данные получают тип `HABIT`.
