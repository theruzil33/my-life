## ADDED Requirements

### Requirement: Изменение частей дня у существующей активности

Вкладки «Привычки» и «Задачи» SHALL предоставлять для каждой активности действие настройки частей дня, открывающее окно с текущим набором частей дня и возможностью выбрать «Утро», «День» и «Вечер». Окно SHALL позволять оставить набор пустым и MUST NOT позволять выбрать одну и ту же часть дня дважды. Сохранение MUST изменять только набор частей дня и MUST NOT изменять название, дату начала, периодичность, тип или уже сохранённые отметки выполнения активности. При успешном сохранении веб-клиент SHALL закрыть окно и обновить отображение активности с учётом нового набора частей дня. Если запрос завершился ошибкой, веб-клиент SHALL показать сообщение об ошибке и MUST NOT менять отображаемый набор частей дня. Пока запрос сохранения выполняется, повторная отправка MUST быть недоступна.

#### Scenario: Открытие настройки частей дня

- **WHEN** пользователь на вкладке «Привычки» или «Задачи» выбирает действие настройки частей дня у активности
- **THEN** веб-клиент показывает окно с текущим набором частей дня активности

#### Scenario: Успешное изменение частей дня

- **WHEN** пользователь отмечает части дня «Утро» и «Вечер» и подтверждает сохранение
- **THEN** веб-клиент отправляет в трекер новый набор частей дня и после успеха показывает у активности чекбоксы «Утро» и «Вечер»

#### Scenario: Очистка набора частей дня

- **WHEN** пользователь снимает все части дня и подтверждает сохранение
- **THEN** веб-клиент отправляет в трекер пустой набор частей дня и после успеха показывает у активности один общий чекбокс выполнения

#### Scenario: Изменение частей дня не меняет расписание и название

- **WHEN** пользователь изменяет набор частей дня активности
- **THEN** веб-клиент передаёт название, дату начала и периодичность без изменений, и активность сохраняет прежнее расписание

#### Scenario: Отмена настройки частей дня

- **WHEN** пользователь закрывает окно настройки частей дня без подтверждения
- **THEN** веб-клиент не отправляет запрос и оставляет прежний набор частей дня

#### Scenario: Ошибка трекера при изменении частей дня

- **WHEN** запрос изменения частей дня завершается ошибкой трекера
- **THEN** веб-клиент показывает сообщение об ошибке и сохраняет прежний набор частей дня

#### Scenario: Повторное сохранение частей дня недоступно во время запроса

- **WHEN** запрос изменения частей дня ещё выполняется
- **THEN** веб-клиент не позволяет подтвердить сохранение повторно

## MODIFIED Requirements

### Requirement: Список привычек на выбранную дату

Вкладка «Привычки» SHALL отображать обязательные привычки (тип `HABIT`) пользователя, запланированные на выбранную дату, получая их из API трекера. Для каждой привычки SHALL отображаться её название. Для привычки с частями дня SHALL отображаться отдельный чекбокс с текущим признаком выполнения на выбранную дату для каждой её части дня, подписанный названием этой части дня. Для привычки без частей дня SHALL отображаться один общий чекбокс с текущим признаком выполнения на выбранную дату. По умолчанию SHALL использоваться сегодняшняя дата. Пользователь SHALL иметь возможность выбрать любую дату не позже сегодняшней, включая прошлые даты; выбор будущей даты MUST быть недоступен. Если на выбранную дату у пользователя нет запланированных привычек, вкладка SHALL показывать пустое состояние вместо списка.

#### Scenario: По умолчанию используется сегодняшняя дата

- **WHEN** пользователь открывает вкладку «Привычки», не выбирая дату
- **THEN** веб-клиент запрашивает у трекера привычки на сегодняшнюю дату и отображает их

#### Scenario: Выбор прошлой даты показывает исторические отметки

- **WHEN** пользователь выбирает дату в прошлом
- **THEN** веб-клиент отображает привычки, запланированные на эту дату, с признаком выполнения именно на эту дату

#### Scenario: Будущая дата недоступна для выбора

- **WHEN** пользователь открывает выбор даты на вкладке «Привычки»
- **THEN** веб-клиент не позволяет выбрать дату позже сегодняшней и не отправляет запрос на будущую дату

#### Scenario: Пустое состояние при отсутствии привычек на дату

- **WHEN** на выбранную дату у пользователя нет запланированных привычек
- **THEN** вкладка показывает пустое состояние вместо списка привычек

#### Scenario: Отображаются только обязательные привычки

- **WHEN** у пользователя на выбранную дату есть и привычки, и задачи
- **THEN** вкладка «Привычки» показывает только привычки и не показывает задачи

#### Scenario: Привычка с частями дня показывается одной строкой с отдельными чекбоксами

- **WHEN** на выбранную дату у пользователя есть привычка с частями дня «Утро» и «Вечер»
- **THEN** вкладка показывает одну строку с названием привычки и двумя чекбоксами, подписанными «Утро» и «Вечер»

#### Scenario: Привычка без частей дня показывается с общим чекбоксом

- **WHEN** на выбранную дату у пользователя есть привычка без частей дня
- **THEN** вкладка показывает одну строку с названием привычки и одним общим чекбоксом выполнения

#### Scenario: Индикация загрузки списка

- **WHEN** веб-клиент запрашивает список привычек на выбранную дату
- **THEN** вкладка показывает признак загрузки до получения ответа трекера

### Requirement: Вкладка «Задачи»

Страница трекера SHALL содержать вкладку «Задачи» для необязательных активностей (тип `TASK`) и SHALL вести их по тем же правилам, что и вкладка «Привычки»: список на выбранную дату, чекбоксы отметки и снятия выполнения, кнопка добавления и модальное окно создания. Для каждой задачи SHALL отображаться её название. Для задачи с частями дня SHALL отображаться отдельный чекбокс с текущим признаком выполнения на выбранную дату для каждой её части дня, подписанный названием этой части дня. Для задачи без частей дня SHALL отображаться один общий чекбокс. По умолчанию SHALL использоваться сегодняшняя дата; пользователь SHALL иметь возможность выбрать любую дату не позже сегодняшней. Если на выбранную дату задач нет, вкладка SHALL показывать пустое состояние; при загрузке — признак загрузки; при ошибке трекера — понятное сообщение об ошибке без устаревших данных.

#### Scenario: По умолчанию используется сегодняшняя дата

- **WHEN** пользователь открывает вкладку «Задачи», не выбирая дату
- **THEN** веб-клиент запрашивает у трекера задачи на сегодняшнюю дату и отображает их

#### Scenario: Отметка выполнения задачи

- **WHEN** пользователь устанавливает чекбокс невыполненной задачи на выбранную дату
- **THEN** веб-клиент отправляет в трекер отметку выполнения и показывает задачу как выполненную

#### Scenario: Снятие отметки выполнения задачи

- **WHEN** пользователь снимает чекбокс выполненной задачи на выбранную дату
- **THEN** веб-клиент отправляет в трекер отмену выполнения и показывает задачу как невыполненную

#### Scenario: Задача с частями дня показывается одной строкой с отдельными чекбоксами

- **WHEN** на выбранную дату у пользователя есть задача с частями дня «Утро» и «Вечер»
- **THEN** вкладка показывает одну строку с названием задачи и двумя чекбоксами, подписанными «Утро» и «Вечер»

#### Scenario: Задача без частей дня показывается с общим чекбоксом

- **WHEN** на выбранную дату у пользователя есть задача без частей дня
- **THEN** вкладка показывает одну строку с названием задачи и одним общим чекбоксом выполнения

#### Scenario: Пустое состояние при отсутствии задач на дату

- **WHEN** на выбранную дату у пользователя нет запланированных задач
- **THEN** вкладка показывает пустое состояние вместо списка

#### Scenario: Индикация загрузки списка задач

- **WHEN** веб-клиент запрашивает список задач на выбранную дату
- **THEN** вкладка показывает признак загрузки до получения ответа трекера

#### Scenario: Ошибка загрузки списка задач

- **WHEN** запрос списка задач на выбранную дату завершается сетевой ошибкой или ошибкой сервера
- **THEN** вкладка показывает сообщение об ошибке и не показывает список задач

### Requirement: Отметка и снятие выполнения на выбранную дату

Каждый чекбокс активности SHALL отмечать выполнение на выбранную дату для своей части дня, а для активности без частей дня — общее выполнение на эту дату. Снятие чекбокса SHALL отменять соответствующую отметку. Веб-клиент SHALL передавать в запросе отметки выбранную дату и, для активности с частями дня, часть дня этого чекбокса. После успешного ответа трекера состояние чекбокса SHALL соответствовать сохранённому признаку выполнения. Если запрос завершился ошибкой, веб-клиент SHALL показать сообщение об ошибке и MUST NOT оставлять чекбокс в изменённом состоянии. Пока запрос отметки выполняется, повторное переключение этого чекбокса MUST быть недоступно; переключение других чекбоксов этой же активности и других активностей SHALL оставаться доступным.

#### Scenario: Отметка выполнения

- **WHEN** пользователь устанавливает чекбокс невыполненной привычки на выбранную дату
- **THEN** веб-клиент отправляет в трекер отметку выполнения на эту дату и показывает привычку как выполненную

#### Scenario: Снятие отметки выполнения

- **WHEN** пользователь снимает чекбокс выполненной привычки на выбранную дату
- **THEN** веб-клиент отправляет в трекер отмену выполнения на эту дату и показывает привычку как невыполненную

#### Scenario: Отметка отдельной части дня

- **WHEN** пользователь устанавливает чекбокс части дня «Утро» у активности с частями дня «Утро» и «Вечер»
- **THEN** веб-клиент отправляет в трекер отметку с частью дня «Утро» и оставляет чекбокс части «Вечер» без изменений

#### Scenario: Снятие отметки отдельной части дня

- **WHEN** пользователь снимает чекбокс части дня «Вечер» у активности, где отмечены части «Утро» и «Вечер»
- **THEN** веб-клиент отправляет в трекер отмену выполнения с частью дня «Вечер» и оставляет чекбокс части «Утро» установленным

#### Scenario: Ошибка отметки возвращает чекбокс в исходное состояние

- **WHEN** запрос отметки или отмены выполнения завершается ошибкой трекера
- **THEN** веб-клиент показывает сообщение об ошибке и возвращает чекбокс в состояние до запроса

#### Scenario: Чекбокс заблокирован во время запроса

- **WHEN** запрос отметки выполнения для чекбокса ещё выполняется
- **THEN** веб-клиент не позволяет повторно переключить этот чекбокс

### Requirement: Создание активности через модальное окно с датой начала не в будущем

Вкладки «Привычки» и «Задачи» SHALL предоставлять кнопку добавления, открывающую кастомное модальное окно создания активности. Модальное окно SHALL содержать поля названия, даты начала, периодичности и частей дня; периодичность SHALL задаваться выбором между ежедневной и конкретными днями недели, при этом выбор дней недели SHALL быть доступен при периодичности «конкретные дни недели». Части дня SHALL задаваться необязательным набором флажков «Утро», «День» и «Вечер»; по умолчанию набор SHALL быть пустым. Тип создаваемой активности SHALL определяться вкладкой, из которой открыто окно: из вкладки «Привычки» создаётся активность типа `HABIT`, из вкладки «Задачи» — типа `TASK`. Веб-клиент SHALL проверять перед отправкой, что название непустое, дата начала не позже сегодняшней, а периодичность заполнена, и MUST NOT отправлять запрос при нарушении этих условий, показывая причину. Веб-клиент SHALL NOT позволять выбрать будущую дату начала. При успешном создании веб-клиент SHALL закрыть модальное окно и обновить список активностей соответствующей вкладки за выбранную дату.

#### Scenario: Открытие модального окна

- **WHEN** пользователь нажимает кнопку добавления на вкладке «Привычки» или «Задачи»
- **THEN** веб-клиент показывает модальное окно с полями названия, даты начала, периодичности и частей дня

#### Scenario: Создание ежедневной привычки

- **WHEN** пользователь на вкладке «Привычки» заполняет название, дату начала не позже сегодняшней и выбирает ежедневную периодичность, затем подтверждает создание
- **THEN** веб-клиент отправляет запрос создания активности типа `HABIT` в трекер, закрывает модальное окно и обновляет список привычек

#### Scenario: Создание задачи

- **WHEN** пользователь на вкладке «Задачи» заполняет название, дату начала не позже сегодняшней и периодичность, затем подтверждает создание
- **THEN** веб-клиент отправляет запрос создания активности типа `TASK` в трекер, закрывает модальное окно и обновляет список задач

#### Scenario: Создание активности с частями дня

- **WHEN** пользователь отмечает флажки «Утро» и «Вечер» и подтверждает создание активности
- **THEN** веб-клиент отправляет запрос создания с набором частей дня «Утро» и «Вечер» и после успеха показывает у активности отдельные чекбоксы частей дня

#### Scenario: Создание активности со всеми частями дня

- **WHEN** пользователь отмечает флажки «Утро», «День» и «Вечер» и подтверждает создание активности
- **THEN** веб-клиент отправляет запрос создания с набором из трёх частей дня

#### Scenario: Создание активности без частей дня

- **WHEN** пользователь не отмечает ни одного флажка частей дня и подтверждает создание активности
- **THEN** веб-клиент отправляет запрос создания с пустым набором частей дня и после успеха показывает у активности один общий чекбокс выполнения

#### Scenario: Создание привычки с прошлой датой начала

- **WHEN** пользователь на вкладке «Привычки» заполняет название, дату начала в прошлом и периодичность, затем подтверждает создание
- **THEN** веб-клиент отправляет запрос создания в трекер, закрывает модальное окно и обновляет список привычек

#### Scenario: Создание привычки по конкретным дням недели

- **WHEN** пользователь выбирает периодичность «конкретные дни недели» и отмечает хотя бы один день недели, затем подтверждает создание
- **THEN** веб-клиент отправляет запрос создания с выбранными днями недели и после успеха закрывает модальное окно

#### Scenario: Дни недели доступны только для соответствующей периодичности

- **WHEN** в модальном окне выбрана ежедневная периодичность
- **THEN** веб-клиент не предлагает выбирать дни недели и не отправляет их в запросе

#### Scenario: Отклонение создания без названия

- **WHEN** пользователь подтверждает создание с пустым названием
- **THEN** веб-клиент не отправляет запрос и показывает сообщение о необходимости указать название

#### Scenario: Отклонение создания с датой начала в будущем

- **WHEN** пользователь подтверждает создание с датой начала позже сегодняшней
- **THEN** веб-клиент не отправляет запрос и показывает сообщение о недопустимой дате начала

#### Scenario: Будущая дата начала недоступна для выбора

- **WHEN** пользователь открывает выбор даты начала в модальном окне
- **THEN** веб-клиент не позволяет выбрать дату позже сегодняшней

#### Scenario: Отклонение создания без периодичности

- **WHEN** пользователь выбирает периодичность «конкретные дни недели», не отметив ни одного дня, и подтверждает создание
- **THEN** веб-клиент не отправляет запрос и показывает сообщение о необходимости выбрать периодичность

#### Scenario: Закрытие модального окна без создания

- **WHEN** пользователь закрывает модальное окно, не подтвердив создание
- **THEN** веб-клиент не создаёт активность и не меняет список активностей

#### Scenario: Ошибка трекера при создании

- **WHEN** запрос создания активности завершается ошибкой трекера
- **THEN** веб-клиент показывает сообщение об ошибке, оставляет модальное окно открытым с введёнными значениями и не обновляет список

#### Scenario: Повторная отправка формы создания недоступна

- **WHEN** запрос создания активности ещё выполняется
- **THEN** веб-клиент не позволяет подтвердить создание повторно

### Requirement: Переименование активности в списке

Вкладки «Привычки» и «Задачи» SHALL предоставлять для каждой активности действие переименования, открывающее окно ввода нового названия с текущим названием активности. Переименование MUST изменять только название и MUST NOT изменять дату начала, периодичность, тип, набор частей дня или отметки выполнения активности. Веб-клиент SHALL проверять перед отправкой, что название непустое, и MUST NOT отправлять запрос при пустом названии, показывая причину. При успешном переименовании веб-клиент SHALL закрыть окно и показать обновлённое название в списке. Если запрос завершился ошибкой, веб-клиент SHALL показать сообщение об ошибке и MUST NOT менять отображаемое название. Пока запрос переименования выполняется, повторная отправка MUST быть недоступна.

#### Scenario: Открытие переименования

- **WHEN** пользователь на вкладке «Привычки» или «Задачи» выбирает действие переименования у активности
- **THEN** веб-клиент показывает окно с текущим названием активности для ввода нового названия

#### Scenario: Успешное переименование

- **WHEN** пользователь вводит непустое новое название и подтверждает переименование
- **THEN** веб-клиент отправляет в трекер изменение названия активности и после успеха показывает новое название в списке

#### Scenario: Переименование не меняет расписание и отметки

- **WHEN** пользователь переименовывает активность, у которой заданы дата начала и периодичность и есть отметки выполнения
- **THEN** веб-клиент передаёт дату начала и периодичность без изменений, и активность сохраняет прежнее расписание и отметки

#### Scenario: Переименование не меняет части дня

- **WHEN** пользователь переименовывает активность с частями дня «Утро» и «Вечер»
- **THEN** веб-клиент передаёт набор частей дня без изменений, и активность сохраняет прежние части дня и их отметки

#### Scenario: Переименование задачи

- **WHEN** пользователь на вкладке «Задачи» переименовывает задачу
- **THEN** веб-клиент отправляет изменение названия задачи и показывает новое название в списке задач

#### Scenario: Отклонение переименования без названия

- **WHEN** пользователь подтверждает переименование с пустым названием
- **THEN** веб-клиент не отправляет запрос и показывает сообщение о необходимости указать название

#### Scenario: Отмена переименования

- **WHEN** пользователь закрывает окно переименования без подтверждения
- **THEN** веб-клиент не отправляет запрос и оставляет прежнее название в списке

#### Scenario: Ошибка трекера при переименовании

- **WHEN** запрос переименования завершается ошибкой трекера
- **THEN** веб-клиент показывает сообщение об ошибке и сохраняет прежнее название в списке

#### Scenario: Повторная отправка переименования недоступна

- **WHEN** запрос переименования ещё выполняется
- **THEN** веб-клиент не позволяет подтвердить переименование повторно

### Requirement: Матрица статистики выполнения

Вкладка «Статистика» SHALL отображать выполнение активностей пользователя в виде матрицы: строки соответствуют частям дня активностей, а столбцы — дням выбранного диапазона. Для активности с частями дня SHALL отображаться отдельная строка для каждой её части дня; для активности без частей дня SHALL отображаться одна общая строка. Каждая строка SHALL содержать название активности и название части дня для активности с частями дня. Матрица SHALL включать активности обоих типов (`HABIT` и `TASK`) и SHALL визуально разделять строки по типу активности, чтобы привычки и задачи были различимы. Квадрат запланированного и выполненного дня SHALL отображаться закрашенным; квадрат запланированного и невыполненного дня SHALL отображаться незакрашенным; дни, не соответствующие периодичности активности, SHALL отображаться визуально отличными от запланированных. Матрица SHALL позволять различить, какая строка относится к какой активности и части дня и какой столбец — к какой дате. Если у пользователя нет активностей в выбранном диапазоне, вкладка SHALL показывать пустое состояние.

#### Scenario: Выполненные дни закрашены

- **WHEN** пользователь открывает вкладку «Статистика», и часть активностей отмечена выполненной на дни выбранного диапазона
- **THEN** для этих активностей и дней отображаются закрашенные квадраты

#### Scenario: Невыполненные запланированные дни не закрашены

- **WHEN** у активности есть запланированный день в выбранном диапазоне без отметки выполнения
- **THEN** квадрат этого дня для этой активности отображается незакрашенным

#### Scenario: Не запланированные дни визуально отличимы

- **WHEN** день выбранного диапазона не соответствует периодичности активности
- **THEN** квадрат этого дня для этой активности визуально отличается от запланированных дней

#### Scenario: Части дня отображаются отдельными строками

- **WHEN** в выбранном диапазоне у пользователя есть активность с частями дня «Утро» и «Вечер»
- **THEN** веб-клиент отображает для неё две строки с названием активности и подписями «Утро» и «Вечер»

#### Scenario: Отметка одной части дня не закрашивает другую

- **WHEN** у активности с частями дня «Утро» и «Вечер» на день диапазона отмечена только часть «Утро»
- **THEN** квадрат дня в строке части «Утро» отображается закрашенным, а в строке части «Вечер» — незакрашенным

#### Scenario: Активность без частей дня отображается одной строкой

- **WHEN** в выбранном диапазоне у пользователя есть активность без частей дня
- **THEN** веб-клиент отображает для неё одну строку без подписи части дня

#### Scenario: Привычки и задачи различимы в матрице

- **WHEN** в выбранном диапазоне у пользователя есть и привычки, и задачи
- **THEN** веб-клиент отображает их в одной матрице и визуально разделяет строки по типу активности

#### Scenario: Строки и столбцы подписаны

- **WHEN** пользователь просматривает матрицу статистики
- **THEN** веб-клиент отображает названия активностей и частей дня для строк и даты для столбцов

#### Scenario: Пустое состояние без привычек

- **WHEN** в выбранном диапазоне у пользователя нет активностей с запланированными днями
- **THEN** вкладка статистики показывает пустое состояние вместо матрицы

#### Scenario: Индикация загрузки статистики

- **WHEN** веб-клиент запрашивает данные статистики за диапазон
- **THEN** вкладка показывает признак загрузки до получения ответа трекера
