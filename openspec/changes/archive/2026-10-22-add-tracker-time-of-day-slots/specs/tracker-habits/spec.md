## ADDED Requirements

### Requirement: Части дня активности

Tracker SHALL хранить у каждой активности набор частей дня. Часть дня MUST быть одним из `MORNING` (утро), `DAY` (день) или `EVENING` (вечер). Набор MUST содержать не более трёх частей дня, MUST NOT содержать повторяющихся значений и MAY быть пустым. Набор частей дня MUST задаваться при создании активности и MAY изменяться при редактировании. Набор MUST возвращаться во всех ответах на чтение активности. Правило SHALL применяться единообразно к активностям обоих типов (`HABIT` и `TASK`).

При изменении набора частей дня уже сохранённые отметки выполнения MUST NOT удаляться и MUST NOT изменяться. Отметки, относящиеся к части дня, которой больше нет в наборе, MUST NOT возвращаться в списке на дату и истории, пока эта часть дня не будет добавлена обратно.

#### Scenario: Создание активности с двумя частями дня

- **WHEN** аутентифицированный пользователь создаёт активность с корректными данными и набором частей дня «утро» и «вечер»
- **THEN** tracker сохраняет активность с этими частями дня и возвращает их в ответе

#### Scenario: Создание активности со всеми тремя частями дня

- **WHEN** аутентифицированный пользователь создаёт активность с набором частей дня «утро», «день» и «вечер»
- **THEN** tracker сохраняет активность со всеми тремя частями дня

#### Scenario: Создание активности без частей дня

- **WHEN** аутентифицированный пользователь создаёт активность, не указывая части дня
- **THEN** tracker сохраняет активность с пустым набором частей дня

#### Scenario: Отклонение повторяющейся части дня

- **WHEN** аутентифицированный пользователь создаёт или редактирует активность с набором, где одна и та же часть дня указана несколько раз
- **THEN** tracker отклоняет запрос ошибкой валидации и не сохраняет активность

#### Scenario: Отклонение неизвестной части дня

- **WHEN** аутентифицированный пользователь создаёт или редактирует активность с частью дня, отличной от `MORNING`, `DAY` и `EVENING`
- **THEN** tracker отклоняет запрос ошибкой валидации и не сохраняет активность

#### Scenario: Части дня возвращаются при чтении

- **WHEN** аутентифицированный пользователь запрашивает список активностей на дату или историю
- **THEN** tracker возвращает для каждой активности её набор частей дня

#### Scenario: Изменение набора частей дня сохраняет прежние отметки

- **WHEN** аутентифицированный пользователь изменяет набор частей дня активности, у которой есть отметки выполнения
- **THEN** tracker сохраняет все ранее созданные отметки и не изменяет их

#### Scenario: Отметки удалённой части дня скрыты до её возвращения

- **WHEN** аутентифицированный пользователь убирает часть дня из набора активности, а затем снова добавляет её
- **THEN** пока часть дня отсутствует, её отметки не возвращаются в списке и истории, а после возвращения части дня снова отображаются

#### Scenario: Части дня применяются к задаче

- **WHEN** аутентифицированный пользователь создаёт активность типа `TASK` с частями дня «утро» и «день»
- **THEN** tracker сохраняет задачу с этими частями дня и возвращает их в ответе

## MODIFIED Requirements

### Requirement: Список привычек на дату

Tracker SHALL предоставлять эндпоинт, возвращающий активности аутентифицированного пользователя, запланированные на указанную дату, с признаком того, отмечена ли каждая из них на эту дату. Дата MUST передаваться необязательным параметром в формате ISO (`yyyy-MM-dd`); если параметр отсутствует, MUST использоваться сегодняшняя дата в настроенном часовом поясе сервиса. Tracker SHALL поддерживать необязательный параметр типа, ограничивающий список одним типом (`HABIT` или `TASK`); если параметр типа отсутствует, SHALL возвращаться активности обоих типов. Каждая активность в ответе MUST содержать свой тип и набор частей дня. Для активности с частями дня ответ MUST содержать отдельный признак выполнения на указанную дату для каждой её части дня. Для активности без частей дня ответ MUST содержать общий признак выполнения на указанную дату. Привычка SHALL попадать в список, если на указанную дату наступила или прошла её дата начала и день недели этой даты соответствует её периодичности. Будущие даты MUST быть допустимы: для них возвращаются активности, запланированные на эту дату.

Если указанная дата раньше самой ранней даты начала среди активностей пользователя, tracker SHALL возвращать пустой список без ошибки. Если у пользователя нет активностей, tracker SHALL возвращать пустой список без ошибки.

#### Scenario: Список на дату без параметра использует сегодня

- **WHEN** аутентифицированный пользователь запрашивает список активностей без параметра даты
- **THEN** tracker формирует список на сегодняшнюю дату в настроенном часовом поясе сервиса

#### Scenario: Ежедневная привычка попадает в список на запрошенную дату

- **WHEN** аутентифицированный пользователь запрашивает список на дату, и у него есть ежедневная привычка, дата начала которой наступила к этой дате
- **THEN** tracker включает эту привычку в список

#### Scenario: Список на прошлую дату отражает исторические отметки

- **WHEN** аутентифицированный пользователь запрашивает список на прошлую дату, и часть его активностей была отмечена на эту дату
- **THEN** tracker возвращает активности, запланированные на эту дату, с признаком выполнения именно на эту дату

#### Scenario: Привычка с будущей датой начала не попадает в список

- **WHEN** аутентифицированный пользователь запрашивает список на дату, и у него есть активность, дата начала которой позже запрошенной даты
- **THEN** tracker не включает эту активность в список

#### Scenario: Привычка, не запланированная на запрошенную дату, не попадает в список

- **WHEN** аутентифицированный пользователь запрашивает список на дату, и у него есть активность с периодичностью по конкретным дням недели, среди которых нет дня недели запрошенной даты
- **THEN** tracker не включает эту активность в список

#### Scenario: Признак выполнения отражает отметку на запрошенную дату

- **WHEN** аутентифицированный пользователь запрашивает список на дату, и часть его активностей уже отмечена на эту дату
- **THEN** tracker возвращает для каждой активности признак, показывающий, отмечена ли она на эту дату

#### Scenario: Признаки выполнения возвращаются отдельно по частям дня

- **WHEN** аутентифицированный пользователь запрашивает список на дату, и у активности с частями дня «утро» и «вечер» отмечена только часть «утро»
- **THEN** tracker возвращает активность с признаком выполнения «утро» равным «выполнено» и признаком выполнения «вечер» равным «не выполнено»

#### Scenario: Активность без частей дня возвращает общий признак

- **WHEN** аутентифицированный пользователь запрашивает список на дату, и у активности без частей дня есть отметка на эту дату
- **THEN** tracker возвращает активность с общим признаком выполнения на эту дату

#### Scenario: Список с указанным типом содержит только этот тип

- **WHEN** аутентифицированный пользователь запрашивает список на дату с параметром типа `TASK`, и у него есть активности обоих типов
- **THEN** tracker возвращает только задачи с типом `TASK` и не включает привычки

#### Scenario: Список без типа содержит оба типа

- **WHEN** аутентифицированный пользователь запрашивает список на дату без параметра типа, и у него есть привычки и задачи, запланированные на эту дату
- **THEN** tracker включает в список активности обоих типов с указанием типа каждой

#### Scenario: Список на будущую дату допустим

- **WHEN** аутентифицированный пользователь запрашивает список на будущую дату
- **THEN** tracker возвращает активности, запланированные на эту дату, и не отвечает ошибкой

#### Scenario: Пустой список на дату раньше самой ранней привычки

- **WHEN** аутентифицированный пользователь запрашивает список на дату, которая раньше самой ранней даты начала среди всех его активностей
- **THEN** tracker возвращает пустой список без ошибки

#### Scenario: Пустой список при отсутствии привычек

- **WHEN** аутентифицированный пользователь без активностей запрашивает список на любую дату
- **THEN** tracker возвращает пустой список без ошибки

### Requirement: История привычек за диапазон дат

Tracker SHALL предоставлять эндпоинт, возвращающий одним запросом активности аутентифицированного пользователя и их статусы выполнения за диапазон дат. В ответ MUST включаться активности обоих типов, и каждая активность MUST содержать свой тип и набор частей дня. Диапазон MUST задаваться обязательными параметрами `from` и `to` в формате ISO (`yyyy-MM-dd`) и MUST трактоваться включительно с обеих сторон. Для каждой активности SHALL возвращаться статус выполнения на каждый запланированный день диапазона отдельно для каждой её части дня; для активности без частей дня SHALL возвращаться один статус на каждый запланированный день. Каждый статус MUST указывать часть дня, к которой он относится, либо её отсутствие для активности без частей дня. Дни, не соответствующие периодичности активности, в ответе MUST NOT перечисляться, а активности без запланированных в диапазоне дней MUST NOT включаться в ответ. Будущие даты в границах диапазона MUST быть допустимы.

Tracker SHALL отвечать ошибкой валидации (`400` с сообщением), если `from` позже `to`. Если `from` раньше самой ранней даты начала среди активностей пользователя, tracker SHALL возвращать пустой список без ошибки. Если у пользователя нет активностей, tracker SHALL возвращать пустой список без ошибки.

#### Scenario: История за прошлый диапазон

- **WHEN** аутентифицированный пользователь запрашивает историю за диапазон прошлых дат, и часть его активностей была отмечена в этом диапазоне
- **THEN** tracker возвращает для каждой активности дни диапазона, соответствующие её периодичности, с признаком выполнения на каждый из этих дней

#### Scenario: История включает активности обоих типов с типом

- **WHEN** аутентифицированный пользователь запрашивает историю за диапазон, в котором есть привычки и задачи
- **THEN** tracker возвращает активность каждого типа с указанием её типа

#### Scenario: История возвращает статусы отдельно по частям дня

- **WHEN** аутентифицированный пользователь запрашивает историю за диапазон, и у активности с частями дня «утро» и «вечер» отмечена только часть «утро» на один из дней
- **THEN** tracker возвращает для этого дня отдельные статусы «утро» и «вечер», где «утро» выполнено, а «вечер» не выполнено

#### Scenario: История активности без частей дня возвращает один статус на день

- **WHEN** аутентифицированный пользователь запрашивает историю за диапазон, и у активности нет частей дня
- **THEN** tracker возвращает один статус на каждый запланированный день без указания части дня

#### Scenario: Не запланированные дни не перечисляются

- **WHEN** аутентифицированный пользователь запрашивает историю за диапазон, и у активности с периодичностью по конкретным дням недели есть дни диапазона вне этой периодичности
- **THEN** tracker не включает эти дни в ответ для данной активности

#### Scenario: Диапазон включает сегодня

- **WHEN** аутентифицированный пользователь запрашивает историю за диапазон, правая граница которого равна сегодняшней дате
- **THEN** tracker включает сегодняшний день в статусы активностей наравне с прошлыми днями

#### Scenario: Будущие даты в диапазоне допустимы

- **WHEN** аутентифицированный пользователь запрашивает историю с границей `to` в будущем
- **THEN** tracker возвращает статусы активностей на запланированные дни этого диапазона и не отвечает ошибкой

#### Scenario: Отклонение диапазона с from позже to

- **WHEN** аутентифицированный пользователь запрашивает историю, где `from` позже `to`
- **THEN** tracker отвечает ошибкой валидации (`400` с сообщением)

#### Scenario: Диапазон ниже самой ранней привычки допустим

- **WHEN** аутентифицированный пользователь запрашивает историю, где `from` раньше самой ранней даты начала среди всех его активностей
- **THEN** tracker возвращает статусы только по запланированным в диапазоне дням и не отвечает ошибкой

### Requirement: Отметка и отмена выполнения на дату

Tracker SHALL предоставлять эндпоинты отметки выполнения привычки и отмены выполнения, принимающие дату выполнения и необязательную часть дня. Отметка и отмена SHALL быть доступны для сегодняшней даты и для прошлых дат. Дата выполнения MUST NOT быть будущей датой, датой раньше даты начала привычки или датой, не соответствующей периодичности привычки; такие запросы MUST отклоняться ошибкой валидации.

Для активности с частями дня часть дня MUST быть указана и MUST входить в набор частей дня активности; иначе запрос MUST отклоняться ошибкой валидации. Для активности без частей дня часть дня MUST NOT быть указана; иначе запрос MUST отклоняться ошибкой валидации. Отметка и отмена SHALL изменять признак выполнения только указанной части дня для активности с частями дня либо общий признак выполнения для активности без частей дня. Повторная отметка уже отмеченной пары «активность + дата + часть дня» MUST NOT создавать дубликат; отмена неотмеченной пары MUST завершаться успешно без изменения состояния.

#### Scenario: Отметка выполнения на сегодня

- **WHEN** аутентифицированный пользователь отмечает выполнение своей привычки на сегодняшнюю дату, соответствующую её периодичности
- **THEN** tracker сохраняет отметку и возвращает привычку как выполненную на эту дату

#### Scenario: Отметка выполнения на прошлую дату

- **WHEN** аутентифицированный пользователь отмечает выполнение своей привычки на прошлую дату, которая не раньше даты начала привычки и соответствует её периодичности
- **THEN** tracker сохраняет отметку на эту дату

#### Scenario: Отмена выполнения на прошлую дату

- **WHEN** аутентифицированный пользователь отменяет выполнение своей привычки на дату, которая ранее была отмечена
- **THEN** tracker удаляет отметку на эту дату и возвращает привычку как невыполненную на эту дату

#### Scenario: Отметка отдельной части дня

- **WHEN** аутентифицированный пользователь отмечает часть дня «утро» активности с частями дня «утро» и «вечер»
- **THEN** tracker сохраняет отметку части «утро» и не отмечает часть «вечер»

#### Scenario: Отмена отдельной части дня

- **WHEN** аутентифицированный пользователь отменяет часть дня «вечер» активности, у которой ранее были отмечены части «утро» и «вечер»
- **THEN** tracker удаляет отметку части «вечер» и сохраняет отметку части «утро»

#### Scenario: Отклонение отметки без части дня для активности с частями дня

- **WHEN** аутентифицированный пользователь отмечает активность с частями дня, не указывая часть дня
- **THEN** tracker отклоняет запрос ошибкой валидации и не сохраняет отметку

#### Scenario: Отклонение отметки части дня вне набора активности

- **WHEN** аутентифицированный пользователь отмечает часть дня, которой нет в наборе частей дня активности
- **THEN** tracker отклоняет запрос ошибкой валидации и не сохраняет отметку

#### Scenario: Отклонение части дня для активности без частей дня

- **WHEN** аутентифицированный пользователь отмечает активность без частей дня, указывая часть дня
- **THEN** tracker отклоняет запрос ошибкой валидации и не сохраняет отметку

#### Scenario: Отклонение отметки на будущую дату

- **WHEN** аутентифицированный пользователь пытается отметить выполнение привычки на будущую дату
- **THEN** tracker отклоняет запрос ошибкой валидации и не сохраняет отметку

#### Scenario: Отклонение отметки на дату раньше начала привычки

- **WHEN** аутентифицированный пользователь пытается отметить выполнение привычки на дату раньше её даты начала
- **THEN** tracker отклоняет запрос ошибкой валидации и не сохраняет отметку

#### Scenario: Отклонение отметки на дату не по периодичности

- **WHEN** аутентифицированный пользователь пытается отметить выполнение привычки на дату, день недели которой не входит в её периодичность
- **THEN** tracker отклоняет запрос ошибкой валидации и не сохраняет отметку

#### Scenario: Повторная отметка не создаёт дубликат

- **WHEN** аутентифицированный пользователь повторно отмечает выполнение привычки на уже отмеченную дату и часть дня
- **THEN** tracker сохраняет единственную отметку на эту пару «дата + часть дня» без создания дубликата

#### Scenario: Отмена неотмеченной даты не изменяет состояние

- **WHEN** аутентифицированный пользователь отменяет выполнение привычки на дату, которая не была отмечена
- **THEN** tracker завершает запрос успешно и не изменяет набор отметок привычки

### Requirement: Автоматическая отметка прошлых дней при создании активности

Tracker SHALL принимать при создании активности необязательный булев признак «отметить прошлое выполненным». Если признак равен `true` и дата начала активности раньше сегодняшней даты в настроенном часовом поясе сервиса, tracker SHALL при создании сохранить отметки выполнения на все дни от даты начала включительно до дня, предшествующего сегодняшнему, которые соответствуют периодичности активности. Для активности с частями дня tracker SHALL сохранить отметку для каждой её части дня на каждый такой прошлый запланированный день. Для активности без частей дня tracker SHALL сохранить общую отметку на каждый такой прошлый запланированный день. Сегодняшний день MUST NOT отмечаться автоматически по этому признаку. Дни, не соответствующие периодичности, MUST NOT отмечаться. Если признак отсутствует или равен `false`, tracker MUST NOT создавать автоматические отметки. Правило SHALL применяться единообразно к активностям обоих типов (`HABIT` и `TASK`). Автоматически созданные отметки SHALL NOT отличаться от отметок, созданных вручную, и SHALL отражаться в списке на дату, истории и статистике.

#### Scenario: Отметка всех прошлых запланированных дней ежедневной активности

- **WHEN** аутентифицированный пользователь создаёт ежедневную активность с датой начала 7 дней назад и признаком «отметить прошлое выполненным», равным `true`
- **THEN** tracker сохраняет активность и отметки выполнения на каждый день от даты начала включительно до вчерашнего дня

#### Scenario: Отмечаются все части дня активности

- **WHEN** аутентифицированный пользователь создаёт активность с частями дня «утро» и «вечер», датой начала в прошлом и признаком «отметить прошлое выполненным», равным `true`
- **THEN** tracker сохраняет отметки и части «утро», и части «вечер» на каждый прошлый запланированный день

#### Scenario: Активность без частей дня получает общие отметки

- **WHEN** аутентифицированный пользователь создаёт активность без частей дня, датой начала в прошлом и признаком «отметить прошлое выполненным», равным `true`
- **THEN** tracker сохраняет общие отметки выполнения на каждый прошлый запланированный день

#### Scenario: Сегодняшний день не отмечается автоматически

- **WHEN** аутентифицированный пользователь создаёт активность с признаком «отметить прошлое выполненным», равным `true`, и датой начала в прошлом
- **THEN** tracker сохраняет отметки только на прошлые запланированные дни и не создаёт отметку на сегодняшний день

#### Scenario: Отмечаются только дни, соответствующие периодичности

- **WHEN** аутентифицированный пользователь создаёт активность с периодичностью по конкретным дням недели, датой начала в прошлом и признаком «отметить прошлое выполненным», равным `true`
- **THEN** tracker сохраняет отметки только на прошедшие дни, день недели которых входит в периодичность активности, и не создаёт отметки на остальные прошлые дни

#### Scenario: Непрошедшие дни не отмечаются

- **WHEN** аутентифицированный пользователь создаёт активность с датой начала, равной сегодняшней, и признаком «отметить прошлое выполненным», равным `true`
- **THEN** tracker сохраняет активность без автоматических отметок выполнения

#### Scenario: Признак отсутствует — автоматические отметки не создаются

- **WHEN** аутентифицированный пользователь создаёт активность с датой начала в прошлом, не передавая признак «отметить прошлое выполненным»
- **THEN** tracker сохраняет активность без автоматических отметок выполнения

#### Scenario: Признак применяется к задаче

- **WHEN** аутентифицированный пользователь создаёт активность типа `TASK` с датой начала в прошлом и признаком «отметить прошлое выполненным», равным `true`
- **THEN** tracker сохраняет задачу и отметки выполнения на её прошлые запланированные дни

#### Scenario: Отклонённое создание не создаёт отметок

- **WHEN** аутентифицированный пользователь отправляет создание активности с признаком «отметить прошлое выполненным», равным `true`, но с некорректными данными (пустое название, будущая дата начала или незаполненная периодичность)
- **THEN** tracker отклоняет запрос ошибкой валидации и не сохраняет ни активность, ни отметки выполнения
