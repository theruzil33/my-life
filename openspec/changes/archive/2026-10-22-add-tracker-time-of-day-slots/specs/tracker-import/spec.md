## MODIFIED Requirements

### Requirement: Разбор активностей, вариантов и типов файла

Tracker SHALL разбирать файл как CSV с запятой в роли разделителя полей. Строка активности SHALL содержать название в первом столбце, необязательный вариант во втором столбце, тип в третьем столбце и значения дней месяца в последующих столбцах. Тип SHALL определять вид активности: «Привычка» SHALL соответствовать типу `HABIT`, «Задача» — типу `TASK`. Строки без распознаваемого типа (заголовок таблицы, итоговые строки) MUST игнорироваться. Если название в строке не указано, названием SHALL считаться название из предыдущей строки-активности.

Вариант SHALL распознаваться как часть дня без учёта регистра и окружающих пробелов: значения «Утром», «Утро», «MORNING» SHALL соответствовать части дня `MORNING`; «Днём», «День», «Днем», «DAY» — части дня `DAY`; «Вечером», «Вечер», «EVENING» — части дня `EVENING`. Если вариант распознан как часть дня, tracker MUST NOT включать его в название активности, а MUST отнести строку к этой части дня. Если вариант не распознан как часть дня и непуст, tracker SHALL включить его в название активности, чтобы варианты одного названия (например, «На работе» и «Дома») считались разными активностями. Если вариант отсутствует, tracker SHALL использовать название активности без варианта.

Строки с одинаковыми типом и итоговым названием SHALL объединяться в одну активность, набор частей дня которой составляют все распознанные в этих строках части дня. Если у объединённой активности есть хотя бы одна строка с распознанной частью дня, строки без варианта для этой же активности MUST NOT создавать отметки выполнения. Tracker SHALL игнорировать окружающие пробелы в текстовых значениях.

#### Scenario: Распознавание типа активности

- **WHEN** строка файла содержит в столбце типа «Привычка» или «Задача»
- **THEN** tracker создаёт активность типа `HABIT` или `TASK` соответственно

#### Scenario: Строки без типа пропускаются

- **WHEN** файл содержит строку заголовка или итоговую строку без распознаваемого типа активности
- **THEN** tracker не создаёт по ней активность и не считает её ошибкой

#### Scenario: Пустое название продолжает предыдущую активность

- **WHEN** строка активности не содержит названия, а предыдущая строка-активность содержала название
- **THEN** tracker относит эту строку к активности с названием из предыдущей строки

#### Scenario: Вариант включается в название

- **WHEN** строка активности содержит название и непустой нераспознанный вариант во втором столбце (например, «На работе»)
- **THEN** tracker формирует название активности из названия и варианта так, что строки с разными вариантами дают разные активности

#### Scenario: Вариант отсутствует

- **WHEN** строка активности не содержит варианта во втором столбце
- **THEN** tracker использует название активности без варианта

#### Scenario: Вариант утра распознаётся как часть дня

- **WHEN** строка активности содержит вариант «Утром»
- **THEN** tracker относит строку к части дня `MORNING` и не включает вариант в название активности

#### Scenario: Варианты дня и вечера распознаются как части дня

- **WHEN** строка активности содержит вариант «Днём» или «Вечером»
- **THEN** tracker относит строку к части дня `DAY` или `EVENING` соответственно и не включает вариант в название активности

#### Scenario: Части дня распознаются без учёта регистра и пробелов

- **WHEN** строка активности содержит вариант « вечером » или «EVENING»
- **THEN** tracker относит строку к части дня `EVENING`

#### Scenario: Строки одной активности объединяются по частям дня

- **WHEN** файл содержит строку «Чистил зубы» с вариантом «Утром» и строку с пустым названием и вариантом «Вечером»
- **THEN** tracker формирует одну активность «Чистил зубы» с частями дня `MORNING` и `EVENING`

#### Scenario: Одинаковые названия разных типов не объединяются

- **WHEN** файл содержит строку «Чтение» типа «Привычка» с вариантом «Утром» и строку «Чтение» типа «Задача» с вариантом «Вечером»
- **THEN** tracker формирует две активности: `HABIT` с частью дня `MORNING` и `TASK` с частью дня `EVENING`

#### Scenario: Строка без варианта не создаёт отметок у активности с частями дня

- **WHEN** файл содержит для одной активности строки с вариантами «Утром» и «Вечером», а также строку без варианта с положительными значениями дней
- **THEN** tracker создаёт одну активность с частями дня `MORNING` и `EVENING` и не сохраняет отметки из строки без варианта

### Requirement: Сопоставление активностей по типу и названию

При импорте tracker SHALL сопоставлять активности файла с существующими активностями пользователя по типу и названию; распознанные части дня MUST NOT входить в название при сопоставлении. Если активности с такими типом и названием у пользователя нет, tracker SHALL создать её. Если такая активность уже есть, tracker SHALL переиспользовать её и MUST NOT создавать дубликат. Для новой активности дата начала SHALL быть первым числом выбранного месяца, периодичность — ежедневной, а набор частей дня SHALL состоять из всех распознанных в файле частей дня этой активности. При переиспользовании существующей активности tracker MUST NOT изменять её дату начала, периодичность, тип, название и набор частей дня.

Если существующая активность уже имеет части дня, отметки из файла SHALL сохраняться только для тех частей дня, которые входят в её текущий набор. Распознанные в файле части дня, которых нет у существующей активности, MUST NOT добавляться к ней и MUST NOT создавать отметки. Если существующая активность не имеет частей дня, распознанные в файле части дня MUST NOT добавляться к ней, а отметки по таким частям MUST NOT создаваться. Отметки из строк без варианта SHALL сохраняться для существующей активности без частей дня на общих основаниях.

#### Scenario: Отсутствующая активность создаётся

- **WHEN** аутентифицированный пользователь импортирует активность, для которой у него нет активности с такими типом и названием
- **THEN** tracker создаёт активность с этим типом и названием, привязанную к пользователю, с датой начала первого числа выбранного месяца и ежедневной периодичностью

#### Scenario: Новая активность создаётся с частями дня из файла

- **WHEN** аутентифицированный пользователь импортирует новую активность, представленную в файле строками с вариантами «Утром» и «Вечером»
- **THEN** tracker создаёт одну активность с набором частей дня `MORNING` и `EVENING`

#### Scenario: Существующая активность переиспользуется без дублирования

- **WHEN** аутентифицированный пользователь импортирует активность, для которой у него уже есть активность с такими типом и названием
- **THEN** tracker использует существующую активность и не создаёт вторую

#### Scenario: Активности различаются по типу и названию

- **WHEN** у пользователя есть активность типа `HABIT` с некоторым названием, а файл содержит активность типа `TASK` или иное название
- **THEN** tracker считает её отдельной и создаёт новую активность

#### Scenario: Расписание существующей активности не меняется

- **WHEN** tracker переиспользует существующую активность с собственной датой начала и периодичностью
- **THEN** дата начала, периодичность и тип существующей активности остаются без изменений

#### Scenario: Части дня существующей активности не меняются

- **WHEN** tracker переиспользует существующую активность с набором частей дня, отличным от набора в файле
- **THEN** набор частей дня существующей активности остаётся без изменений

#### Scenario: Отметки сохраняются только для существующих частей дня

- **WHEN** существующая активность имеет часть дня `MORNING`, а файл содержит для неё положительные значения в строках с частями дня `MORNING` и `EVENING`
- **THEN** tracker сохраняет отметки только для части дня `MORNING` и не добавляет часть дня `EVENING`

### Requirement: Заполнение отметок выполнения по дням месяца

Для каждой активности и каждого дня выбранного месяца tracker SHALL сохранять отметку выполнения, если в столбце этого дня указано значение строго больше нуля. Для активности с частями дня отметка SHALL сохраняться отдельно для каждой части дня, представленной строкой файла, и MUST NOT затрагивать другие части дня этой активности. Для активности без частей дня SHALL сохраняться общая отметка на дату. Пустое или нулевое значение дня MUST NOT создавать отметку. Дни за пределами длины выбранного месяца (например, 30 и 31 для февраля) MUST игнорироваться. Дни позже сегодняшней даты в настроенном часовом поясе сервиса MUST NOT создавать отметку. Повторная отметка на уже отмеченную пару «активность + дата + часть дня» (или «активность + дата» для активности без частей дня) MUST NOT создавать дубликат. Дни, не соответствующие расписанию активности (до её даты начала или вне её периодичности), MUST NOT отмечаться.

#### Scenario: Положительные значения дней создают отметки

- **WHEN** файл содержит для активности положительные значения в нескольких столбцах дней
- **THEN** tracker сохраняет отметку выполнения на каждый такой день выбранного месяца

#### Scenario: Отметки сохраняются по каждой части дня

- **WHEN** файл содержит для активности с частями дня `MORNING` и `EVENING` положительные значения в столбце дня в обеих строках
- **THEN** tracker сохраняет для этого дня отдельные отметки частей `MORNING` и `EVENING`

#### Scenario: Отметка одной части дня не создаёт отметку другой

- **WHEN** файл содержит для активности с частями дня `MORNING` и `EVENING` положительное значение дня только в строке части `MORNING`
- **THEN** tracker сохраняет отметку только для части `MORNING` и не создаёт отметку для части `EVENING`

#### Scenario: Нулевые и пустые дни не создают отметок

- **WHEN** в столбце дня указан ноль или значение отсутствует
- **THEN** tracker не создаёт отметку на этот день

#### Scenario: Повторный импорт не дублирует отметки

- **WHEN** аутентифицированный пользователь повторно импортирует файл, где для дня и части дня уже есть отметка
- **THEN** tracker сохраняет единственную отметку на эту пару «активность + дата + часть дня»

#### Scenario: Дни за пределами месяца игнорируются

- **WHEN** файл содержит значения в столбцах дней, которых нет в выбранном месяце
- **THEN** tracker не создаёт отметок на эти дни

#### Scenario: Будущие дни не отмечаются

- **WHEN** файл содержит положительное значение в столбце дня позже сегодняшней даты в настроенном часовом поясе сервиса
- **THEN** tracker не создаёт отметку на этот день

### Requirement: Результат импорта

Tracker SHALL возвращать в ответе на успешный импорт количество созданных активностей и количество сохранённых отметок выполнения. Созданной SHALL считаться уникальная активность после объединения строк файла по типу, названию и распознанным частям дня. Сохранённой отметкой SHALL считаться отметка конкретной части дня для активности с частями дня или общая отметка для активности без частей дня.

#### Scenario: Успешный импорт возвращает сводку

- **WHEN** аутентифицированный пользователь успешно импортирует файл
- **THEN** tracker возвращает количество созданных активностей и количество сохранённых отметок

#### Scenario: Объединённая активность считается один раз

- **WHEN** файл содержит одну активность строками с частями дня «Утром» и «Вечером», и такой активности у пользователя ещё нет
- **THEN** tracker возвращает в сводке одну созданную активность

#### Scenario: Отметки частей дня учитываются в сводке

- **WHEN** импорт сохраняет отметки частей дня «утро» и «вечер» на один и тот же день
- **THEN** tracker учитывает в сводке две сохранённые отметки
