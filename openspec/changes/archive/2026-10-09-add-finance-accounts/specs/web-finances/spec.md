## Purpose

Пользовательский интерфейс финансов в веб-клиенте: страница со списком счетов, добавление счёта с названием и начальной суммой через модальное окно и удаление счёта с подтверждением.

## ADDED Requirements

### Requirement: Доступ к странице финансов

Страница финансов SHALL быть доступна по адресу `/finances` и SHALL быть доступна только аутентифицированному пользователю.

#### Scenario: Аутентифицированный пользователь открывает финансы

- **WHEN** аутентифицированный пользователь открывает адрес `/finances`
- **THEN** веб-клиент показывает страницу финансов

#### Scenario: Неаутентифицированный пользователь открывает финансы

- **WHEN** пользователь без аутентифицированной сессии открывает адрес `/finances`
- **THEN** веб-клиент перенаправляет его на страницу входа и не показывает содержимое финансов

### Requirement: Список счетов на странице финансов

Страница финансов SHALL отображать все счета пользователя, получая их из API финансов. Для каждого счёта SHALL отображаться его название и начальная сумма. Если у пользователя нет счетов, страница SHALL показывать пустое состояние вместо списка. Во время загрузки страница SHALL показывать признак загрузки, а при ошибке загрузки — понятное сообщение об ошибке и MUST NOT показывать список.

#### Scenario: Список счетов отображается

- **WHEN** аутентифицированный пользователь открывает страницу финансов, и у него есть счета
- **THEN** веб-клиент показывает список этих счетов с названием и начальной суммой каждого

#### Scenario: Пустое состояние при отсутствии счетов

- **WHEN** аутентифицированный пользователь без счетов открывает страницу финансов
- **THEN** страница показывает пустое состояние вместо списка счетов

#### Scenario: Индикация загрузки списка

- **WHEN** веб-клиент запрашивает список счетов
- **THEN** страница показывает признак загрузки до получения ответа API финансов

#### Scenario: Ошибка загрузки списка счетов

- **WHEN** запрос списка счетов завершается сетевой ошибкой или ошибкой сервера
- **THEN** страница показывает сообщение об ошибке и не показывает список счетов

### Requirement: Создание счёта через модальное окно

Страница финансов SHALL предоставлять кнопку добавления, открывающую модальное окно создания счёта. Модальное окно SHALL содержать поля названия и начальной суммы. Веб-клиент SHALL проверять перед отправкой, что название непустое, а начальная сумма указана и является числом, и MUST NOT отправлять запрос при нарушении этих условий, показывая причину. При успешном создании веб-клиент SHALL закрыть модальное окно и обновить список счётов. Если запрос завершился ошибкой, веб-клиент SHALL показать сообщение об ошибке, оставить модальное окно открытым с введёнными значениями и MUST NOT обновлять список. Пока запрос создания выполняется, повторная отправка формы MUST быть недоступна.

#### Scenario: Открытие модального окна создания счёта

- **WHEN** пользователь нажимает кнопку добавления на странице финансов
- **THEN** веб-клиент показывает модальное окно с полями названия и начальной суммы

#### Scenario: Успешное создание счёта

- **WHEN** пользователь заполняет непустое название и начальную сумму и подтверждает создание
- **THEN** веб-клиент отправляет запрос создания в API финансов, закрывает модальное окно и обновляет список счетов

#### Scenario: Отклонение создания без названия

- **WHEN** пользователь подтверждает создание с пустым названием
- **THEN** веб-клиент не отправляет запрос и показывает сообщение о необходимости указать название

#### Scenario: Отклонение создания без суммы

- **WHEN** пользователь подтверждает создание без начальной суммы
- **THEN** веб-клиент не отправляет запрос и показывает сообщение о необходимости указать начальную сумму

#### Scenario: Закрытие модального окна без создания

- **WHEN** пользователь закрывает модальное окно, не подтвердив создание
- **THEN** веб-клиент не создаёт счёт и не меняет список счетов

#### Scenario: Ошибка API финансов при создании

- **WHEN** запрос создания счёта завершается ошибкой API финансов
- **THEN** веб-клиент показывает сообщение об ошибке, оставляет модальное окно открытым с введёнными значениями и не обновляет список

#### Scenario: Повторная отправка формы создания недоступна

- **WHEN** запрос создания счёта ещё выполняется
- **THEN** веб-клиент не позволяет подтвердить создание повторно

### Requirement: Удаление счёта с подтверждением

Страница финансов SHALL предоставлять для каждого счёта действие удаления. Перед удалением веб-клиент SHALL запрашивать подтверждение пользователя. При подтверждении веб-клиент SHALL отправить в API финансов запрос удаления счёта и после успешного ответа SHALL убрать счёт из списка. При отмене подтверждения веб-клиент MUST NOT отправлять запрос и MUST NOT менять список. Если запрос удаления завершился ошибкой, веб-клиент SHALL показать сообщение об ошибке и MUST NOT убирать счёт из списка. Пока запрос удаления этого счёта выполняется, повторное удаление MUST быть недоступно.

#### Scenario: Запрос подтверждения удаления

- **WHEN** пользователь выбирает действие удаления у счёта
- **THEN** веб-клиент запрашивает подтверждение удаления до отправки запроса

#### Scenario: Подтверждённое удаление убирает счёт из списка

- **WHEN** пользователь подтверждает удаление счёта
- **THEN** веб-клиент отправляет запрос удаления и после успеха убирает счёт из отображаемого списка

#### Scenario: Отмена удаления не меняет список

- **WHEN** пользователь отменяет подтверждение удаления
- **THEN** веб-клиент не отправляет запрос удаления и оставляет счёт в списке

#### Scenario: Ошибка API финансов при удалении

- **WHEN** запрос удаления завершается ошибкой API финансов
- **THEN** веб-клиент показывает сообщение об ошибке и оставляет счёт в списке

#### Scenario: Повторное удаление недоступно во время запроса

- **WHEN** запрос удаления счёта ещё выполняется
- **THEN** веб-клиент не позволяет повторно инициировать удаление этого счёта

### Requirement: Передача учётных данных в запросах к API финансов

Веб-клиент SHALL передавать access-токен из памяти в заголовке авторизации во всех запросах к API финансов и SHALL передавать CSRF-токен в изменяющих запросах к API финансов (создание и удаление счёта). Если access-токен отсутствует, веб-клиент MUST NOT отправлять запрос к API финансов.

#### Scenario: Запросы чтения передают access-токен

- **WHEN** веб-клиент запрашивает список счетов
- **THEN** запрос к API финансов содержит заголовок авторизации с access-токеном

#### Scenario: Изменяющие запросы финансов передают CSRF-токен

- **WHEN** веб-клиент создаёт или удаляет счёт
- **THEN** запрос к API финансов содержит CSRF-токен и заголовок авторизации

#### Scenario: Запросы финансов не отправляются без access-токена

- **WHEN** веб-клиент не имеет access-токена
- **THEN** запросы к API финансов не отправляются
