## Purpose

Ведение денежных счетов пользователя в сервисе `finance`: создание счёта с названием и начальной суммой, получение списка собственных счетов и удаление счёта, с изоляцией данных по аутентифицированному пользователю.

## ADDED Requirements

### Requirement: Создание счёта с названием и начальной суммой

Finance SHALL предоставлять эндпоинт создания счёта аутентифицированного пользователя, который сохраняет счёт с названием и начальной суммой. Название MUST быть непустым. Начальная сумма MUST быть указана и MUST быть числом с не более чем двумя знаками после запятой; валюта MUST NOT моделироваться. Созданный счёт MUST быть привязан к пользователю, выполнившему запрос.

#### Scenario: Успешное создание счёта

- **WHEN** аутентифицированный пользователь создаёт счёт с непустым названием и указанной начальной суммой
- **THEN** finance сохраняет счёт, привязанный к этому пользователю, и возвращает созданный счёт с его идентификатором, названием и начальной суммой

#### Scenario: Создание нескольких счетов

- **WHEN** аутентифицированный пользователь создаёт один счёт, а затем ещё один с другим названием
- **THEN** finance сохраняет оба счёта и привязывает их к этому пользователю

#### Scenario: Отклонение создания без названия

- **WHEN** аутентифицированный пользователь создаёт счёт с пустым или отсутствующим названием
- **THEN** finance отклоняет запрос ошибкой валидации и не сохраняет счёт

#### Scenario: Отклонение создания без начальной суммы

- **WHEN** аутентифицированный пользователь создаёт счёт без начальной суммы
- **THEN** finance отклоняет запрос ошибкой валидации и не сохраняет счёт

#### Scenario: Отклонение создания с суммой, превышающей два знака после запятой

- **WHEN** аутентифицированный пользователь создаёт счёт с начальной суммой, у которой больше двух знаков после запятой
- **THEN** finance отклоняет запрос ошибкой валидации и не сохраняет счёт

#### Scenario: Нулевая начальная сумма допустима

- **WHEN** аутентифицированный пользователь создаёт счёт с начальной суммой, равной нулю
- **THEN** finance сохраняет счёт и возвращает его с нулевой начальной суммой

### Requirement: Список счетов пользователя

Finance SHALL предоставлять эндпоинт, возвращающий список счетов аутентифицированного пользователя. Каждый счёт в ответе MUST содержать идентификатор, название и начальную сумму. При отсутствии счетов finance SHALL возвращать пустой список без ошибки.

#### Scenario: Список возвращает счета пользователя

- **WHEN** аутентифицированный пользователь запрашивает список своих счетов, и у него есть сохранённые счета
- **THEN** finance возвращает эти счета с их названиями и начальными суммами

#### Scenario: Пустой список при отсутствии счетов

- **WHEN** аутентифицированный пользователь без счетов запрашивает список
- **THEN** finance возвращает пустой список без ошибки

### Requirement: Удаление счёта

Finance SHALL предоставлять эндпоинт удаления счёта аутентифицированного пользователя. Удаление MUST удалять счёт безвозвратно и MUST быть доступно только для собственного счёта пользователя. Удаление одного счёта MUST NOT затрагивать другие счета пользователя. Изменение счёта (в том числе изменение названия или начальной суммы) MUST быть недоступно: единственными операциями над счётом являются создание, чтение списка и удаление.

#### Scenario: Успешное удаление счёта

- **WHEN** аутентифицированный пользователь удаляет свой счёт
- **THEN** finance удаляет счёт и возвращает успешный ответ без тела

#### Scenario: Удаление не затрагивает другие счета

- **WHEN** аутентифицированный пользователь удаляет один из нескольких своих счетов
- **THEN** finance удаляет только указанный счёт и сохраняет остальные счета без изменений

#### Scenario: Удаление чужого счёта отклоняется

- **WHEN** аутентифицированный пользователь пытается удалить счёт, принадлежащий другому пользователю
- **THEN** finance отвечает ошибкой «не найдено» (`404`) и не изменяет данные другого счёта

#### Scenario: Удаление несуществующего счёта отклоняется

- **WHEN** аутентифицированный пользователь пытается удалить счёт с несуществующим идентификатором
- **THEN** finance отвечает ошибкой «не найдено» (`404`) и не изменяет данные

### Requirement: Изоляция счетов по пользователю

Finance SHALL ограничивать доступ к счетам их владельцем: пользователь MUST NOT видеть или удалять счета другого пользователя. Запрос MUST идентифицировать пользователя по внутреннему заголовку с его идентификатором, который проставляет gateway.

#### Scenario: Пользователь не видит чужие счета

- **WHEN** аутентифицированный пользователь запрашивает список счетов, и у другого пользователя есть свои счета
- **THEN** finance возвращает только счета запрашивающего пользователя

#### Scenario: Запрос без идентификатора пользователя отклоняется

- **WHEN** запрос к эндпоинтам счетов не содержит внутреннего заголовка с идентификатором пользователя
- **THEN** finance отклоняет запрос с ошибкой аутентификации
