## Why

Сейчас порядок категорий на странице финансов жёстко задан: категории одного типа идут по возрастанию идентификатора, то есть в порядке создания. Пользователь не может поставить часто используемые категории выше или сгруппировать их так, как ему удобно, и вынужден каждый раз искать нужную категорию глазами. Нужно дать пользователю самому задавать порядок категорий, отдельно для прихода и ухода, чтобы этот порядок был единым на вкладках «Категории», «Операции» и «Статистика».

## What Changes

- Категория финансов получает сохраняемый порядок внутри своего типа (`INCOME` или `EXPENSE`). Порядок прихода и порядок ухода задаются независимо друг от друга.
- В сервисе `finance` появляется эндпоинт изменения порядка категорий одного типа; список категорий возвращается в заданном пользователем порядке внутри каждого типа, а не по возрастанию идентификатора.
- Новые категории добавляются в конец своего типа. Существующие категории при первом применении сохраняют текущий порядок (по возрастанию идентификатора).
- На вкладке «Категории» у каждого блока появляются кнопки перемещения вверх/вниз. Перемещается блок целиком: группа (все её категории вместе) или одиночная категория без группы.
- Вкладки «Операции» и «Статистика» перестают пересортировывать категории по идентификатору внутри типа и отображают их в пользовательском порядке, полученном из API финансов. Относительный порядок типов на этих вкладках (уход перед приходом) сохраняется.
- Группировка по названию группы остаётся только визуальной и MUST NOT менять состав или порядок категорий, возвращаемых API.

### Modified Capabilities
- `finance-categories`: категория получает сохраняемый порядок внутри типа; появляется эндпоинт изменения порядка; список категорий возвращается в пользовательском порядке.
- `web-finances`: вкладка «Категории» получает управление порядком блоков (кнопки «выше»/«ниже»); вкладки «Операции» и «Статистика» отображают категории в пользовательском порядке.

## Impact

- `backend/finance`: поле `sortOrder` в сущности `Category` и колонке `finance_categories`, миграция Flyway `V9__add_sort_order_to_finance_categories.sql` с обратным заполнением по `id` внутри типа; запрос изменения порядка (новый DTO и эндпоинт в `CategoryController`/`CategoryService`), сортировка списка и назначение порядка при создании; unit- и интеграционные тесты (`CategoryServiceTest`, `CategoryRepositoryTest`, `CategoryControllerTest`).
- `client/web`: `src/api/financeApi.js` (запрос изменения порядка), `src/finances/CategoriesTab.jsx` (кнопки перемещения блоков и оптимистичное обновление списка), `src/finances/OperationsTab.jsx` и `src/finances/StatisticsTab.jsx` (отказ от пересортировки по `id`), стили в `src/App.css`, тесты (`test/finances/*`, `test/api/financeApi.test.js`, `test/pages/FinancesPage.test.jsx`).
- Контракт API финансов: новый запрос `PUT /finances/categories/order` с телом `{ type, categoryIds }`; список категорий по-прежнему возвращает `{ id, type, name, group, plannedAmount }`, но в новом порядке внутри типа.
- Gateway не меняется: маршрут уже покрыт префиксом `/finances`.
