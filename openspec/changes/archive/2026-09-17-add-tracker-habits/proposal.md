## Why

Сервис `tracker` сейчас пустой и не умеет ничего. Первая пользовательская ценность, которую от него ожидают, — ежедневное отслеживание привычек: пользователь заводит привычку, отмечает её выполнение по дням и видит, что нужно сделать сегодня. Без этого `tracker` не приносит пользы, а gateway уже умеет аутентифицировать пользователя и передавать его идентификатор в сервис, поэтому можно сразу строить учёт привычек per-user.

## What Changes

- Добавить в `tracker` создание привычки: название, дата начала действия (сегодня или будущая дата) и периодичность — ежедневно либо конкретные дни недели.
- Добавить редактирование привычки: название, дата начала действия, периодичность. Уже сохранённые отметки выполнения при этом не удаляются и не пересчитываются.
- Добавить получение списка привычек на произвольную дату вместе со статусом «отмечена ли привычка на эту дату»; без параметра даты используется сегодня, прошлые даты допустимы.
- Добавить получение истории одним запросом: список привычек с их статусами выполнения за диапазон дат (включительно), в том числе за прошлые периоды.
- Возвращать ошибку валидации (`400` с сообщением), если запрошенная дата списка или начало диапазона истории раньше самой ранней даты начала среди привычек пользователя.
- Добавить отметку выполнения привычки и отмену отметки не только на сегодня, но и на прошлые даты.
- Определять «сегодня» по настраиваемому часовому поясу сервиса (один пояс для всех пользователей).
- Разрешать отметку/отмену только для дат в диапазоне от даты начала привычки до сегодня, которые совпадают с периодичностью привычки; будущие даты, даты до начала и даты не по периодичности отклонять ошибкой валидации.
- Идентифицировать пользователя по внутреннему заголовку `X-User-Id`, который добавляет gateway после проверки JWT; привычки одного пользователя недоступны другому.
- **BREAKING**: отсутствует — `tracker` ранее не содержал бизнес-логики.

## Capabilities

### New Capabilities

- `tracker-habits`: создание и редактирование ежедневных привычек (название, дата начала, периодичность), список привычек на произвольную дату (по умолчанию сегодня) с признаком выполнения, история привычек со статусами за диапазон дат и отметка/отмена выполнения на сегодня и прошлые даты.

### Modified Capabilities

_(нет — существующие спеки `gateway-user-auth` и `gateway-request-routing` не меняют требований)_

## Impact

- Затронутый код: `backend/tracker/src/main/java/com/theruzil/tracker/**`, `backend/tracker/src/main/resources/application.properties`, `backend/tracker/pom.xml` (добавление Spring Data JPA, PostgreSQL-драйвера, Flyway), новые миграции `backend/tracker/src/main/resources/db/migration/**`.
- Новая инфраструктурная зависимость: PostgreSQL, доступный `tracker` по JDBC. На первом этапе используется общая база проекта, таблицы `tracker` изолируются префиксом `tracker_`.
- Новые внешние API (за gateway, с префиксом `/tracker`): создание привычки, редактирование привычки, список привычек на дату (по умолчанию сегодня), история привычек за диапазон дат, отметка выполнения, отмена выполнения.
- Ожидается, что `tracker` доступен только через gateway (trust к заголовку `X-User-Id`); прямой внешний доступ к сервису не предусмотрен.
- Существующий gateway не модифицируется.
