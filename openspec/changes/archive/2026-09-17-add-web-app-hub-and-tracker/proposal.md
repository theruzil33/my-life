## Why

После входа веб-клиент `client/web` показывает только заглушку с email и кнопкой выхода, поэтому единственное доступное пользователю действие — выйти из системы. Backend-сервис `backend/tracker` уже полностью реализует API привычек (создание, список на дату, история за диапазон, отметка/отмена выполнения), но у него нет пользовательского интерфейса. Нужно превратить главную страницу в хаб приложений и дать пользователю первый реальный инструмент — трекер привычек, работающий через существующий API.

## What Changes

- Главная страница после входа превращается в хаб приложений: сохраняется отображение email пользователя и кнопка выхода, добавляется сетка квадратных карточек приложений по центру. Карточка «Трекер» ведёт на страницу трекера; для будущих приложений добавляются неактивные карточки-заглушки.
- Добавляется маршрут страницы трекера `/tracker` (защищённый, доступен только аутентифицированному пользователю).
- Страница трекера получает две вкладки:
  - «Привычки»: список привычек, запланированных на выбранную дату, с чекбоксом отметки выполнения; дата по умолчанию — сегодня, доступен выбор любой даты не позже сегодня, включая прошлые. Кнопка «Добавить привычку» открывает кастомную модалку с полями новой привычки (название, дата начала, периодичность).
  - «Статистика»: матрица выполнения привычек, где строки — привычки, а столбцы — дни диапазона; запланированные и выполненные дни отображаются закрашенными квадратиками. По умолчанию показывается текущий месяц (с первого числа по сегодня), доступен выбор произвольного диапазона с правой границей не позже сегодня.
- Клиентский HTTP-слой расширяется API привычек (`GET /tracker/habits`, `POST /tracker/habits`, `GET /tracker/habits/history`, `PUT`/`DELETE /tracker/habits/{id}/completions/{date}`) и передачей access-токена.
- Dev-прокси Vite расширяется префиксом `/tracker` в дополнение к `/auth`.
- Изменение и удаление привычки не реализуются.
- Backend (`backend/tracker`, `backend/gateway`) не изменяется: используется существующий контракт API и маршрутизация `/tracker/**`.

## Capabilities

### New Capabilities

- `web-app-hub`: главная аутентифицированная страница как хаб приложений — отображение email пользователя, сетка карточек приложений, навигация к странице приложения.
- `web-tracker`: пользовательский интерфейс трекера привычек в веб-клиенте — список привычек на выбранную дату с отметкой выполнения, создание привычки через модалку, вкладка статистики выполнения за выбираемый диапазон.

### Modified Capabilities

Нет. Существующие capabilities (`web-user-auth`, `tracker-habits`, `gateway-user-auth`, `gateway-request-routing`) не меняют требований: защита новых аутентифицированных страниц и передача токена/CSRF уже описаны в `web-user-auth`, а API привычек и маршрутизация — в `tracker-habits` и `gateway-request-routing`.

## Impact

- **Код**: `client/web/src/**` (новые страницы, компоненты, API-модуль, стили, маршруты в `App.jsx`), `client/web/vite.config.js` (dev-прокси `/tracker`).
- **Тесты**: `client/web/test/**` — новые тесты страниц/компонентов/API по существующему соглашению (Vitest + Testing Library, тесты вне `src/`).
- **Зависимости**: новые зависимости не требуются; используются React 19, react-router-dom 7, нативный `fetch`.
- **Backend**: без изменений; предполагается, что gateway (`/tracker/**` → tracker) и tracker запущены.
- **Данные**: новые данные не создаются, схема БД не меняется.
