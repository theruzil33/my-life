# web-finances Specification

## Purpose

Пользовательский интерфейс финансов в веб-клиенте: страница финансов с балансом в шапке и вкладками «Категории», «Операции» и «Статистика». Баланс показывается на всех вкладках и пересчитывается при изменении начального баланса. На вкладке «Категории» — список категорий с типом (приход или уход) и визуальной группировкой по названию группы, а также создание, редактирование и удаление категории; на вкладках «Операции» и «Статистика» — ввод и просмотр операций.

## Requirements

### Requirement: Доступ к странице финансов

Страница финансов SHALL быть доступна по адресу `/finances` и SHALL быть доступна только аутентифицированному пользователю.

#### Scenario: Аутентифицированный пользователь открывает финансы

- **WHEN** аутентифицированный пользователь открывает адрес `/finances`
- **THEN** веб-клиент показывает страницу финансов

#### Scenario: Неаутентифицированный пользователь открывает финансы

- **WHEN** пользователь без аутентифицированной сессии открывает адрес `/finances`
- **THEN** веб-клиент перенаправляет его на страницу входа и не показывает содержимое финансов

### Requirement: Вкладки и вкладка по умолчанию на странице финансов

Страница финансов SHALL содержать вкладки «Категории», «Операции» и «Статистика». По умолчанию SHALL быть выбрана вкладка «Операции». Переключение вкладки SHALL показывать содержимое выбранной вкладки и скрывать содержимое остальных. Содержимое вкладок SHALL получаться из API финансов независимо друг от друга. При каждом открытии вкладки её содержимое SHALL перечитываться из API финансов, чтобы отражать изменения, сделанные на других вкладках.

#### Scenario: Вкладки отображаются на странице финансов

- **WHEN** аутентифицированный пользователь открывает страницу финансов
- **THEN** веб-клиент показывает вкладки «Категории», «Операции» и «Статистика»

#### Scenario: По умолчанию выбрана вкладка «Операции»

- **WHEN** аутентифицированный пользователь открывает страницу финансов
- **THEN** веб-клиент показывает содержимое вкладки «Операции» и не показывает содержимое остальных вкладок

#### Scenario: Переключение на вкладку «Категории»

- **WHEN** пользователь выбирает вкладку «Категории»
- **THEN** веб-клиент показывает содержимое вкладки «Категории» и скрывает содержимое остальных вкладок

#### Scenario: Переключение на вкладку «Статистика»

- **WHEN** пользователь выбирает вкладку «Статистика»
- **THEN** веб-клиент показывает содержимое вкладки «Статистика» и скрывает содержимое остальных вкладок

#### Scenario: Открытие вкладки перечитывает данные

- **WHEN** пользователь открывает вкладку «Операции» или «Статистика» (впервые или повторно после работы на других вкладках)
- **THEN** веб-клиент заново запрашивает категории и операции этой вкладки из API финансов, чтобы отразить изменения, сделанные на других вкладках

### Requirement: Показ баланса на странице финансов

Страница финансов SHALL показывать текущий баланс пользователя, получая его из API финансов. Баланс SHALL отображаться в шапке страницы и SHALL быть виден на всех вкладках. Баланс SHALL отображаться числом с двумя знаками после запятой. Отрицательный баланс SHALL отображаться как есть. Во время загрузки страница SHALL показывать признак загрузки, а при ошибке загрузки — понятное сообщение об ошибке и MUST NOT показывать значение баланса как валидное.

#### Scenario: Баланс отображается

- **WHEN** аутентифицированный пользователь открывает страницу финансов
- **THEN** веб-клиент показывает текущий баланс, полученный из API финансов

#### Scenario: Баланс виден на всех вкладках

- **WHEN** пользователь переключается между вкладками страницы финансов
- **THEN** текущий баланс остаётся видимым

#### Scenario: Формат баланса

- **WHEN** веб-клиент отображает баланс
- **THEN** баланс показан числом с двумя знаками после запятой

#### Scenario: Отрицательный баланс отображается

- **WHEN** API финансов возвращает отрицательный баланс
- **THEN** веб-клиент показывает отрицательное значение

#### Scenario: Индикация загрузки баланса

- **WHEN** веб-клиент запрашивает баланс
- **THEN** страница показывает признак загрузки до получения ответа API финансов

#### Scenario: Ошибка загрузки баланса

- **WHEN** запрос баланса завершается сетевой ошибкой или ошибкой сервера
- **THEN** страница показывает сообщение об ошибке и не показывает значение баланса как валидное

### Requirement: Изменение начального баланса через модальное окно

Страница финансов SHALL предоставлять действие изменения начального баланса, открывающее модальное окно с текущим значением начального баланса. Модальное окно SHALL позволять изменить значение начального баланса. Веб-клиент SHALL проверять перед отправкой, что значение указано и является числом с не более чем двумя знаками после запятой, и MUST NOT отправлять запрос при нарушении, показывая причину. Ноль и отрицательное значение допустимы. При успешном сохранении веб-клиент SHALL закрыть модальное окно и обновить отображаемый баланс. Если запрос завершился ошибкой, веб-клиент SHALL показать сообщение об ошибке, оставить модальное окно открытым с введённым значением и MUST NOT обновлять баланс. Пока запрос сохранения выполняется, повторная отправка MUST быть недоступна.

#### Scenario: Открытие модального окна с текущим значением

- **WHEN** пользователь выбирает действие изменения начального баланса
- **THEN** веб-клиент показывает модальное окно с текущим значением начального баланса

#### Scenario: Успешное изменение начального баланса

- **WHEN** пользователь вводит корректное значение и подтверждает сохранение
- **THEN** веб-клиент отправляет запрос в API финансов, закрывает модальное окно и обновляет отображаемый баланс

#### Scenario: Нулевое и отрицательное значение допустимы

- **WHEN** пользователь вводит значение начального баланса, равное нулю или отрицательное
- **THEN** веб-клиент отправляет запрос сохранения

#### Scenario: Отклонение пустого значения

- **WHEN** пользователь подтверждает сохранение с пустым значением начального баланса
- **THEN** веб-клиент не отправляет запрос и показывает сообщение о необходимости указать значение

#### Scenario: Отклонение значения с более чем двумя знаками после запятой

- **WHEN** пользователь подтверждает сохранение значения начального баланса с более чем двумя знаками после запятой
- **THEN** веб-клиент не отправляет запрос и показывает сообщение о недопустимом значении

#### Scenario: Закрытие модального окна без сохранения

- **WHEN** пользователь закрывает модальное окно, не подтвердив сохранение
- **THEN** веб-клиент не отправляет запрос и не меняет отображаемый баланс

#### Scenario: Ошибка API финансов при изменении

- **WHEN** запрос изменения начального баланса завершается ошибкой API финансов
- **THEN** веб-клиент показывает сообщение об ошибке, оставляет модальное окно открытым с введённым значением и не обновляет баланс

#### Scenario: Повторная отправка недоступна

- **WHEN** запрос изменения начального баланса ещё выполняется
- **THEN** веб-клиент не позволяет подтвердить сохранение повторно

### Requirement: Список категорий на вкладке «Категории»

Вкладка «Категории» SHALL отображать все категории пользователя, получая их из API финансов. Для каждой категории SHALL отображаться её название. Названия категорий прихода SHALL отображаться зелёным цветом, а названия категорий ухода — красным. Если у пользователя нет категорий, вкладка SHALL показывать пустое состояние вместо списка. Во время загрузки вкладка SHALL показывать признак загрузки, а при ошибке загрузки — понятное сообщение об ошибке и MUST NOT показывать список.

#### Scenario: Список категорий отображается

- **WHEN** аутентифицированный пользователь открывает вкладку «Категории», и у него есть категории
- **THEN** веб-клиент показывает список этих категорий с названием каждой

#### Scenario: Категории прихода и ухода различаются цветом

- **WHEN** аутентифицированный пользователь открывает вкладку «Категории»
- **THEN** веб-клиент показывает названия категорий прихода зелёным цветом, а названия категорий ухода — красным

#### Scenario: Пустое состояние при отсутствии категорий

- **WHEN** аутентифицированный пользователь без категорий открывает вкладку «Категории»
- **THEN** вкладка показывает пустое состояние вместо списка категорий

#### Scenario: Индикация загрузки списка категорий

- **WHEN** веб-клиент запрашивает список категорий
- **THEN** вкладка показывает признак загрузки до получения ответа API финансов

#### Scenario: Ошибка загрузки списка категорий

- **WHEN** запрос списка категорий завершается сетевой ошибкой или ошибкой сервера
- **THEN** вкладка показывает сообщение об ошибке и не показывает список категорий

### Requirement: Визуальная группировка категорий

Вкладка «Категории» SHALL объединять категории в визуальные блоки по названию группы. Категории с одинаковым непустым названием группы SHALL показываться одним блоком с заголовком, содержащим название группы. Блок именованной группы SHALL быть визуально выделен рамкой так же, как элемент категории, чтобы группа и отдельная категория выглядели единообразно. Категории без группы SHALL показываться каждая отдельным блоком без заголовка. Блок MUST NOT смешивать типы: блок SHALL содержать категории только одного типа. Сначала SHALL показываться блоки категорий прихода, затем блоки категорий ухода. Внутри одного типа блоки SHALL идти в порядке первого появления их категорий в ответе API, а категории внутри блока — в порядке ответа API. Группировка SHALL быть только визуальной и MUST NOT изменять состав или порядок категорий, возвращаемых API.

#### Scenario: Категории одной группы объединяются в блок с заголовком

- **WHEN** веб-клиент отображает две категории одного типа с одинаковым непустым названием группы
- **THEN** вкладка показывает их одним блоком и отображает название группы как заголовок этого блока

#### Scenario: Блок именованной группы выделен рамкой

- **WHEN** веб-клиент отображает блок категорий с непустым названием группы
- **THEN** вкладка показывает этот блок в рамке, оформленной так же, как элемент категории

#### Scenario: Категории без группы показываются отдельными блоками

- **WHEN** веб-клиент отображает две категории одного типа без группы
- **THEN** вкладка показывает каждую из них отдельным блоком без заголовка

#### Scenario: Блоки прихода идут перед блоками ухода

- **WHEN** веб-клиент отображает блоки категорий обоих типов
- **THEN** сначала отображаются блоки категорий прихода, затем блоки категорий ухода

#### Scenario: Одна группа не смешивает типы

- **WHEN** у пользователя есть категории прихода и ухода с одинаковым непустым названием группы
- **THEN** вкладка показывает их разными блоками: в блоке прихода и в блоке ухода

### Requirement: Плановая сумма и действия в списке категорий

Вкладка «Категории» SHALL показывать для каждой категории её плановую сумму за месяц после кнопок «Редактировать» и «Удалить», если план задан. Плановая сумма SHALL отображаться числом с двумя знаками после запятой. Если план у категории не задан, вкладка SHALL NOT показывать плановую сумму для этой категории. Кнопки «Редактировать» и «Удалить» SHALL располагаться последовательно, рядом друг с другом, и MUST быть выровнены одинаково у разных категорий.

#### Scenario: Плановая сумма показывается после кнопок действий

- **WHEN** вкладка «Категории» показывает категорию с заданной плановой суммой
- **THEN** веб-клиент показывает её плановую сумму с двумя знаками после запятой после кнопок «Редактировать» и «Удалить»

#### Scenario: План не показывается без плановой суммы

- **WHEN** вкладка «Категории» показывает категорию без плана
- **THEN** веб-клиент не показывает плановую сумму для этой категории

#### Scenario: Кнопки действий расположены последовательно и выровнены между категориями

- **WHEN** вкладка «Категории» показывает несколько категорий с кнопками «Редактировать» и «Удалить»
- **THEN** у каждой категории обе кнопки идут последовательно рядом друг с другом и выровнены одинаково у разных категорий

### Requirement: Создание категории через модальное окно

Вкладка «Категории» SHALL предоставлять кнопку добавления, открывающую модальное окно создания категории. Модальное окно SHALL содержать выбор типа (приход или уход), поле названия и необязательное поле группы. Поле группы SHALL предлагать существующие названия групп выбранного типа и SHALL позволять ввести новое название. Веб-клиент SHALL проверять перед отправкой, что выбран тип и название непустое, и MUST NOT отправлять запрос при нарушении этих условий, показывая причину. При успешном создании веб-клиент SHALL закрыть модальное окно и обновить список категорий. Если запрос завершился ошибкой, веб-клиент SHALL показать сообщение об ошибке, оставить модальное окно открытым с введёнными значениями и MUST NOT обновлять список. Пока запрос создания выполняется, повторная отправка формы MUST быть недоступна.

#### Scenario: Открытие модального окна создания категории

- **WHEN** пользователь нажимает кнопку добавления на вкладке «Категории»
- **THEN** веб-клиент показывает модальное окно с выбором типа, полем названия и полем группы

#### Scenario: Успешное создание категории с группой

- **WHEN** пользователь выбирает тип, заполняет непустое название и непустую группу и подтверждает создание
- **THEN** веб-клиент отправляет запрос создания с типом, названием и группой, закрывает модальное окно и обновляет список категорий

#### Scenario: Успешное создание категории без группы

- **WHEN** пользователь выбирает тип, заполняет непустое название и оставляет поле группы пустым
- **THEN** веб-клиент отправляет запрос создания без группы, закрывает модальное окно и обновляет список категорий

#### Scenario: Поле группы предлагает существующие группы выбранного типа

- **WHEN** пользователь выбирает тип и у него уже есть категории этого типа с группами
- **THEN** веб-клиент предлагает существующие названия групп этого типа, позволяя также ввести новое

#### Scenario: Отклонение создания без типа

- **WHEN** пользователь подтверждает создание, не выбрав тип
- **THEN** веб-клиент не отправляет запрос и показывает сообщение о необходимости выбрать тип

#### Scenario: Отклонение создания без названия

- **WHEN** пользователь подтверждает создание с пустым названием
- **THEN** веб-клиент не отправляет запрос и показывает сообщение о необходимости указать название

#### Scenario: Закрытие модального окна без создания

- **WHEN** пользователь закрывает модальное окно, не подтвердив создание
- **THEN** веб-клиент не создаёт категорию и не меняет список категорий

#### Scenario: Ошибка API финансов при создании

- **WHEN** запрос создания категории завершается ошибкой API финансов
- **THEN** веб-клиент показывает сообщение об ошибке, оставляет модальное окно открытым с введёнными значениями и не обновляет список

#### Scenario: Повторная отправка формы создания недоступна

- **WHEN** запрос создания категории ещё выполняется
- **THEN** веб-клиент не позволяет подтвердить создание повторно

### Requirement: Редактирование категории через модальное окно

Вкладка «Категории» SHALL предоставлять для каждой категории действие редактирования, открывающее модальное окно с текущими названием и группой категории. Модальное окно SHALL позволять изменить название и группу; тип категории MUST NOT быть доступен для изменения и MUST NOT изменяться. Поле группы SHALL предлагать существующие названия групп этого типа и SHALL позволять ввести новое. Веб-клиент SHALL проверять перед отправкой, что название непустое, и MUST NOT отправлять запрос при нарушении, показывая причину. При успешном редактировании веб-клиент SHALL закрыть модальное окно и обновить список категорий. Если запрос завершился ошибкой, веб-клиент SHALL показать сообщение об ошибке, оставить модальное окно открытым с введёнными значениями и MUST NOT обновлять список. Пока запрос редактирования выполняется, повторная отправка MUST быть недоступна.

#### Scenario: Открытие модального окна редактирования

- **WHEN** пользователь выбирает действие редактирования у категории
- **THEN** веб-клиент показывает модальное окно с текущими названием и группой категории и без возможности изменить тип

#### Scenario: Успешное редактирование категории

- **WHEN** пользователь изменяет название и/или группу и подтверждает редактирование
- **THEN** веб-клиент отправляет запрос редактирования в API финансов, закрывает модальное окно и обновляет список категорий

#### Scenario: Тип категории недоступен для изменения

- **WHEN** пользователь открывает модальное окно редактирования категории
- **THEN** веб-клиент не позволяет изменить тип категории

#### Scenario: Отклонение редактирования без названия

- **WHEN** пользователь подтверждает редактирование с пустым названием
- **THEN** веб-клиент не отправляет запрос и показывает сообщение о необходимости указать название

#### Scenario: Ошибка API финансов при редактировании

- **WHEN** запрос редактирования категории завершается ошибкой API финансов
- **THEN** веб-клиент показывает сообщение об ошибке, оставляет модальное окно открытым с введёнными значениями и не обновляет список

#### Scenario: Повторная отправка формы редактирования недоступна

- **WHEN** запрос редактирования категории ещё выполняется
- **THEN** веб-клиент не позволяет подтвердить редактирование повторно

### Requirement: Поле плановой суммы за месяц в формах категории

Модальные окна создания и редактирования категории SHALL содержать необязательное поле плановой суммы за месяц. В окне создания поле SHALL быть пустым; в окне редактирования поле SHALL быть заполнено текущей плановой суммой категории, если она задана. Веб-клиент SHALL проверять перед отправкой, что заполненная плановая сумма является числом строго больше нуля с не более чем двумя знаками после запятой, и MUST NOT отправлять запрос при нарушении, показывая причину. Пустое поле SHALL отправляться как отсутствие плана; в окне редактирования пустое поле SHALL означать удаление плана у категории. Веб-клиент SHALL передавать плановую сумму в API финансов при создании и редактировании категории. При успешном сохранении веб-клиент SHALL закрыть модальное окно и обновить список категорий. Если запрос завершился ошибкой, веб-клиент SHALL показать сообщение об ошибке, оставить модальное окно открытым с введёнными значениями и MUST NOT обновлять список.

#### Scenario: Поле плана доступно при создании

- **WHEN** пользователь нажимает кнопку добавления на вкладке «Категории»
- **THEN** веб-клиент показывает модальное окно с необязательным полем плановой суммы за месяц

#### Scenario: Успешное создание категории с планом

- **WHEN** пользователь заполняет тип, название и корректную плановую сумму и подтверждает создание
- **THEN** веб-клиент отправляет запрос создания с плановой суммой, закрывает модальное окно и обновляет список категорий

#### Scenario: Создание категории без плана

- **WHEN** пользователь оставляет поле плановой суммы пустым и подтверждает создание
- **THEN** веб-клиент отправляет запрос создания без плана и после успеха обновляет список категорий

#### Scenario: Поле плана заполнено текущим значением при редактировании

- **WHEN** пользователь открывает модальное окно редактирования категории, у которой задана плановая сумма
- **THEN** веб-клиент показывает в поле плановой суммы текущую плановую сумму категории

#### Scenario: Отклонение нулевой или отрицательной плановой суммы

- **WHEN** пользователь подтверждает создание или редактирование с плановой суммой, равной нулю или меньшей нуля
- **THEN** веб-клиент не отправляет запрос и показывает сообщение о необходимости указать положительную сумму

#### Scenario: Отклонение плановой суммы с более чем двумя знаками после запятой

- **WHEN** пользователь подтверждает создание или редактирование с плановой суммой, у которой больше двух знаков после запятой
- **THEN** веб-клиент не отправляет запрос и показывает сообщение о недопустимой сумме

#### Scenario: Пустое поле при редактировании убирает план

- **WHEN** пользователь очищает поле плановой суммы при редактировании категории и подтверждает сохранение
- **THEN** веб-клиент отправляет запрос редактирования без плана и после успеха обновляет список категорий

#### Scenario: Ошибка API финансов при сохранении плана

- **WHEN** запрос создания или редактирования категории с плановой суммой завершается ошибкой API финансов
- **THEN** веб-клиент показывает сообщение об ошибке, оставляет модальное окно открытым с введёнными значениями и не обновляет список

### Requirement: Удаление категории с подтверждением

Вкладка «Категории» SHALL предоставлять для каждой категории действие удаления. Перед удалением веб-клиент SHALL запрашивать подтверждение пользователя. При подтверждении веб-клиент SHALL отправить в API финансов запрос удаления категории и после успешного ответа SHALL убрать категорию из списка. При отмене подтверждения веб-клиент MUST NOT отправлять запрос и MUST NOT менять список. Если запрос удаления завершился ошибкой, веб-клиент SHALL показать сообщение об ошибке и MUST NOT убирать категорию из списка. Пока запрос удаления этой категории выполняется, повторное удаление MUST быть недоступно.

#### Scenario: Запрос подтверждения удаления категории

- **WHEN** пользователь выбирает действие удаления у категории
- **THEN** веб-клиент запрашивает подтверждение удаления до отправки запроса

#### Scenario: Подтверждённое удаление убирает категорию из списка

- **WHEN** пользователь подтверждает удаление категории
- **THEN** веб-клиент отправляет запрос удаления и после успеха убирает категорию из отображаемого списка

#### Scenario: Отмена удаления не меняет список

- **WHEN** пользователь отменяет подтверждение удаления категории
- **THEN** веб-клиент не отправляет запрос удаления и оставляет категорию в списке

#### Scenario: Ошибка API финансов при удалении категории

- **WHEN** запрос удаления категории завершается ошибкой API финансов
- **THEN** веб-клиент показывает сообщение об ошибке и оставляет категорию в списке

#### Scenario: Повторное удаление недоступно во время запроса

- **WHEN** запрос удаления категории ещё выполняется
- **THEN** веб-клиент не позволяет повторно инициировать удаление этой категории

### Requirement: Передача учётных данных в запросах к API финансов

Веб-клиент SHALL передавать access-токен из памяти в заголовке авторизации во всех запросах к API финансов и SHALL передавать CSRF-токен в изменяющих запросах к API финансов (изменение начального баланса, создание, редактирование и удаление категории). Если access-токен отсутствует, веб-клиент MUST NOT отправлять запрос к API финансов.

#### Scenario: Запросы чтения передают access-токен

- **WHEN** веб-клиент запрашивает баланс или список категорий
- **THEN** запрос к API финансов содержит заголовок авторизации с access-токеном

#### Scenario: Изменяющие запросы финансов передают CSRF-токен

- **WHEN** веб-клиент изменяет начальный баланс либо создаёт, редактирует или удаляет категорию
- **THEN** запрос к API финансов содержит CSRF-токен и заголовок авторизации

#### Scenario: Запросы финансов не отправляются без access-токена

- **WHEN** веб-клиент не имеет access-токена
- **THEN** запросы к API финансов не отправляются

### Requirement: Вкладка «Операции» — выбор даты и сумм по категориям

Вкладка «Операции» SHALL отображать выбор даты и список всех категорий пользователя, получая категории и операции выбранной даты из API финансов. По умолчанию SHALL быть выбрана сегодняшняя дата. Пользователь SHALL иметь возможность выбрать любую дату — как в прошлом, так и в будущем. Для каждой категории SHALL отображаться одно поле ввода суммы. Поле суммы категории SHALL показывать сумму операции этой категории на выбранную дату, если операция существует, и SHALL быть пустым в противном случае. Категории ухода SHALL отображаться перед категориями прихода; внутри одного типа категории SHALL идти в порядке, возвращаемом API финансов. Вкладка SHALL объединять категории одного типа с одинаковым непустым названием группы в общий блок, оформленный рамкой так же, как блок группы на вкладке «Категории», и SHALL показывать название группы заголовком этого блока. Блок MUST NOT смешивать типы: категории прихода и ухода с одинаковым названием группы SHALL показываться разными блоками. Категории без группы SHALL показываться отдельно, без заголовка. Блоки SHALL идти в порядке первого появления их категорий в ответе API внутри типа. Группировка SHALL быть только визуальной и MUST NOT менять состав или порядок категорий, возвращаемых API. Если у пользователя нет категорий, вкладка SHALL показывать пустое состояние вместо списка. Во время загрузки вкладка SHALL показывать признак загрузки, а при ошибке загрузки — понятное сообщение об ошибке и MUST NOT показывать список.

#### Scenario: Выбор даты и список категорий с полями суммы

- **WHEN** аутентифицированный пользователь открывает вкладку «Операции», и у него есть категории
- **THEN** веб-клиент показывает выбор даты и список этих категорий, у каждой из которых есть поле ввода суммы

#### Scenario: Доступны даты в прошлом и будущем

- **WHEN** пользователь выбирает дату в прошлом или в будущем
- **THEN** веб-клиент показывает категории и суммы операций на выбранную дату

#### Scenario: Поле пустое, когда операции нет

- **WHEN** у категории на выбранную дату нет операции
- **THEN** веб-клиент показывает её поле суммы пустым

#### Scenario: Поле показывает сумму существующей операции

- **WHEN** у категории на выбранную дату есть операция
- **THEN** веб-клиент показывает в её поле сумму этой операции

#### Scenario: Категории ухода идут перед категориями прихода

- **WHEN** веб-клиент отображает категории обоих типов на вкладке «Операции»
- **THEN** сначала отображаются категории ухода, затем категории прихода

#### Scenario: Категории одной группы выделяются блоком с заголовком

- **WHEN** веб-клиент отображает две категории одного типа с одинаковым непустым названием группы
- **THEN** вкладка показывает их одним блоком в рамке и отображает название группы заголовком этого блока, а у каждой категории остаётся её поле суммы

#### Scenario: Блок группы не смешивает типы

- **WHEN** у пользователя есть категории прихода и ухода с одинаковым непустым названием группы
- **THEN** вкладка показывает их разными блоками: в блоке ухода и в блоке прихода

#### Scenario: Категории без группы показываются отдельно

- **WHEN** веб-клиент отображает две категории одного типа без группы
- **THEN** вкладка показывает каждую из них отдельной строкой без заголовка

#### Scenario: Пустое состояние при отсутствии категорий

- **WHEN** аутентифицированный пользователь без категорий открывает вкладку «Операции»
- **THEN** вкладка показывает пустое состояние вместо списка категорий

#### Scenario: Индикация загрузки вкладки «Операции»

- **WHEN** веб-клиент запрашивает категории и операции за выбранную дату
- **THEN** вкладка показывает признак загрузки до получения ответа API финансов

#### Scenario: Ошибка загрузки вкладки «Операции»

- **WHEN** запрос категорий или операций завершается сетевой ошибкой или ошибкой сервера
- **THEN** вкладка показывает сообщение об ошибке и не показывает список

### Requirement: Сохранение суммы операции на вкладке «Операции»

Вкладка «Операции» SHALL сохранять операцию, когда пользователь вводит корректную сумму в поле категории на выбранной дате. Веб-клиент SHALL проверять перед отправкой, что сумма указана и является числом строго больше нуля с не более чем двумя знаками после запятой, и MUST NOT отправлять запрос при нарушении, показывая причину. При успешном сохранении веб-клиент SHALL обновить отображение суммы этой категории. Повторное сохранение для пары «категория + дата» SHALL обновлять существующую операцию, а не создавать новую. Если запрос завершился ошибкой, веб-клиент SHALL показать сообщение об ошибке и MUST NOT отображать сумму как успешно сохранённую. Пока запрос сохранения выполняется, повторная отправка для этой категории MUST быть недоступна.

#### Scenario: Успешное сохранение суммы

- **WHEN** пользователь вводит в поле категории корректную сумму и подтверждает ввод
- **THEN** веб-клиент отправляет запрос сохранения в API финансов и после успеха обновляет отображение суммы этой категории

#### Scenario: Повторное сохранение обновляет сумму

- **WHEN** пользователь вводит новую корректную сумму для категории, у которой на выбранную дату уже есть операция
- **THEN** веб-клиент сохраняет новую сумму для той же пары «категория + дата», не создавая вторую операцию

#### Scenario: Отклонение пустой суммы

- **WHEN** пользователь подтверждает ввод с пустым полем суммы
- **THEN** веб-клиент не отправляет запрос и не создаёт операцию

#### Scenario: Отклонение неположительной суммы

- **WHEN** пользователь подтверждает ввод суммы, равной нулю или меньшей нуля
- **THEN** веб-клиент не отправляет запрос и показывает сообщение о необходимости указать положительную сумму

#### Scenario: Отклонение суммы с более чем двумя знаками после запятой

- **WHEN** пользователь подтверждает ввод суммы, у которой больше двух знаков после запятой
- **THEN** веб-клиент не отправляет запрос и показывает сообщение о недопустимой сумме

#### Scenario: Ошибка API финансов при сохранении суммы

- **WHEN** запрос сохранения суммы завершается ошибкой API финансов
- **THEN** веб-клиент показывает сообщение об ошибке и не отображает сумму как успешно сохранённую

#### Scenario: Повторная отправка суммы недоступна

- **WHEN** запрос сохранения суммы для категории ещё выполняется
- **THEN** веб-клиент не позволяет повторно отправить сумму для этой категории

### Requirement: Удаление операции очисткой поля суммы

Вкладка «Операции» SHALL удалять операцию, когда пользователь очищает поле суммы категории, у которой на выбранную дату есть операция. Перед удалением веб-клиент SHALL запрашивать подтверждение пользователя. При подтверждении веб-клиент SHALL отправить в API финансов запрос удаления этой операции и после успешного ответа SHALL оставить поле пустым. При отмене подтверждения веб-клиент MUST NOT отправлять запрос и SHALL восстановить в поле прежнюю сумму операции. Если запрос удаления завершился ошибкой, веб-клиент SHALL показать сообщение об ошибке и SHALL восстановить в поле прежнюю сумму операции. Пока запрос удаления выполняется, повторное удаление этой операции MUST быть недоступно.

#### Scenario: Запрос подтверждения при очистке поля

- **WHEN** пользователь очищает поле суммы категории, у которой на выбранную дату есть операция
- **THEN** веб-клиент запрашивает подтверждение удаления до отправки запроса

#### Scenario: Подтверждённое удаление оставляет поле пустым

- **WHEN** пользователь подтверждает удаление операции
- **THEN** веб-клиент отправляет запрос удаления и после успеха оставляет поле суммы пустым

#### Scenario: Отмена удаления восстанавливает сумму

- **WHEN** пользователь отменяет подтверждение удаления операции
- **THEN** веб-клиент не отправляет запрос удаления и восстанавливает в поле прежнюю сумму операции

#### Scenario: Ошибка API финансов при удалении операции

- **WHEN** запрос удаления операции завершается ошибкой API финансов
- **THEN** веб-клиент показывает сообщение об ошибке и восстанавливает в поле прежнюю сумму операции

#### Scenario: Повторное удаление недоступно во время запроса

- **WHEN** запрос удаления операции ещё выполняется
- **THEN** веб-клиент не позволяет повторно инициировать удаление этой операции

### Requirement: Вкладка «Статистика» — матрица операций за месяц

Вкладка «Статистика» SHALL отображать все операции пользователя за выбранный календарный месяц в виде таблицы «категории × дни месяца», получая категории и операции из API финансов. Вкладка SHALL предоставлять выбор месяца и года; любой произвольный диапазон дат MUST NOT быть доступен. По умолчанию SHALL быть выбран текущий календарный месяц. Строки таблицы SHALL соответствовать категориям пользователя, столбцы — каждому дню выбранного месяца включительно. В ячейке строки категории и столбца дня SHALL отображаться сумма операции этой категории на эту дату, если операция существует; при отсутствии операции ячейка SHALL оставаться пустой. Категории ухода SHALL идти перед категориями прихода; внутри одного типа категории SHALL идти в порядке, возвращаемом API финансов. Таблица SHALL иметь видимые границы ячеек. Столбцы дней SHALL занимать всю доступную ширину таблицы; если все дни не помещаются по ширине, таблица SHALL прокручиваться горизонтально. Вкладка MUST NOT создавать отдельную вертикальную прокрутку таблицы: таблица SHALL отображаться полностью по своей высоте, а вертикальная прокрутка SHALL обеспечиваться страницей — окном браузера. Полоса горизонтальной прокрутки MUST NOT перекрывать строки таблицы. Вкладка SHALL объединять категории одного типа с одинаковым непустым названием группы в группу: слева SHALL отображаться объединённая ячейка с названием группы, выровненная по вертикальному центру строк этой группы, а строки её категорий SHALL располагаться справа как части группы. Категория без группы SHALL занимать по ширине то же место, что группа вместе со своими категориями. Группа MUST NOT смешивать типы: категории прихода и ухода с одинаковым названием группы SHALL находиться в разных группах. Группировка SHALL быть только визуальной и MUST NOT менять состав или порядок категорий, возвращаемых API. При смене месяца и года веб-клиент SHALL заново запрашивать операции выбранного месяца и обновлять таблицу. Если у пользователя нет категорий, вкладка SHALL показывать пустое состояние вместо таблицы. Во время загрузки вкладка SHALL показывать признак загрузки, а при ошибке загрузки — понятное сообщение об ошибке и MUST NOT показывать таблицу.

#### Scenario: Таблица статистики отображается

- **WHEN** аутентифицированный пользователь открывает вкладку «Статистика», и у него есть категории
- **THEN** веб-клиент показывает таблицу, строки которой — категории, а столбцы — дни выбранного месяца

#### Scenario: Ячейка показывает сумму операции

- **WHEN** у категории на день выбранного месяца есть операция
- **THEN** веб-клиент показывает в соответствующей ячейке сумму этой операции

#### Scenario: Пустая ячейка при отсутствии операции

- **WHEN** у категории на день выбранного месяца нет операции
- **THEN** соответствующая ячейка таблицы остаётся пустой

#### Scenario: Категории ухода идут перед категориями прихода

- **WHEN** веб-клиент отображает таблицу статистики для категорий обоих типов
- **THEN** строки категорий ухода идут перед строками категорий прихода

#### Scenario: Категории одной группы показываются группой с названием слева

- **WHEN** веб-клиент отображает две категории одного типа с одинаковым непустым названием группы
- **THEN** слева отображается объединённая ячейка с названием группы, выровненная по вертикальному центру строк этих категорий, а строки категорий расположены справа как части группы

#### Scenario: Категория без группы занимает всю левую область

- **WHEN** веб-клиент отображает категорию без группы
- **THEN** её название занимает по ширине то же место, что группа вместе со своими категориями

#### Scenario: Группа не смешивает типы

- **WHEN** у пользователя есть категории прихода и ухода с одинаковым непустым названием группы
- **THEN** таблица показывает их в разных группах: в группе ухода и в группе прихода

#### Scenario: Границы ячеек отображаются

- **WHEN** веб-клиент показывает таблицу статистики
- **THEN** ячейки таблицы имеют видимые границы

#### Scenario: Столбцы дней занимают всю доступную ширину

- **WHEN** количество дней в выбранном месяце невелико и помещается по ширине
- **THEN** столбцы дней распределяются на всю доступную ширину таблицы

#### Scenario: Много дней — горизонтальная прокрутка

- **WHEN** количество дней в выбранном месяце не помещается по ширине контейнера
- **THEN** таблица прокручивается горизонтально, сохраняя все столбцы дней

#### Scenario: Нет отдельной вертикальной прокрутки таблицы

- **WHEN** таблица статистики по высоте превышает видимую область окна
- **THEN** вкладка показывает таблицу полностью по высоте без собственного вертикального скролла, а вертикально прокручивается только страница браузера

#### Scenario: Горизонтальная прокрутка не перекрывает строки

- **WHEN** в таблице статистики появляется полоса горизонтальной прокрутки
- **THEN** полоса прокрутки не перекрывает последнюю строку таблицы, и строка полностью видна

#### Scenario: Месяц по умолчанию

- **WHEN** аутентифицированный пользователь открывает вкладку «Статистика»
- **THEN** веб-клиент показывает операции текущего календарного месяца и выбран текущий месяц и год

#### Scenario: Выбор месяца и года

- **WHEN** пользователь выбирает другой месяц и год
- **THEN** веб-клиент показывает операции выбранного месяца, а столбцы таблицы соответствуют дням этого месяца

#### Scenario: Произвольный диапазон недоступен

- **WHEN** пользователь открывает вкладку «Статистика»
- **THEN** веб-клиент не предоставляет полей начала и конца произвольного диапазона дат

#### Scenario: Пустое состояние при отсутствии категорий

- **WHEN** аутентифицированный пользователь без категорий открывает вкладку «Статистика»
- **THEN** вкладка показывает пустое состояние вместо таблицы

#### Scenario: Индикация загрузки вкладки «Статистика»

- **WHEN** веб-клиент запрашивает операции за выбранный месяц
- **THEN** вкладка показывает признак загрузки до получения ответа API финансов

#### Scenario: Ошибка загрузки вкладки «Статистика»

- **WHEN** запрос операций за выбранный месяц завершается сетевой ошибкой или ошибкой сервера
- **THEN** вкладка показывает сообщение об ошибке и не показывает таблицу

### Requirement: План и дельта на вкладке «Статистика»

Вкладка «Статистика» SHALL показывать в таблице для каждой строки-категории две дополнительные колонки «План» и «Дельта», расположенные после названия категории и перед столбцами дней месяца. Колонка «План» SHALL показывать плановую сумму категории за месяц; если план у категории не задан, колонка SHALL оставаться пустой. Колонка «Дельта» SHALL показывать разность между плановой суммой категории и суммой фактических операций этой категории за выбранный месяц; положительная дельта SHALL означать остаток до плана, отрицательная — перерасход. Если план у категории не задан, колонка «Дельта» SHALL оставаться пустой. Плановая сумма и дельта SHALL отображаться числом с двумя знаками после запятой, при этом отрицательная дельта SHALL показываться со знаком минус. Дельта SHALL рассчитываться ровно по тем операциям выбранного месяца, которые отображаются в строке этой категории. Две колонки SHALL показываться для категорий обоих типов (прихода и ухода). План и дельта SHALL обновляться при смене месяца вместе с таблицей. При загрузке вкладки и при ошибке загрузки план и дельта MUST NOT показываться как валидные данные.

#### Scenario: Колонки плана и дельты отображаются

- **WHEN** аутентифицированный пользователь открывает вкладку «Статистика», и у него есть категории
- **THEN** веб-клиент показывает колонки «План» и «Дельта» после названия категории и перед столбцами дней месяца

#### Scenario: План показывается для категории с заданным планом

- **WHEN** у категории задана плановая сумма за месяц
- **THEN** в колонке «План» этой категории показывается плановая сумма с двумя знаками после запятой

#### Scenario: Пустой план при отсутствии плановой суммы

- **WHEN** у категории план не задан
- **THEN** колонки «План» и «Дельта» этой категории остаются пустыми

#### Scenario: Дельта равна плану минус факт

- **WHEN** у категории задан план, и за выбранный месяц по ней есть операции
- **THEN** дельта равна плановой сумме минус сумма операций этой категории за месяц

#### Scenario: Положительная дельта означает остаток до плана

- **WHEN** сумма операций категории за месяц меньше её плана
- **THEN** веб-клиент показывает положительную дельту

#### Scenario: Отрицательная дельта означает перерасход

- **WHEN** сумма операций категории за месяц больше её плана
- **THEN** веб-клиент показывает дельту со знаком минус

#### Scenario: Дельта без операций равна плану

- **WHEN** у категории задан план, и за выбранный месяц по ней нет операций
- **THEN** веб-клиент показывает дельту, равную плановой сумме

#### Scenario: План и дельта показываются для обоих типов

- **WHEN** у пользователя есть категории прихода и ухода с заданными планами
- **THEN** и у строк прихода, и у строк ухода показываются план и дельта

#### Scenario: План и дельта не показываются при ошибке загрузки

- **WHEN** запрос категорий или операций за выбранный месяц завершается сетевой ошибкой или ошибкой сервера
- **THEN** веб-клиент показывает сообщение об ошибке и не показывает план и дельту

### Requirement: Итоги прихода и ухода за выбранный период на вкладке «Статистика»

Вкладка «Статистика» SHALL показывать итоговые суммы прихода и ухода за применённый диапазон дат. Блок итогов SHALL располагаться между формой выбора диапазона и таблицей. Итог прихода SHALL равняться сумме сумм всех операций выбранного диапазона, категории которых имеют тип прихода; итог ухода SHALL равняться сумме сумм всех операций выбранного диапазона, категории которых имеют тип ухода. Итоги SHALL обновляться при каждом применении диапазона вместе с таблицей. Итоги SHALL быть согласованы с таблицей: они MUST учитывать ровно те же операции выбранного диапазона, которые отображаются в ячейках таблицы. Итоговые суммы SHALL отображаться в том же формате, что и ячейки таблицы (число с двумя знаками после запятой). Если за выбранный диапазон нет операций соответствующего типа, соответствующий итог SHALL показываться как `0.00`. При загрузке вкладки и при ошибке загрузки итоги MUST NOT показываться как валидные данные: вкладка показывает признак загрузки или сообщение об ошибке вместо таблицы и итогов.

#### Scenario: Итоги отображаются между выбором диапазона и таблицей

- **WHEN** аутентифицированный пользователь открывает вкладку «Статистика», и у него есть категории
- **THEN** веб-клиент показывает блок с итоговыми суммами прихода и ухода между формой выбора диапазона и таблицей

#### Scenario: Приход равен сумме операций категорий прихода

- **WHEN** у пользователя за выбранный диапазон есть операции по категориям прихода
- **THEN** итог прихода равен сумме сумм этих операций

#### Scenario: Уход равен сумме операций категорий ухода

- **WHEN** у пользователя за выбранный диапазон есть операции по категориям ухода
- **THEN** итог ухода равен сумме сумм этих операций

#### Scenario: Итоги обновляются при смене диапазона

- **WHEN** пользователь применяет новый диапазон
- **THEN** веб-клиент показывает итоги, рассчитанные по операциям нового диапазона

#### Scenario: Нулевые итоги при отсутствии операций

- **WHEN** за выбранный диапазон нет операций
- **THEN** веб-клиент показывает итог прихода `0.00` и итог ухода `0.00`

#### Scenario: Итоги согласованы с таблицей

- **WHEN** веб-клиент показывает итоги и таблицу за один диапазон
- **THEN** итог прихода равен сумме сумм ячеек строк категорий прихода, а итог ухода — сумме сумм ячеек строк категорий ухода

#### Scenario: Итоги не показываются при ошибке загрузки

- **WHEN** запрос операций за диапазон завершается сетевой ошибкой или ошибкой сервера
- **THEN** веб-клиент показывает сообщение об ошибке и не показывает итоги

### Requirement: Единый пользовательский порядок категорий на вкладках финансов

Веб-клиент SHALL отображать категории в порядке, возвращаемом API финансов, на всех вкладках страницы финансов («Категории», «Операции», «Статистика»). Внутри одного типа порядок категорий SHALL соответствовать порядку из ответа API финансов и MUST NOT пересортировываться по идентификатору. Относительный порядок типов на каждой вкладке сохраняется: на вкладке «Категории» категории прихода идут перед категориями ухода, а на вкладках «Операции» и «Статистика» категории ухода идут перед категориями прихода. Изменение порядка на вкладке «Категории» SHALL отражаться на остальных вкладках при их следующем перечитывании из API финансов.

#### Scenario: Все вкладки используют порядок из API финансов

- **WHEN** API финансов возвращает категории одного типа в пользовательском порядке
- **THEN** веб-клиент показывает их в этом порядке на вкладках «Категории», «Операции» и «Статистика»

#### Scenario: Клиент не пересортировывает категории по идентификатору

- **WHEN** порядок категорий одного типа в ответе API финансов отличается от порядка по возрастанию идентификатора
- **THEN** веб-клиент сохраняет порядок из ответа API и не переставляет категории по идентификатору

#### Scenario: Изменение порядка отражается на других вкладках

- **WHEN** пользователь меняет порядок категорий на вкладке «Категории» и затем открывает вкладку «Операции» или «Статистика»
- **THEN** веб-клиент перечитывает категории из API финансов и показывает их в новом порядке

### Requirement: Управление порядком блоков на вкладке «Категории»

Вкладка «Категории» SHALL предоставлять у каждого блока действия перемещения блока вверх и вниз по порядку. Блоком считается либо именованная группа (все категории одного типа с одинаковым непустым названием группы), либо одиночная категория без группы. Перемещение блока SHALL перемещать блок целиком: группу — вместе со всеми её категориями, сохраняя порядок категорий внутри блока. Порядок SHALL изменяться отдельно для категорий прихода и категорий ухода: блок MAY перемещаться только в пределах блоков своего типа и MUST NOT переходить через блоки другого типа. Порядок блоков внутри одного типа SHALL соответствовать порядку первого появления их категорий в ответе API финансов. Действие перемещения вверх SHALL быть недоступно для первого блока своего типа, а действие перемещения вниз — для последнего блока своего типа. При успешном перемещении веб-клиент SHALL сохранить новый порядок в API финансов и обновить отображение порядка. Пока запрос сохранения порядка выполняется, повторное перемещение блоков MUST быть недоступно. Если запрос завершился ошибкой, веб-клиент SHALL показать сообщение об ошибке и MUST NOT менять отображаемый порядок.

#### Scenario: Действия перемещения отображаются у каждого блока

- **WHEN** аутентифицированный пользователь открывает вкладку «Категории», и у него есть категории
- **THEN** у каждого блока показаны действия перемещения вверх и вниз

#### Scenario: Перемещение блока вверх

- **WHEN** пользователь перемещает блок вверх, и выше в том же типе есть другой блок
- **THEN** веб-клиент меняет блоки местами, сохраняет новый порядок в API финансов и показывает блок выше

#### Scenario: Перемещение блока вниз

- **WHEN** пользователь перемещает блок вниз, и ниже в том же типе есть другой блок
- **THEN** веб-клиент меняет блоки местами, сохраняет новый порядок в API финансов и показывает блок ниже

#### Scenario: Группа перемещается целиком

- **WHEN** пользователь перемещает блок именованной группы
- **THEN** веб-клиент перемещает всю группу вместе со всеми её категориями, не меняя порядок категорий внутри группы

#### Scenario: Блок не переходит через блоки другого типа

- **WHEN** пользователь перемещает блок категорий прихода
- **THEN** веб-клиент перемещает его только среди блоков прихода и не помещает его среди блоков ухода

#### Scenario: Действия недоступны на краях типа

- **WHEN** пользователь смотрит первый или последний блок своего типа на вкладке «Категории»
- **THEN** недоступное на краю действие перемещения (вверх для первого, вниз для последнего) не позволяет переместить блок

#### Scenario: Ошибка сохранения порядка не меняет порядок

- **WHEN** запрос сохранения нового порядка завершается ошибкой API финансов
- **THEN** веб-клиент показывает сообщение об ошибке и не меняет отображаемый порядок блоков

#### Scenario: Повторное перемещение недоступно во время запроса

- **WHEN** запрос сохранения порядка ещё выполняется
- **THEN** веб-клиент не позволяет повторно перемещать блоки

### Requirement: Кнопка импорта и модальное окно загрузки CSV-файла

В шапке страницы финансов рядом с действием изменения начального баланса SHALL отображаться кнопка импорта CSV-файла. Нажатие кнопки импорта SHALL открывать модальное окно импорта, а не встроенную форму. Модальное окно SHALL содержать выбор месяца и года и выбор файла. По умолчанию SHALL быть выбран текущий календарный месяц. Модальное окно SHALL закрываться по отмене без отправки запроса. Веб-клиент MUST NOT отправлять запрос импорта, если файл не выбран, и SHALL показывать понятное сообщение о необходимости выбрать файл. При отправке веб-клиент SHALL передавать access-токен в заголовке авторизации и CSRF-токен, отправляя файл вместе с выбранным месяцем и годом. Пока запрос импорта выполняется, веб-клиент SHALL показывать признак загрузки и MUST NOT позволять повторно инициировать импорт.

#### Scenario: Кнопка импорта рядом с изменением начального баланса

- **WHEN** аутентифицированный пользователь открывает страницу финансов
- **THEN** веб-клиент показывает в шапке кнопку импорта рядом с действием изменения начального баланса

#### Scenario: Нажатие кнопки импорта открывает модальное окно

- **WHEN** пользователь нажимает кнопку импорта
- **THEN** веб-клиент открывает модальное окно импорта с выбором месяца, года и файла

#### Scenario: Импорт не показан встроенной формой на вкладках

- **WHEN** аутентифицированный пользователь открывает вкладки «Статистика», «Операции» или «Категории»
- **THEN** веб-клиент не показывает форму импорта внутри содержимого вкладки

#### Scenario: Месяц по умолчанию

- **WHEN** пользователь открывает модальное окно импорта
- **THEN** веб-клиент показывает выбранным текущий календарный месяц

#### Scenario: Отмена закрывает модальное окно без импорта

- **WHEN** пользователь закрывает модальное окно импорта, не отправляя файл
- **THEN** веб-клиент закрывает модальное окно и не отправляет запрос импорта

#### Scenario: Отправка без выбранного файла недоступна

- **WHEN** пользователь пытается импортировать, не выбрав файл
- **THEN** веб-клиент не отправляет запрос и показывает сообщение о необходимости выбрать файл

#### Scenario: Импорт передаёт учётные данные и CSRF-токен

- **WHEN** веб-клиент отправляет выбранный файл с месяцем и годом
- **THEN** запрос к API финансов содержит access-токен, CSRF-токен, файл, месяц и год

#### Scenario: Повторный импорт недоступен во время запроса

- **WHEN** запрос импорта ещё выполняется
- **THEN** веб-клиент не позволяет повторно инициировать импорт

### Requirement: Результат и ошибки импорта

При успешном импорте веб-клиент SHALL показывать сводку результата (количество созданных категорий и количество затронутых операций) и SHALL перечитать отображаемые данные финансов, чтобы отразить импортированные операции. При ошибке импорта веб-клиент SHALL показывать понятное сообщение об ошибке. Во время импорта веб-клиент MUST NOT показывать сводку результата как успешную до успешного ответа API финансов.

#### Scenario: Успешный импорт показывает сводку

- **WHEN** API финансов успешно завершает импорт
- **THEN** веб-клиент показывает количество созданных категорий и количество затронутых операций

#### Scenario: Успешный импорт обновляет данные финансов

- **WHEN** API финансов успешно завершает импорт
- **THEN** веб-клиент перечитывает баланс и операции, чтобы отразить импортированные данные

#### Scenario: Ошибка импорта показывает сообщение

- **WHEN** запрос импорта завершается сетевой ошибкой или ошибкой сервера
- **THEN** веб-клиент показывает сообщение об ошибке и не показывает успешную сводку

#### Scenario: Сводка не показывается во время импорта

- **WHEN** запрос импорта ещё выполняется
- **THEN** веб-клиент показывает признак загрузки и не показывает успешную сводку
