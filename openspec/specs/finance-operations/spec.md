# finance-operations Specification

## Purpose

Ведение операций пользователя в сервисе `finance`: учёт денежных операций с датой, суммой и обязательной категорией, сохранение и обновление суммы операции на пару «категория + дата», чтение операций за дату, удаление операции, запрет удаления категории с операциями и изоляция данных по аутентифицированному пользователю.

## Requirements

### Requirement: Сохранение суммы операции на категорию и дату

Finance SHALL предоставлять эндпоинт, сохраняющий сумму операции аутентифицированного пользователя для указанных категории и даты. Категория MUST быть указана и MUST принадлежать пользователю, выполнившему запрос. Дата MUST быть указана. Сумма MUST быть указана и MUST быть числом строго больше нуля с не более чем двумя знаками после запятой. Для пары «категория + дата» MUST существовать не более одной операции: если операции на эту пару ещё нет, finance SHALL создать её; если операция уже есть, finance SHALL обновить её сумму, не создавая вторую операцию. Тип операции (приход или уход) MUST определяться типом категории и MUST NOT задаваться в запросе. Сохранённая операция MUST быть привязана к пользователю, выполнившему запрос, и MUST NOT быть привязана к счёту. Сохранение операции MUST NOT изменять счета и их начальные суммы.

#### Scenario: Успешное создание операции

- **WHEN** аутентифицированный пользователь сохраняет сумму для своей категории и указанной даты, и операции на эту пару ещё нет
- **THEN** finance создаёт операцию с этой категорией, датой и суммой, привязывает её к пользователю и возвращает созданную операцию с её идентификатором, категорией, датой и суммой

#### Scenario: Повторное сохранение обновляет сумму

- **WHEN** аутентифицированный пользователь сохраняет сумму для пары «категория + дата», по которой уже есть операция
- **THEN** finance обновляет сумму существующей операции и MUST NOT создавать вторую операцию на эту пару

#### Scenario: Сумма с двумя знаками после запятой допустима

- **WHEN** аутентифицированный пользователь сохраняет операцию с суммой, у которой ровно два знака после запятой
- **THEN** finance сохраняет операцию и возвращает её с этой суммой

#### Scenario: Дата в прошлом допустима

- **WHEN** аутентифицированный пользователь сохраняет операцию с датой раньше сегодняшней
- **THEN** finance сохраняет операцию на указанную дату

#### Scenario: Дата в будущем допустима

- **WHEN** аутентифицированный пользователь сохраняет операцию с датой позже сегодняшней
- **THEN** finance сохраняет операцию на указанную дату

#### Scenario: Отклонение сохранения без категории

- **WHEN** аутентифицированный пользователь сохраняет операцию без категории
- **THEN** finance отклоняет запрос ошибкой валидации и не сохраняет операцию

#### Scenario: Отклонение сохранения с чужой или несуществующей категорией

- **WHEN** аутентифицированный пользователь сохраняет операцию с категорией, принадлежащей другому пользователю, или с несуществующим идентификатором категории
- **THEN** finance отвечает ошибкой «не найдено» (`404`) и не сохраняет операцию

#### Scenario: Отклонение сохранения без даты

- **WHEN** аутентифицированный пользователь сохраняет операцию без даты
- **THEN** finance отклоняет запрос ошибкой валидации и не сохраняет операцию

#### Scenario: Отклонение сохранения без суммы

- **WHEN** аутентифицированный пользователь сохраняет операцию без суммы
- **THEN** finance отклоняет запрос ошибкой валидации и не сохраняет операцию

#### Scenario: Отклонение сохранения с неположительной суммой

- **WHEN** аутентифицированный пользователь сохраняет операцию с суммой, равной нулю или меньшей нуля
- **THEN** finance отклоняет запрос ошибкой валидации и не сохраняет операцию

#### Scenario: Отклонение сохранения с суммой, превышающей два знака после запятой

- **WHEN** аутентифицированный пользователь сохраняет операцию с суммой, у которой больше двух знаков после запятой
- **THEN** finance отклоняет запрос ошибкой валидации и не сохраняет операцию

#### Scenario: Сохранение операции не меняет счета

- **WHEN** аутентифицированный пользователь сохраняет операцию
- **THEN** список и начальные суммы его счетов остаются без изменений

### Requirement: Список операций за дату

Finance SHALL предоставлять эндпоинт, возвращающий операции аутентифицированного пользователя за указанную дату. Запрос MUST содержать дату; при отсутствии даты запрос MUST быть отклонён ошибкой валидации. Каждая операция в ответе MUST содержать идентификатор, идентификатор категории, дату и сумму. При отсутствии операций за указанную дату finance SHALL возвращать пустой список без ошибки.

#### Scenario: Список возвращает операции за дату

- **WHEN** аутентифицированный пользователь запрашивает операции за дату, и на эту дату у него есть сохранённые операции
- **THEN** finance возвращает эти операции с их идентификаторами, категориями, датой и суммами

#### Scenario: Пустой список при отсутствии операций

- **WHEN** аутентифицированный пользователь запрашивает операции за дату, на которую операций нет
- **THEN** finance возвращает пустой список без ошибки

#### Scenario: Отклонение запроса без даты

- **WHEN** аутентифицированный пользователь запрашивает операции без указания даты
- **THEN** finance отклоняет запрос ошибкой валидации

### Requirement: Список операций за диапазон дат

Finance SHALL предоставлять эндпоинт, возвращающий операции аутентифицированного пользователя за диапазон дат включительно. Запрос MUST содержать начало и конец диапазона; при отсутствии любой из границ запрос MUST быть отклонён ошибкой валидации. Если начало диапазона позже конца, запрос MUST быть отклонён ошибкой валидации. Диапазон MAY включать даты в будущем. Каждая операция в ответе MUST содержать идентификатор, идентификатор категории, дату и сумму. При отсутствии операций в диапазоне finance SHALL возвращать пустой список без ошибки.

#### Scenario: Список возвращает операции за диапазон

- **WHEN** аутентифицированный пользователь запрашивает операции за диапазон дат, и у него есть операции внутри диапазона
- **THEN** finance возвращает эти операции с их идентификаторами, категориями, датами и суммами

#### Scenario: Диапазон с будущими датами допустим

- **WHEN** аутентифицированный пользователь запрашивает операции за диапазон, включающий даты в будущем
- **THEN** finance возвращает операции этого диапазона без ошибки

#### Scenario: Пустой список при отсутствии операций в диапазоне

- **WHEN** аутентифицированный пользователь запрашивает операции за диапазон, в котором у него нет операций
- **THEN** finance возвращает пустой список без ошибки

#### Scenario: Отклонение запроса без границы диапазона

- **WHEN** аутентифицированный пользователь запрашивает операции за диапазон без начала или без конца
- **THEN** finance отклоняет запрос ошибкой валидации

#### Scenario: Отклонение диапазона с началом позже конца

- **WHEN** аутентифицированный пользователь запрашивает операции за диапазон, начало которого позже конца
- **THEN** finance отклоняет запрос ошибкой валидации

### Requirement: Удаление операции

Finance SHALL предоставлять эндпоинт удаления операции аутентифицированного пользователя. Удаление MUST удалять операцию безвозвратно и MUST быть доступно только для собственной операции пользователя. Удаление одной операции MUST NOT затрагивать другие операции пользователя.

#### Scenario: Успешное удаление операции

- **WHEN** аутентифицированный пользователь удаляет свою операцию
- **THEN** finance удаляет операцию и возвращает успешный ответ без тела

#### Scenario: Удаление не затрагивает другие операции

- **WHEN** аутентифицированный пользователь удаляет одну из нескольких своих операций
- **THEN** finance удаляет только указанную операцию и сохраняет остальные операции без изменений

#### Scenario: Удаление чужой операции отклоняется

- **WHEN** аутентифицированный пользователь пытается удалить операцию, принадлежащую другому пользователю
- **THEN** finance отвечает ошибкой «не найдено» (`404`) и не изменяет данные другой операции

#### Scenario: Удаление несуществующей операции отклоняется

- **WHEN** аутентифицированный пользователь пытается удалить операцию с несуществующим идентификатором
- **THEN** finance отвечает ошибкой «не найдено» (`404`) и не изменяет данные

### Requirement: Изоляция операций по пользователю

Finance SHALL ограничивать доступ к операциям их владельцем: пользователь MUST NOT видеть, изменять или удалять операции другого пользователя. Запрос MUST идентифицировать пользователя по внутреннему заголовку с его идентификатором, который проставляет gateway.

#### Scenario: Пользователь не видит чужие операции

- **WHEN** аутентифицированный пользователь запрашивает операции за дату, и у другого пользователя есть свои операции на эту дату
- **THEN** finance возвращает только операции запрашивающего пользователя

#### Scenario: Запрос без идентификатора пользователя отклоняется

- **WHEN** запрос к эндпоинтам операций не содержит внутреннего заголовка с идентификатором пользователя
- **THEN** finance отклоняет запрос с ошибкой аутентификации
