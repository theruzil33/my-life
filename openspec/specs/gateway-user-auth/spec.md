# gateway-user-auth Specification

## Purpose

Capability отвечает за регистрацию новых пользователей, вход по email и паролю и выдачу JWT access-токена, который используется всеми backend-сервисами для проверки личности пользователя.

## Requirements

### Requirement: Регистрация пользователя по email и паролю

Gateway SHALL предоставлять эндпоинт регистрации, который создаёт нового пользователя с уникальным email и паролем. Пароль MUST храниться только в виде необратимого хеша, а исходный пароль MUST NOT сохраняться или логироваться.

#### Scenario: Успешная регистрация

- **WHEN** клиент отправляет запрос регистрации с корректным email и паролем, для которых пользователь ещё не существует
- **THEN** gateway создаёт пользователя и возвращает успешный ответ без пароля и его хеша в теле

#### Scenario: Отклонение регистрации с уже существующим email

- **WHEN** клиент отправляет регистрацию с email, который уже зарегистрирован
- **THEN** gateway отклоняет запрос с ошибкой конфликта и не создаёт дубликат пользователя

#### Scenario: Отклонение регистрации с некорректными данными

- **WHEN** клиент отправляет регистрацию с email в неверном формате или с паролем короче минимально допустимой длины
- **THEN** gateway отклоняет запрос с ошибкой валидации и не создаёт пользователя

#### Scenario: Email нормализуется перед сравнением

- **WHEN** клиент регистрируется с email, отличающимся от существующего только регистром
- **THEN** gateway трактует такой email как уже занятый и отклоняет регистрацию

### Requirement: Вход в систему и выдача JWT access-токена

Gateway SHALL предоставлять эндпоинт входа, который проверяет пару email/пароль и при успехе возвращает подписанный JWT access-токен с ограниченным сроком действия.

#### Scenario: Успешный вход

- **WHEN** клиент отправляет корректные email и пароль зарегистрированного пользователя
- **THEN** gateway возвращает JWT access-токен со сроком действия и не возвращает пароль или его хеш

#### Scenario: Отклонение входа с неверным паролем

- **WHEN** клиент отправляет существующий email и неверный пароль
- **THEN** gateway отклоняет запрос с ошибкой аутентификации, не раскрывая, какой из параметров неверен

#### Scenario: Отклонение входа для незарегистрированного email

- **WHEN** клиент отправляет email, для которого пользователь не зарегистрирован
- **THEN** gateway отклоняет запрос с тем же ответом, что и при неверном пароле

### Requirement: Проверка JWT для защищённых запросов

Gateway SHALL проверять JWT access-токен для всех защищённых маршрутов и MUST NOT пропускать запрос к backend-сервису, если токен отсутствует, подпись недействительна или срок действия истёк.

#### Scenario: Запрос с валидным токеном

- **WHEN** защищённый запрос содержит заголовок авторизации с корректным и неистёкшим JWT access-токеном
- **THEN** gateway пропускает запрос и передаёт сервису идентификатор аутентифицированного пользователя

#### Scenario: Запрос без токена

- **WHEN** защищённый запрос не содержит заголовка авторизации
- **THEN** gateway отвечает ошибкой аутентификации и не обращается к backend-сервису

#### Scenario: Запрос с недействительной подписью токена

- **WHEN** защищённый запрос содержит JWT access-токен с подписью, не соответствующей секрету gateway
- **THEN** gateway отвечает ошибкой аутентификации и не обращается к backend-сервису

#### Scenario: Запрос с истёкшим токеном

- **WHEN** защищённый запрос содержит JWT access-токен, срок действия которого истёк
- **THEN** gateway отвечает ошибкой аутентификации и не обращается к backend-сервису

### Requirement: Публичные эндпоинты без проверки токена

Gateway SHALL позволять обращаться к эндпоинтам регистрации и входа без JWT access-токена, сохраняя проверку токена для остальных маршрутов.

#### Scenario: Обращение к эндпоинту регистрации без токена

- **WHEN** клиент вызывает эндпоинт регистрации без заголовка авторизации
- **THEN** gateway обрабатывает запрос, не требуя JWT access-токен

#### Scenario: Обращение к эндпоинту входа без токена

- **WHEN** клиент вызывает эндпоинт входа без заголовка авторизации
- **THEN** gateway обрабатывает запрос, не требуя JWT access-токен
