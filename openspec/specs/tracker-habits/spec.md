# tracker-habits Specification

## Purpose

Capability отвечает за ведение ежедневных привычек пользователя: создание и редактирование привычки с названием, датой начала действия и периодичностью, получение списка привычек на произвольную дату (включая прошлые) с признаком выполнения, получение истории привычек со статусами за диапазон дат, а также отметку и отмену выполнения на сегодня и прошлые даты.

## Requirements

### Requirement: Создание привычки с датой начала не в будущем

Tracker SHALL предоставлять эндпоинт создания активности, который сохраняет активность для аутентифицированного пользователя с типом, названием, датой начала действия и периодичностью. Тип MUST быть указан и MUST быть одним из `HABIT` или `TASK`. Название MUST быть непустым, дата начала MUST быть сегодняшней датой или прошлой датой, а периодичность MUST быть либо ежедневной, либо непустым набором конкретных дней недели.

#### Scenario: Успешное создание ежедневной привычки с сегодняшней датой начала

- **WHEN** аутентифицированный пользователь создаёт привычку с типом `HABIT`, непустым названием, датой начала равной сегодня, и периодичностью «ежедневно»
- **THEN** tracker сохраняет привычку, привязанную к этому пользователю, и возвращает созданную привычку с её типом, названием, датой начала и периодичностью

#### Scenario: Создание привычки с прошлой датой начала

- **WHEN** аутентифицированный пользователь создаёт привычку с датой начала раньше сегодняшней
- **THEN** tracker сохраняет привычку с указанной прошлой датой начала

#### Scenario: Создание привычки с конкретными днями недели

- **WHEN** аутентифицированный пользователь создаёт привычку с периодичностью в виде непустого набора дней недели
- **THEN** tracker сохраняет привычку с этими днями недели в качестве периодичности

#### Scenario: Успешное создание необязательной задачи

- **WHEN** аутентифицированный пользователь создаёт активность с типом `TASK`, непустым названием, датой начала не позже сегодняшней и корректной периодичностью
- **THEN** tracker сохраняет задачу, привязанную к этому пользователю, и возвращает созданную задачу с типом `TASK`

#### Scenario: Отклонение создания без названия

- **WHEN** аутентифицированный пользователь создаёт активность с пустым или отсутствующим названием
- **THEN** tracker отклоняет запрос ошибкой валидации и не сохраняет активность

#### Scenario: Отклонение создания с датой начала в будущем

- **WHEN** аутентифицированный пользователь создаёт активность с датой начала позже сегодняшней даты
- **THEN** tracker отклоняет запрос ошибкой валидации и не сохраняет активность

#### Scenario: Отклонение создания без периодичности

- **WHEN** аутентифицированный пользователь создаёт активность с пустым набором дней недели и без признака ежедневной периодичности
- **THEN** tracker отклоняет запрос ошибкой валидации и не сохраняет активность

#### Scenario: Отклонение создания без типа

- **WHEN** аутентифицированный пользователь создаёт активность без типа
- **THEN** tracker отклоняет запрос ошибкой валидации и не сохраняет активность

#### Scenario: Отклонение создания с неизвестным типом

- **WHEN** аутентифицированный пользователь создаёт активность с типом, отличным от `HABIT` и `TASK`
- **THEN** tracker отклоняет запрос ошибкой валидации и не сохраняет активность

### Requirement: Редактирование привычки

Tracker SHALL предоставлять эндпоинт редактирования существующей активности пользователя, позволяющий изменить название, дату начала действия и периодичность. Изменение MUST применять те же правила валидации, что и при создании, MUST сохранять тип активности без изменений и MUST NOT удалять или изменять уже сохранённые отметки выполнения активности.

#### Scenario: Успешное редактирование привычки

- **WHEN** аутентифицированный пользователь изменяет название, дату начала и/или периодичность своей активности на корректные значения
- **THEN** tracker сохраняет новые значения и возвращает обновлённую активность

#### Scenario: Сохранение отметок выполнения при редактировании

- **WHEN** аутентифицированный пользователь редактирует активность, для которой ранее были отмечены выполнения
- **THEN** tracker сохраняет все ранее отмеченные даты выполнения без изменений

#### Scenario: Сохранение типа при редактировании

- **WHEN** аутентифицированный пользователь редактирует задачу с типом `TASK`
- **THEN** tracker сохраняет тип `TASK` и возвращает обновлённую задачу

#### Scenario: Отклонение редактирования с некорректной датой начала

- **WHEN** аутентифицированный пользователь изменяет дату начала активности на дату в будущем
- **THEN** tracker отклоняет запрос ошибкой валидации и не изменяет активность

### Requirement: Список привычек на дату

Tracker SHALL предоставлять эндпоинт, возвращающий активности аутентифицированного пользователя, запланированные на указанную дату, с признаком того, отмечена ли каждая из них на эту дату. Дата MUST передаваться необязательным параметром в формате ISO (`yyyy-MM-dd`); если параметр отсутствует, MUST использоваться сегодняшняя дата в настроенном часовом поясе сервиса. Tracker SHALL поддерживать необязательный параметр типа, ограничивающий список одним типом (`HABIT` или `TASK`); если параметр типа отсутствует, SHALL возвращаться активности обоих типов. Каждая активность в ответе MUST содержать свой тип. Привычка SHALL попадать в список, если на указанную дату наступила или прошла её дата начала и день недели этой даты соответствует её периодичности. Будущие даты MUST быть допустимы: для них возвращаются активности, запланированные на эту дату.

Если указанная дата раньше самой ранней даты начала среди активностей пользователя, tracker SHALL возвращать пустой список без ошибки. Если у пользователя нет активностей, tracker SHALL возвращать пустой список без ошибки.

#### Scenario: Список на дату без параметра использует сегодня

- **WHEN** аутентифицированный пользователь запрашивает список активностей без параметра даты
- **THEN** tracker формирует список на сегодняшнюю дату в настроенном часовом поясе сервиса

#### Scenario: Ежедневная привычка попадает в список на запрошенную дату

- **WHEN** аутентифицированный пользователь запрашивает список на дату, и у него есть ежедневная привычка, дата начала которой наступила к этой дате
- **THEN** tracker включает эту привычку в список

#### Scenario: Список на прошлую дату отражает исторические отметки

- **WHEN** аутентифицированный пользователь запрашивает список на прошлую дату, и часть его активностей была отмечена на эту дату
- **THEN** tracker возвращает активности, запланированные на эту дату, с признаком выполнения именно на эту дату

#### Scenario: Привычка с будущей датой начала не попадает в список

- **WHEN** аутентифицированный пользователь запрашивает список на дату, и у него есть активность, дата начала которой позже запрошенной даты
- **THEN** tracker не включает эту активность в список

#### Scenario: Привычка, не запланированная на запрошенную дату, не попадает в список

- **WHEN** аутентифицированный пользователь запрашивает список на дату, и у него есть активность с периодичностью по конкретным дням недели, среди которых нет дня недели запрошенной даты
- **THEN** tracker не включает эту активность в список

#### Scenario: Признак выполнения отражает отметку на запрошенную дату

- **WHEN** аутентифицированный пользователь запрашивает список на дату, и часть его активностей уже отмечена на эту дату
- **THEN** tracker возвращает для каждой активности признак, показывающий, отмечена ли она на эту дату

#### Scenario: Список с указанным типом содержит только этот тип

- **WHEN** аутентифицированный пользователь запрашивает список на дату с параметром типа `TASK`, и у него есть активности обоих типов
- **THEN** tracker возвращает только задачи с типом `TASK` и не включает привычки

#### Scenario: Список без типа содержит оба типа

- **WHEN** аутентифицированный пользователь запрашивает список на дату без параметра типа, и у него есть привычки и задачи, запланированные на эту дату
- **THEN** tracker включает в список активности обоих типов с указанием типа каждой

#### Scenario: Список на будущую дату допустим

- **WHEN** аутентифицированный пользователь запрашивает список на будущую дату
- **THEN** tracker возвращает активности, запланированные на эту дату, и не отвечает ошибкой

#### Scenario: Пустой список на дату раньше самой ранней привычки

- **WHEN** аутентифицированный пользователь запрашивает список на дату, которая раньше самой ранней даты начала среди всех его активностей
- **THEN** tracker возвращает пустой список без ошибки

#### Scenario: Пустой список при отсутствии привычек

- **WHEN** аутентифицированный пользователь без активностей запрашивает список на любую дату
- **THEN** tracker возвращает пустой список без ошибки

### Requirement: История привычек за диапазон дат

Tracker SHALL предоставлять эндпоинт, возвращающий одним запросом активности аутентифицированного пользователя и их статусы выполнения за диапазон дат. В ответ MUST включаться активности обоих типов, и каждая активность MUST содержать свой тип. Диапазон MUST задаваться обязательными параметрами `from` и `to` в формате ISO (`yyyy-MM-dd`) и MUST трактоваться включительно с обеих сторон. Для каждой активности SHALL возвращаться статус выполнения на каждый день диапазона, соответствующий её периодичности; дни, не соответствующие периодичности активности, в ответе MUST NOT перечисляться, а активности без запланированных в диапазоне дней MUST NOT включаться в ответ. Будущие даты в границах диапазона MUST быть допустимы.

Tracker SHALL отвечать ошибкой валидации (`400` с сообщением), если `from` позже `to`. Если `from` раньше самой ранней даты начала среди активностей пользователя, tracker SHALL возвращать пустой список без ошибки. Если у пользователя нет активностей, tracker SHALL возвращать пустой список без ошибки.

#### Scenario: История за прошлый диапазон

- **WHEN** аутентифицированный пользователь запрашивает историю за диапазон прошлых дат, и часть его активностей была отмечена в этом диапазоне
- **THEN** tracker возвращает для каждой активности дни диапазона, соответствующие её периодичности, с признаком выполнения на каждый из этих дней

#### Scenario: История включает активности обоих типов с типом

- **WHEN** аутентифицированный пользователь запрашивает историю за диапазон, в котором есть привычки и задачи
- **THEN** tracker возвращает активность каждого типа с указанием её типа

#### Scenario: Не запланированные дни не перечисляются

- **WHEN** аутентифицированный пользователь запрашивает историю за диапазон, и у активности с периодичностью по конкретным дням недели есть дни диапазона вне этой периодичности
- **THEN** tracker не включает эти дни в ответ для данной активности

#### Scenario: Диапазон включает сегодня

- **WHEN** аутентифицированный пользователь запрашивает историю за диапазон, правая граница которого равна сегодняшней дате
- **THEN** tracker включает сегодняшний день в статусы активностей наравне с прошлыми днями

#### Scenario: Будущие даты в диапазоне допустимы

- **WHEN** аутентифицированный пользователь запрашивает историю с границей `to` в будущем
- **THEN** tracker возвращает статусы активностей на запланированные дни этого диапазона и не отвечает ошибкой

#### Scenario: Отклонение диапазона с from позже to

- **WHEN** аутентифицированный пользователь запрашивает историю, где `from` позже `to`
- **THEN** tracker отвечает ошибкой валидации (`400` с сообщением)

#### Scenario: Диапазон ниже самой ранней привычки допустим

- **WHEN** аутентифицированный пользователь запрашивает историю, где `from` раньше самой ранней даты начала среди всех его активностей
- **THEN** tracker возвращает статусы только по запланированным в диапазоне дням и не отвечает ошибкой

### Requirement: Отметка и отмена выполнения на дату

Tracker SHALL предоставлять эндпоинты отметки выполнения привычки и отмены выполнения, принимающие дату выполнения. Отметка и отмена SHALL быть доступны для сегодняшней даты и для прошлых дат. Датой выполнения MUST NOT быть будущая дата, дата раньше даты начала привычки или дата, не соответствующая периодичности привычки; такие запросы MUST отклоняться ошибкой валидации.

#### Scenario: Отметка выполнения на сегодня

- **WHEN** аутентифицированный пользователь отмечает выполнение своей привычки на сегодняшнюю дату, соответствующую её периодичности
- **THEN** tracker сохраняет отметку и возвращает привычку как выполненную на эту дату

#### Scenario: Отметка выполнения на прошлую дату

- **WHEN** аутентифицированный пользователь отмечает выполнение своей привычки на прошлую дату, которая не раньше даты начала привычки и соответствует её периодичности
- **THEN** tracker сохраняет отметку на эту дату

#### Scenario: Отмена выполнения на прошлую дату

- **WHEN** аутентифицированный пользователь отменяет выполнение своей привычки на дату, которая ранее была отмечена
- **THEN** tracker удаляет отметку на эту дату и возвращает привычку как невыполненную на эту дату

#### Scenario: Отклонение отметки на будущую дату

- **WHEN** аутентифицированный пользователь пытается отметить выполнение привычки на будущую дату
- **THEN** tracker отклоняет запрос ошибкой валидации и не сохраняет отметку

#### Scenario: Отклонение отметки на дату раньше начала привычки

- **WHEN** аутентифицированный пользователь пытается отметить выполнение привычки на дату раньше её даты начала
- **THEN** tracker отклоняет запрос ошибкой валидации и не сохраняет отметку

#### Scenario: Отклонение отметки на дату не по периодичности

- **WHEN** аутентифицированный пользователь пытается отметить выполнение привычки на дату, день недели которой не входит в её периодичность
- **THEN** tracker отклоняет запрос ошибкой валидации и не сохраняет отметку

#### Scenario: Повторная отметка не создаёт дубликат

- **WHEN** аутентифицированный пользователь повторно отмечает выполнение привычки на уже отмеченную дату
- **THEN** tracker сохраняет единственную отметку на эту дату без создания дубликата

#### Scenario: Отмена неотмеченной даты не изменяет состояние

- **WHEN** аутентифицированный пользователь отменяет выполнение привычки на дату, которая не была отмечена
- **THEN** tracker завершает запрос успешно и не изменяет набор отметок привычки

### Requirement: Определение сегодняшней даты по часовому поясу сервиса

Tracker SHALL определять сегодняшнюю дату и день недели по настроенному часовому поясу сервиса, применяя его единообразно при создании привычки, выборе даты по умолчанию для списка и истории и проверке допустимости даты выполнения.

#### Scenario: Сегодняшняя дата определяется по настроенному поясу

- **WHEN** запрос обрабатывается в момент, когда дата в настроенном часовом поясе сервиса отличается от даты в UTC
- **THEN** tracker использует дату в настроенном часовом поясе как сегодняшнюю

#### Scenario: Дата начала может быть равна сегодняшней дате в настроенном поясе

- **WHEN** аутентифицированный пользователь создаёт привычку с датой начала, равной сегодняшней дате в настроенном часовом поясе сервиса
- **THEN** tracker принимает такую дату как допустимую дату начала

### Requirement: Изоляция привычек по пользователю

Tracker SHALL ограничивать доступ к привычкам их владельцем: пользователь MUST NOT видеть, редактировать или отмечать привычки другого пользователя. Запрос MUST идентифицировать пользователя по внутреннему заголовку с его идентификатором, который проставляет gateway.

#### Scenario: Пользователь не видит чужие привычки

- **WHEN** аутентифицированный пользователь запрашивает список привычек на дату или историю за диапазон, и у другого пользователя есть привычки в этом же диапазоне
- **THEN** tracker возвращает только привычки запрашивающего пользователя

#### Scenario: Изменение чужой привычки отклоняется

- **WHEN** аутентифицированный пользователь пытается отредактировать или отметить привычку, принадлежащую другому пользователю
- **THEN** tracker отвечает ошибкой «не найдено» и не изменяет данные другой привычки

#### Scenario: Запрос без идентификатора пользователя отклоняется

- **WHEN** запрос к эндпоинтам привычек не содержит внутреннего заголовка с идентификатором пользователя
- **THEN** tracker отклоняет запрос с ошибкой аутентификации

### Requirement: Тип активности для привычек и задач

Tracker SHALL хранить у каждой активности признак типа: `HABIT` (обязательная привычка) или `TASK` (необязательная задача). Тип MUST задаваться при создании, MUST возвращаться в ответах на чтение и MUST NOT изменяться при редактировании. Все остальные правила отслеживания (дата начала, периодичность, список на дату, история, отметка и отмена выполнения, изоляция по пользователю, определение сегодняшней даты по часовому поясу сервиса) SHALL применяться к обоим типам единообразно; тип MUST NOT изменять эти правила и MUST NOT влиять на отметки и статистику другого типа.

#### Scenario: Активность сохраняется с типом привычки

- **WHEN** аутентифицированный пользователь создаёт активность с типом `HABIT`
- **THEN** tracker сохраняет активность и возвращает её с типом `HABIT`

#### Scenario: Активность сохраняется с типом задачи

- **WHEN** аутентифицированный пользователь создаёт активность с типом `TASK`
- **THEN** tracker сохраняет активность и возвращает её с типом `TASK`

#### Scenario: Тип возвращается при чтении

- **WHEN** аутентифицированный пользователь запрашивает список активностей на дату или историю
- **THEN** tracker возвращает для каждой активности её тип

#### Scenario: Тип не изменяется при редактировании

- **WHEN** аутентифицированный пользователь редактирует активность, не указывая новый тип
- **THEN** tracker сохраняет прежний тип активности

#### Scenario: Отметки разных типов не влияют друг на друга

- **WHEN** у пользователя есть привычка и задача, и он отмечает выполнение одной из них на дату
- **THEN** tracker изменяет признак выполнения только у отмеченной активности и не изменяет активность другого типа

### Requirement: Удаление активности

Tracker SHALL предоставлять эндпоинт удаления активности аутентифицированного пользователя. Удаление MUST удалять саму активность и все её отметки выполнения безвозвратно и MUST быть доступно для активностей обоих типов (`HABIT` и `TASK`) по единым правилам. Удаление одной активности MUST NOT затрагивать другие активности пользователя и их отметки. Попытка удалить активность другого пользователя или несуществующую активность MUST отвечать ошибкой «не найдено» (`404`) и MUST NOT изменять данные. Запрос MUST идентифицировать пользователя по внутреннему заголовку с его идентификатором, который проставляет gateway.

#### Scenario: Успешное удаление привычки

- **WHEN** аутентифицированный пользователь удаляет свою активность типа `HABIT`
- **THEN** tracker удаляет активность и возвращает успешный ответ без тела

#### Scenario: Успешное удаление задачи

- **WHEN** аутентифицированный пользователь удаляет свою активность типа `TASK`
- **THEN** tracker удаляет задачу и возвращает успешный ответ без тела

#### Scenario: Отметки выполнения удаляются вместе с активностью

- **WHEN** аутентифицированный пользователь удаляет активность, у которой были отмечены выполнения на прошлые даты
- **THEN** tracker удаляет активность и все её отметки выполнения, и они больше не возвращаются в истории

#### Scenario: Удаление не затрагивает другие активности

- **WHEN** аутентифицированный пользователь удаляет одну из нескольких своих активностей
- **THEN** tracker удаляет только указанную активность и сохраняет остальные активности и их отметки без изменений

#### Scenario: Удаление чужой активности отклоняется

- **WHEN** аутентифицированный пользователь пытается удалить активность, принадлежащую другому пользователю
- **THEN** tracker отвечает ошибкой «не найдено» (`404`) и не изменяет данные другой активности

#### Scenario: Удаление несуществующей активности отклоняется

- **WHEN** аутентифицированный пользователь пытается удалить активность с несуществующим идентификатором
- **THEN** tracker отвечает ошибкой «не найдено» (`404`) и не изменяет данные

#### Scenario: Запрос удаления без идентификатора пользователя отклоняется

- **WHEN** запрос удаления активности не содержит внутреннего заголовка с идентификатором пользователя
- **THEN** tracker отклоняет запрос с ошибкой аутентификации

### Requirement: Автоматическая отметка прошлых дней при создании активности

Tracker SHALL принимать при создании активности необязательный булев признак «отметить прошлое выполненным». Если признак равен `true` и дата начала активности раньше сегодняшней даты в настроенном часовом поясе сервиса, tracker SHALL при создании сохранить отметки выполнения на все дни от даты начала включительно до дня, предшествующего сегодняшнему, которые соответствуют периодичности активности. Сегодняшний день MUST NOT отмечаться автоматически по этому признаку. Дни, не соответствующие периодичности, MUST NOT отмечаться. Если признак отсутствует или равен `false`, tracker MUST NOT создавать автоматические отметки. Правило SHALL применяться единообразно к активностям обоих типов (`HABIT` и `TASK`). Автоматически созданные отметки SHALL NOT отличаться от отметок, созданных вручную, и SHALL отражаться в списке на дату, истории и статистике.

#### Scenario: Отметка всех прошлых запланированных дней ежедневной активности

- **WHEN** аутентифицированный пользователь создаёт ежедневную активность с датой начала 7 дней назад и признаком «отметить прошлое выполненным», равным `true`
- **THEN** tracker сохраняет активность и отметки выполнения на каждый день от даты начала включительно до вчерашнего дня

#### Scenario: Сегодняшний день не отмечается автоматически

- **WHEN** аутентифицированный пользователь создаёт активность с признаком «отметить прошлое выполненным», равным `true`, и датой начала в прошлом
- **THEN** tracker сохраняет отметки только на прошлые запланированные дни и не создаёт отметку на сегодняшний день

#### Scenario: Отмечаются только дни, соответствующие периодичности

- **WHEN** аутентифицированный пользователь создаёт активность с периодичностью по конкретным дням недели, датой начала в прошлом и признаком «отметить прошлое выполненным», равным `true`
- **THEN** tracker сохраняет отметки только на прошедшие дни, день недели которых входит в периодичность активности, и не создаёт отметки на остальные прошлые дни

#### Scenario: Непрошедшие дни не отмечаются

- **WHEN** аутентифицированный пользователь создаёт активность с датой начала, равной сегодняшней, и признаком «отметить прошлое выполненным», равным `true`
- **THEN** tracker сохраняет активность без автоматических отметок выполнения

#### Scenario: Признак отсутствует — автоматические отметки не создаются

- **WHEN** аутентифицированный пользователь создаёт активность с датой начала в прошлом, не передавая признак «отметить прошлое выполненным»
- **THEN** tracker сохраняет активность без автоматических отметок выполнения

#### Scenario: Признак применяется к задаче

- **WHEN** аутентифицированный пользователь создаёт активность типа `TASK` с датой начала в прошлом и признаком «отметить прошлое выполненным», равным `true`
- **THEN** tracker сохраняет задачу и отметки выполнения на её прошлые запланированные дни

#### Scenario: Отклонённое создание не создаёт отметок

- **WHEN** аутентифицированный пользователь отправляет создание активности с признаком «отметить прошлое выполненным», равным `true`, но с некорректными данными (пустое название, будущая дата начала или незаполненная периодичность)
- **THEN** tracker отклоняет запрос ошибкой валидации и не сохраняет ни активность, ни отметки выполнения
